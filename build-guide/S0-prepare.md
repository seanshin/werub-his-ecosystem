### 첫 기동용 격리 네트워크

각 시스템의 코드와 설정 예시에 **특정 설치본의 주소가 기본값으로 들어 있는 파일**이 있습니다(11개 저장소 합계 245개 — [파일 목록](replace-list.md) · 문서 제외 · 2026-09-11 기준 커밋). 주소를 바꾸지 않고 띄우면 **다른 설치본으로 요청이 갈 수 있습니다.**

- 첫 기동은 **외부로 나가는 연결을 막은 상태**에서 합니다. 시스템끼리의 내부 연결만 열어 둡니다.
- 주소 교체(S1 · 각 단계 ③)를 끝내고 확인한 뒤에, 필요한 외부 연결만 하나씩 엽니다.
**시스템별 실행 판본**(기준 커밋의 컨테이너 정의에 적힌 값 · 설치본에서 실제로 도는 판본과 다를 수 있습니다)

| 시스템 | 애플리케이션 | DB · 캐시 · 그 밖 |
|---|---|---|
| sign | Node 22(API · 웹) | PostgreSQL 16 · 같은 이미지를 암호 프록시 · 신원 확인 프록시가 재사용 |
| LIS | Node 20(API · 웹) | PostgreSQL 16 · Redis 7(개발 compose) |
| ERP | Python 3.12(core · 워커 2) · Node 22(웹) | PostgreSQL 15 · Redis 7 · BI 는 별도 compose |
| PACS | Python 3.12(백엔드) · Node 22(관리 화면) · nginx(뷰어) | PostgreSQL 16 · Redis 7 · Orthanc 24.12.2 · Prometheus · Grafana 11.2 |
| twin | Python 3.12 · Node 22(웹) | PostgreSQL 16 · Redis 7 |
| cerno | **Python 3.13** · **Node 24**(웹) | **PostgreSQL 없음** — 문서 등록부는 SQLite 파일(볼륨) · Redis 7 |
| edu | Node 20(API · 웹) | PostgreSQL 16 · Redis 7 |
| Clinic | (저장소 공용 API 와 함께) | PostgreSQL 15(pgvector 이미지) · Redis 7 |
| Jitsi | Node 20(연동 API) | Jitsi `stable-9823` 이미지 묶음 · coturn 4.6 · Prometheus · Grafana 11.2 |
| AI Server | Python(`requirements.txt`) | **컨테이너 정의가 저장소에 없습니다** — 설치 방식은 [S6](S6-ai.md) |

- 한 서버에 올릴 때 **Node 가 20 · 22 · 24 세 판본**, **PostgreSQL 이 15 · 16 두 판본**입니다. 컨테이너로 올리면 서로 부딪치지 않지만, 호스트에 직접 설치하면 판본 관리 도구가 필요합니다.
- `latest` 태그로 적힌 이미지(PACS 의 exporter 2개 등)는 받는 날에 따라 판본이 달라집니다. 리허설 때 받은 판본을 기록해 둡니다.
- 🔴 **고정 태그라고 다 받아지는 것은 아닙니다.** 따라가기에서 위 표의 영상 서버(Orthanc) 판본은 공개 레지스트리에 그 태그가 없어 이미지를 받지 못했고, 같은 계열의 다른 판본으로 바꿔 설치했습니다(2026-09-14 → [S3](S3-clinical-departments.md)). **설치 전에 표의 이미지가 실제로 받아지는지 먼저 확인**하고, 받아지지 않으면 어느 판본으로 갈지 기관이 정합니다(기준 커밋을 벗어나는 결정입니다).
- 이미지가 **arm64 를 내는지**도 미리 봅니다. 따라가기(arm64 개발 PC)에서 위 표의 이미지 대부분은 arm64 를 받을 수 있었습니다.

- 모델 가중치 · 코드 마스터 · 공공 데이터처럼 밖에서 받아야 하는 것은 **격리 구간 밖에서 받아 반입**하는 방식을 먼저 정합니다. 기준 커밋에서 확인한 반입 경로는 다음 둘입니다(2026-09-16).
  - **코드 마스터(진단 · 수가 · 약품)** — HIS 관리 화면(`/admin/codes`)에 반입 경로가 있고, **미리보기 → 반영 두 단계**입니다. 미리보기는 파일의 차이만 보여 주고 **아무것도 저장하지 않습니다**(잘못된 파일 하나로 마스터 전체가 망가지지 않게 한 것입니다). 반영은 관리자만 할 수 있고, 수가는 덮어쓰지 않고 **새 버전**으로 쌓입니다.
  - **AI 모델 가중치** — 격리 구간 밖에서 받아 모델 저장소째 옮깁니다 → [S6](S6-ai.md).
  - 그 밖(공공 데이터 원본 · 시스템별 기준 데이터)의 반입 방법은 `확인 필요(따라가기)`.
- 격리를 어떤 수단(방화벽 · 호스트 규칙 등)으로 할지는 기관의 망 구성에 따릅니다. **나가는 연결을 무엇으로 파악하는지는 시스템마다 다릅니다**(2026-09-16 기준 커밋 확인).
  - **HIS** — 외부로 나가는 호출 지점의 목록이 제품 안에 있고 대외 발신 관제 화면에 함께 나옵니다 → [S1](S1-core-his.md). AI 요청 목적지는 허용 목록(`AI_EGRESS_ALLOWED_HOSTS`)으로 따로 통제하며, **비어 있으면 외부 호스트로 보내지 않습니다** → [S6](S6-ai.md).
  - **그 밖의 시스템** — 이런 목록이 없습니다. 출발점은 [바꿔야 할 코드 기본값](replace-list.md)의 `주소` 분류(기준 커밋에서 센 파일 목록)이고, **그 목록에 없는 형태는 잡히지 않습니다.** 시스템별로 막아야 할 나가는 연결의 완전한 목록은 `확인 필요(따라가기)`.

## ③ 설정 — 설치 전에 정리해 둘 값

이 단계에서는 값을 넣지 않고 **값 대장**을 만듭니다. 대장은 기관 내부 문서로 두고, 공개 자료나 저장소에 올리지 않습니다.

| 무엇 | 들어갈 곳(키 이름) | 비고 |
|---|---|---|
| 국가 | HIS `hospital.country` | 결정 `country.institutionProfile` 을 기록하면 시스템이 이 값을 바꿉니다. 아무도 정하지 않으면 KR 로 동작합니다(결정 등록부 문구) |
| 기관명 · 영문명 | HIS `hospital.name` · `hospital.nameEn` | 코드에 고정된 병원명이 따로 있습니다 → [S1](S1-core-his.md) |
| 주소 · 영문 주소 | HIS `hospital.address` · `hospital.addressEn` | |
| 진료과 | HIS 진료과 마스터 | 🔴 **더하는 화면이 없습니다** — 아래 「진료과는 화면에서 더할 수 없습니다」 |
| 시스템별 서비스 주소 | 각 시스템 설정 → 단계별 ③ | `<your-hospital>.example.org` 처럼 기관 도메인 체계를 먼저 정합니다 |
| 비밀값 목록 | 각 시스템 환경 파일 | 누가 만들고 어디에 보관하는지 정합니다. 여러 시스템이 **같은 값을 나눠 가져야 하는 비밀키**가 있습니다(ERP · Jitsi) → [S5](S5-management.md) · [S2](S2-patient-access.md) |

**진료과는 화면에서 더할 수 없습니다.** 기준 커밋을 읽어 확인했습니다(2026-09-16).

- 진료과 목록의 정본은 **진료과 마스터 한 곳**이고, 기본 시드가 **36개**를 넣습니다(임상 18 · 내과 세부 8 · 의료지원 6 · 행정 4 — 시드 코드에서 셌습니다). 화면들은 각자 목록을 들고 있지 않고 이 마스터를 읽습니다.
- 🔴 **이 마스터를 더하거나 고치는 API 가 없습니다.** 조회(`GET /api/v1/codes/departments`)만 있고, 진단 · 처치 · 약품 코드에는 있는 추가 · 수정 · 삭제가 진료과에는 없습니다. 그래서 기관 고유 진료과는 **DB 에 직접 넣어야 합니다.**
- 관리 화면의 「진료과 코드 카탈로그」(`/admin/dept-catalog`)는 **진료과를 더하는 곳이 아닙니다** — 이미 있는 진료과에 표준 약물 · 검사 · 영상 코드와 처방 가이드를 붙이는 화면입니다.
- 마스터에 없는 이름이 이미 쓰이고 있어도 화면에서 사라지지 않습니다(마스터와 현재 저장값을 함께 보여줍니다). 어휘를 정리할지는 기관이 정합니다.

## ④ 사람이 정할 것

### 결정 3층과 권한자 지정

결정 등록부(`/admin/decisions`)는 결정을 대신하지 않습니다. **무엇을, 누가 정하는지**와 선택지를 적어 둡니다. 세 층을 섞지 않고, 하위 층이 상위 층을 대신하지 못합니다.

| 층 | 무엇을 정하나 | 등록부에 나오는 결정권자(역할) — 기관이 사람을 지정 |
|---|---|---|
| **허가권자** — 법적 운영 요건 | 법령 · 인허가 · 위탁계약이 정하는 것 | 개설자 · 원장 · 개인정보보호책임자(CPO) · 정보보호책임자(CISO) · 법무 · 규제 자문 · 원무(보험)팀장 · 국제사업 책임자 |
| **원내 위원회** — 운영 정책 | 법적 요건 안에서 병원이 정하는 정책 | 의료기기 · AI 거버넌스 위원회 · 질향상 · 환자안전위원회(QPS) · 의무기록위원회 · 정보보호위원회 · 의료정보위원회 · 진료부 · 간호부 · 약제부 등 |
| **직원** — 건별 현장 판단 | 이 환자에게 지금 할 것인가 | 업무 화면의 승인 창에서 담당 직원이 판단합니다 |

- **위원회는 기본값으로 9종이 들어 있습니다** — `DTC` 약사 · `IC` 감염관리 · `MRC` 의무기록 · `QPS` 질향상·환자안전 · `TRF` 수혈 · `ETH` 병원윤리 · `NUT` 영양 · `SAFE` 안전관리 · `OPS` 운영. 위원회마다 **정족수와 회의 주기**(월례 · 분기 · 수시)가 기본값으로 붙어 있고, 기관은 이 값을 자기 규정에 맞게 고칩니다. 위원회 코드 기준으로 덮어쓰는 방식이라 **기관이 위원회를 더하거나 이름을 바꿀 수 있습니다**(근거: HIS 기준 커밋 `apps/api/src/modules/gld/governance.service.ts` 의 위원회 기본 목록 · 2026-09-12 확인).
- 결정 등록부에는 이 밖의 위원회(의료기기 · AI 거버넌스 · 정보보호 · 의료정보)도 결정권자로 나옵니다. 기본 9종에 없는 위원회를 쓰려면 **이 단계에서 먼저 등록합니다.**
- **정책성 설정에는 담당 위원회가 이미 붙어 있습니다.** 예를 들어 투약 바코드 확인 강제 · 마취 전 평가 게이트 · 퇴원 게이트 · **AI 서버 사용 마스터 스위치**는 질향상·환자안전위원회가 담당으로 등재돼 있습니다. "근거 없이 켜져 있던 설정"을 담당 위원회에 배정하는 작업이 코드에 들어 있습니다 → [취지 4](../overview/02-principles.md).
- **결정을 화면에 기록할 수 있는 계정 권한**: 안건 등록 · 의결 · 시행은 `ADMIN`, 일부 조회와 조치 확인은 `EXECUTIVE` 도 함께, 결정 목록 열람은 `DOCTOR` · `NURSE` 까지 열려 있습니다(근거: 같은 모듈의 역할 선언 · 2026-09-12 확인). 계정 자체를 만드는 것은 [S1](S1-core-his.md).
- 이 단계에서 권한자를 **사람으로** 지정해 두지 않으면, 이후 단계의 결정이 모두 "미결"로 남습니다.

### 이 단계의 결정 (9)

| 키 | 층 | 개시 관계 | 무엇을 정하나 |
|---|---|---|---|
| `country.institutionProfile` | 허가권자 | 🔴 개시 전 필수 | 이 설치본이 어느 나라 기관인가(KR · AE). 기록하면 `hospital.country` 에 반영됩니다 |

| 아직 안 되는 것 | 대체 수단 |
|---|---|

| 소스 저장소의 라이선스 표기가 MIT 로 정리되지 않았습니다 | 받을 때 그 저장소의 표기를 확인하고 매니페스트와 대조합니다 |
| 처리량 · 응답 시간 · AI 품질이 계측되지 않았습니다 | 따라가기에서 잰 것은 **메모리 사용과 디스크 · 이미지 크기**뿐이고, 개발 PC(arm64 · GPU 없음)라 기준 장비가 아닙니다. 하한 기록(8코어 · 16GB)과 위 저장 공간 실측만 참고하고, 여유를 두고 확보합니다 |

| 화면 번역은 모두 AI 초안이고 사람 검수를 마친 것이 없습니다 | 검수 주체를 [S1](S1-core-his.md)의 `i18n.*` 결정으로 정합니다 |
| 제3자 구성요소의 판본 일부(Orthanc 이미지 안 판본 · `latest` 태그)가 미확정입니다 | 받는 날의 판본을 기관 대장에 적습니다 |

## ⑦ 흔한 함정

- **받는 날에 따라 판본이 바뀌는 태그.** `7-alpine` · `latest` 같은 태그는 다시 받으면 판본이 바뀌고, Redis 는 판본에 따라 약관도 바뀝니다. 받은 판본을 적어 둡니다.
- **커뮤니티 재포장 모델 태그.** 일부 기본 태그는 원 개발사가 아닌 제3자가 올린 것입니다. 원본과 같은지, 원 약관이 그대로 적용되는지는 기관이 확인합니다.
- **"기록 없음"은 "미완료"가 아닙니다.** 이미 했지만 화면에 적지 않았을 수 있습니다. 반대로 화면에 적지 않은 것은 시스템이 모릅니다.
- **결정은 "정했다"와 "그렇게 됐다"가 다릅니다.** 결정마다 적용 방식(시스템 반영 · 위원회 이행 · 배포 필요 · 기록만)이 다르므로 상태를 따로 봅니다.
- **위원회 의결로 허가권자 결정을 대신하지 않습니다.** 층을 섞으면 등록부가 결정의 근거를 잃습니다.
- **주소를 바꾸기 전에 격리를 풀지 않습니다.** 격리를 먼저 풀면 다른 설치본으로 요청이 나갈 수 있습니다.
- **디스크를 데이터 기준으로만 잡는 것.** 따라가기에서는 **빌드 이미지와 모델 때문에** 먼저 가득 찼고, 그 순간 데이터베이스가 복구 모드로 들어갔습니다. 설치 중에도 남은 용량을 봅니다.
- **이미지를 받을 수 있는지 확인하지 않고 설치를 시작하는 것.** 고정 태그가 레지스트리에서 사라진 경우가 실제로 있었습니다(따라가기).

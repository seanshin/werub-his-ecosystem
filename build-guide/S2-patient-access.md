## ② 설치

> 🔴 **이 단계는 따라가기에서 설치하지 않았습니다**(2026-09-13~16). 공개 홈페이지 · 환자 앱 · 원격 화상(Jitsi)은 새 설치본으로 세워 보지 않았고, 웹 환자 포털만 HIS 와 함께 올라와 있었습니다. 아래 설치 · 설정 내용은 **기준 커밋의 코드와 저장소 문서를 읽고 쓴 것**이며, 명령 · 순서 · 함정이 실제로 그대로인지는 확인하지 못했습니다. 공개 홈페이지 → HIS · 환자 앱 → HIS 연결도 실제 호출로 확인하지 않았습니다(연결 표 `구현·미검증`).

| 구성 요소 | 구현 상태 | 설치 |
|---|---|---|
| 공개 홈페이지 | `운영` | HIS 저장소의 별도 Next.js 앱(`apps/homepage`). **격리 빌드**라 공용 패키지를 직접 쓰지 않고 복제본 + 대조 검사로 맞춥니다. HIS 웹 · API 배포와 **따로 발행**하며, 발행은 사람이 합니다. 발행은 앱 자체 명령(`next build`)이 아니라 저장소의 **홈페이지 빌드 스크립트**(`infra/scripts/build-homepage.sh`)가 합니다 — HIS 관리 화면의 「홈페이지 배포」 버튼이 이 스크립트를 뒤에서 부르고, 스크립트는 진행 상태를 상태 파일(JSON)에 적어 **화면이 그 파일을 읽어 진행·결과를 보여 줍니다.** 🔴 목적지(정적 호스팅 위치 · 리전 · API 원본)가 **환경 변수의 기본값으로 특정 설치본 값을 갖고 있으므로 자기 기관 값으로 바꿉니다**(S0 · S1). 빌드에는 **빌드 스탬프**가 들어가, 라이브가 「지금 어느 빌드를 서비스 중인가」에 기계로 답할 수 있게 합니다 |
| 웹 환자 포털 | (HIS 에 포함) | HIS 웹과 함께 올라갑니다 → [S1](S1-core-his.md) |
| 환자 앱 | `개발` · 스토어 미배포 | HIS 저장소의 `apps/mobile`(Expo · React Native). HIS 서버 배포와 무관하며, 앱 빌드와 스토어(또는 기관 배포 경로)를 거쳐야 기기에 반영됩니다. 🔴 **저장소의 작업 스크립트에는 개발 실행만 있습니다**(`expo start` · `--android` · `--ios` · `--web`). **스토어 빌드 · 제출 명령은 저장소에 없습니다** — 기관이 Expo 의 표준 빌드 경로를 따로 정합니다(2026-09-12 기준 커밋 확인) |
| 원격 화상(Jitsi) | `중단` | 🔴 **현재 설치본은 동작하지 않습니다. 새로 구성합니다.** 기본 구성 파일로 9개 컨테이너를 올리고, 실시간 자막은 별도 구성 파일을 겹쳐 켭니다(선택). 순서는 **`.env` 예시 복사 → 비밀값 생성 스크립트(`scripts/generate-secrets.sh`) → compose 기동** 입니다. 생성 스크립트는 `.env` 의 **빈 비밀번호 칸만** 무작위 값으로 채웁니다(XMPP 구성요소 · 녹화 · TURN). 실시간 자막은 `docker-compose.transcription.yml` 을 겹쳐 켭니다. 저장소에는 상태 점검 · 연동 시험 · 부하 시험 · 녹화 백업 · 한국어 덮어쓰기 스크립트도 함께 있습니다 |

Jitsi 구성요소(Jitsi Meet · Jicofo · Videobridge · Jibri · Jigasi)는 Apache-2.0, coturn 은 BSD-3-Clause, Prosody 는 MIT 입니다([THIRD_PARTY.md §1](../THIRD_PARTY.md#1-별도-서비스로-쓰는-제3자-서버)).

## ③ 설정

### 공개 홈페이지

- 🔴 **기관 정보가 코드에 있습니다.** 병원 이름 · 연락처 · 주소가 사이트 정보 상수 파일에, 일부 소개 문구 · 수치가 페이지 소스에 들어 있습니다. 병원명 고정 문자열이 든 파일이 이 앱에 36개 있습니다(HIS 저장소 118개 중 · 2026-09-10 계측). 코드를 고쳐 바꿉니다.
- 환경 파일의 키 이름(설정 예시 기준): `HOMEPAGE_API_ORIGIN` · `INTERNAL_API_URL` · `NEXT_PUBLIC_API_URL`. 모두 자기 기관 주소로 바꿉니다.
- 브라우저는 HIS API 를 **상대 경로**로 부릅니다. 공개 사이트와 HIS API 를 같은 출처 뒤(역방향 프록시 등)에 두는 구성을 전제로 합니다.
- 콘텐츠는 HIS 의 홈페이지 콘텐츠 관리(CMS) 화면에 넣습니다. 편집 화면이 "비어 있는 항목"으로 표시하는 자리를 채우지 않으면 공개 화면이 비거나 기본 모양으로 나옵니다.

### 환자 앱

- HIS API 주소 `EXPO_PUBLIC_API_URL` 과 원격진료 화상 주소 `EXPO_PUBLIC_TELEHEALTH_URL` 을 **앱 빌드 환경변수로 반드시 지정**합니다. 지정하지 않으면 코드에 적힌 기본 주소로 연결됩니다.
- 푸시를 쓰려면 앱에 알림 패키지와 설정을 추가하고, HIS 에서 환자 앱 푸시 발행을 켭니다(기본 꺼짐).

### 알림 채널과 대외 발신

- HIS 의 대외 발신은 **세 조건**(구현 + 설정(기본 꺼짐) + 승인)을 모두 갖춰야 나갑니다. 채널별 상태는 대외 발신 관제(`/admin/outbound-channels`)에서 봅니다.
- 환자 앱 알림 마스터는 `notification.patientPush.enabled` 입니다. 결정 `policy.patientPush.enable` 을 기록하면 시스템이 이 값을 바꿉니다.
- 문자 발송 제공자는 **등록돼 있지 않습니다.** **등록에 필요한 것은 `대외 발신 관제`(`/admin/outbound-channels`) 화면이 세 가지로 나눠 보여 줍니다**(2026-09-12 확인 · [화면 소개](../screens/his.md#대외-발신-관제--구현--설정--승인)).

  | 조건 | 무엇 | 어디서 |
  |---|---|---|
  | ① 위탁계약 | **허가권자 결정** — 개인정보 처리위탁 계약을 근거 문서와 함께 기록 | [결정 등록부](../checklist/decisions.md) |
  | ② 제공자 코드 구현 | 🔴 **아직 구현되어 있지 않습니다** — 개발 작업이며, 이 화면에서 켜지지 않습니다 | — |
  | ③ 제공자 · 발신번호 설정 | 제공자명과 **사전등록된 발신번호**를 화면에서 기록(비어 있는 설정 키를 화면이 그대로 알려 줍니다) | 같은 화면의 입력란 |

  화면이 현재 상태를 못 박습니다 — 🔴 **"지금은 설정을 저장해도 문자가 나가지 않습니다 — 제공자 코드가 구현되어 있지 않습니다. 그동안 인증번호는 서버 로그에만 남습니다(실환자 개시 불가)."** ②가 끝나기 전에는 ①·③을 갖춰도 발송되지 않습니다.

### 원격 화상(Jitsi)

- 필수 설정: 도메인 · 공인 주소 · **JWT 공유 비밀키(HIS 쪽 값과 같아야 함)** · TURN 비밀값. HIS 웹이 여는 화상 주소 키는 `NEXT_PUBLIC_JITSI_URL` 입니다.
- 운영 전에 정할 것: 내부 콜백 비밀값(`INTERNAL_SECRET`) · API 키 발급과 권한 · 녹화 보존 기간 · 녹화 외부 저장 여부.
- 방화벽: 미디어 중계와 TURN 용 UDP · TCP 포트를 **방화벽의 모든 계층에서** 엽니다. 포트 목록은 Jitsi 저장소 README 에 있습니다.
- 역방향 프록시는 저장소의 경로별 프록시 설정 파일을 기준으로 삼습니다. 관리용 대시보드는 기본으로 서버 안에서만 열립니다.

### 로그인 방식

HIS 와 Jitsi(와 회의 관리 API)는 **같은 공유 비밀키**로 토큰을 서명 · 검증합니다. 공개키 검증 방식이 아니므로 비밀키의 보관 · 교체를 따로 관리해야 합니다.

| 아직 안 되는 것 | 대체 수단 |
|---|---|

| 원격 화상 연결이 모두 `중단` 입니다(HIS → Jitsi 3 · 환자 앱 → Jitsi 1) | Jitsi 를 새로 구성합니다. 구성 전에는 비대면 진료 화면에서 화상을 쓸 수 없습니다 |
| Jitsi 모바일 웹 지원이 보류 · 차단돼 있습니다 | 데스크톱 브라우저로 운영합니다. **대안은 설정이 아니라 사람 결정입니다** — 아래 「모바일에서 왜 막히나」 |
| HIS 가 Clinic · Jitsi 에 주는 단기 토큰 교환은 `설계만` 입니다 | 지금은 공유 비밀키 방식으로 붙습니다 |
| 앱 화면에는 다국어가 없고, 홈페이지는 영어 · 일본어 · 중국어 소개 한 장씩입니다 | 외국인 환자 안내는 웹 포털 · 원내 창구로 보완합니다 |
| 환자 포털의 외부 영상(DICOM) 업로드 중계는 `미구현` 입니다 | → [S3](S3-clinical-departments.md) |

**모바일에서 왜 막히나.** 기준 커밋을 읽어 확인했습니다(2026-09-16).

- 화상 서버의 화면 설정에 **모바일 앱 권유가 꺼져 있고**, 스타일시트에 **모바일 미지원 안내 화면**("모바일에서는 화상회의를 이용할 수 없습니다 / PC · 노트북으로 접속해 주세요")이 한국어로 따로 만들어져 있습니다. 즉 **막은 것이 실수가 아니라 의도**입니다.
- 동시에 서빙 설정에서 **딥링크 연결이 켜져 있어**, 모바일로 들어오면 앱으로 보내는 안내 화면을 먼저 만나게 됩니다.
- 🔴 그래서 **"설정 한 줄로 켜는 대안"이 없습니다.** 저장소 자신의 기록도 모바일 웹 지원을 켤지 말지를 **실기기 확인과 사업 · 지원부담 판단이 필요한 미결정 항목**으로 남겨 두었습니다.
- 기관이 할 수 있는 것은 둘입니다 — ① 데스크톱 전용으로 운영하고 **예약 단계에서 "PC 가 필요하다"를 미리 안내**하거나, ② 모바일 웹을 켜기로 **결정하고** 실기기 확인을 포함한 재구성을 하는 것입니다. 어느 쪽이든 [S7](S7-rehearsal.md)에서 동작을 확인합니다.

연결 상태: 공개 홈페이지 → HIS 2개 · 환자 앱 → HIS 1개가 `구현·미검증` 입니다([연결 상태](../RELEASES/draft/compatibility.md)).

## ⑦ 흔한 함정

- **앱 빌드 환경변수를 비워 두는 것.** 코드의 기본 주소로 연결됩니다. 반드시 자기 기관 주소로 빌드합니다.
- **홈페이지를 HIS API 와 다른 출처에 두는 것.** 상대 경로 호출이 깨집니다.
- **공용 표현 프리셋을 바꾸고 복제본을 동기화하지 않는 것.** 저장소 스크립트(`sync:cms-style`)를 돌리지 않으면 대조 검사가 실패합니다. 앱의 복제본(검사 판정 규칙 · 안내 문구)도 같습니다.
- **Jitsi 방화벽을 한 계층만 여는 것.** 3명 이상 통화에서 영상이 끊긴다고 저장소 문서가 적습니다.
- **Jitsi 공유 비밀키를 한쪽만 바꾸는 것.** 맞춰야 하는 값은 **`JWT_APP_ID` 와 `JWT_APP_SECRET`** 입니다(Jitsi 쪽 환경 예시 기준). 🔴 **비밀값 생성 스크립트는 빈 칸을 무작위로 채우므로, Jitsi 쪽에서만 돌리면 HIS 가 발급한 토큰이 거절됩니다.** 바꿀 때는 양쪽을 같은 시점에 바꿉니다 → [신원 허브](../diagrams/identity-hub.md). 교체 중 통화 중단을 어떻게 다룰지는 `확인 필요(따라가기)`.
- **Jitsi 웹 설정을 바꾸고 컨테이너를 다시 만들지 않는 것.** 인터페이스 설정은 컨테이너를 다시 만들어야 반영됩니다.
- **결정 순서를 건너뛰는 것.** 적법 근거 확인 전에 알림 마스터를 켜지 않습니다.

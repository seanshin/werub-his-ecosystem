# S1 코어 HIS — 설치 · 기관 정보 · 코드 마스터 · 조직 · 병원 규정

> ⚠️ 초안 — **새 설치본으로 한 번 따라가 본 결과를 반영했습니다**(2026-09-13~16 · 개발 PC 한 대 · arm64 · 8GB 가상 머신 · GPU 없음 · 외부로 나가지 못하는 네트워크). 남은 `확인 필요(따라가기)` 표시는 x86 · GPU 기준 장비나 사람 결정이 필요한 곳입니다. · 기준 HIS v4.18.0(`e9d303984f80`) · 2026-09-11 · [가이드 목차](README.md)

> **EN** — Stage S1 stands up the core HIS — the record of patients, encounters, orders and billing, and the identity hub that issues staff tokens for every sibling system. Walking it on a fresh install showed the repository's own container files do not run as-is (image build, schema apply and start-up all had to be worked around), and the default seed switches some AI and patient-notification features on. Both are written out here.

## ① 목적과 완료 조건

생태계의 코어이자 **신원 허브**인 HIS 를 격리 네트워크 안에 세웁니다. 직원 로그인 토큰을 HIS 가 발급하고 다른 시스템이 검증하므로, 이후 모든 단계가 HIS 에 기댑니다.

완료 조건:

- [ ] HIS 웹 · API · 상시 감시자가 떠 있고, 시스템 설정 화면(`/admin/config`)이 열린다
- [ ] 🔴 HIS 저장소의 **설치본 주소 기본값을 자기 기관 값으로 바꿨고**, 격리 상태에서 밖으로 나가는 요청이 없음을 확인했다
- [ ] 화면 · 발급 문서에 **자기 기관명**이 나온다(코드에 고정된 병원명 교체 포함)
- [ ] 🔴 개인식별정보 암호화 키를 새로 만들었다(`security.encryptionKey` 통과)
- [ ] 🔴 정기 암호화 백업이 돈다(`security.dbBackup` 통과)
- [ ] 국가에 맞는 코드 마스터를 반입했다
- [ ] 부서 · 병상 · 직원 · 역할을 등록했다
- [ ] 🔴 요양기관 종별을 정했다(`billing.institutionType`)

기관 기본정보 가운데 인허가에서 나오는 값(요양기관 기호 · 사업자등록번호 · 대표자 등)은 이 단계에서 다 채우지 못할 수 있습니다. 그 값은 [S8](S8-go-real.md) 전에 확정합니다.

### 설치 순서

HIS 저장소 README 의 **Quick Start** 가 안내하는 순서는 다음과 같습니다(명령 이름은 기준 커밋의 README 표기).

```sh
npm install          # 의존성 설치
npm run docker:up    # PostgreSQL + Redis 컨테이너 기동
npm run db:migrate   # 마이그레이션
npm run db:seed      # 시드(가상 병원 데이터)
npm run dev          # 실행 — 개발 실행
```

- 위 명령은 **개발 실행**입니다(`nest start --watch`). 운영 설치본은 명령이 다릅니다 — **빌드**(`npm run build`) → **스키마 반영** → **기동은 빌드 산출물 실행**(`node dist/main`).
  - **프로세스 관리자는 pm2 입니다**(기준 커밋 배포 스크립트 확인 · 2026-09-17). 프로세스는 넷으로 나뉘어 있습니다 — API · 웹 · 터널 · 프록시. 이름과 실행 정의의 정본은 **저장소가 아니라 서버 쪽 pm2 설정 파일**에 있습니다(저장소에는 그 파일이 없습니다).
  - **상시 감시자는 API 와 별개의 pm2 프로세스**입니다(`apps/api/dist/sentinel.main.js`). API 를 배포할 때 함께 재시작합니다 — **감시자가 낡으면 감시가 낡기 때문**입니다. 감시자는 정합성 점검 SQL 파일(`infra/scripts/data-integrity-scan.sql`)을 읽으므로 **소스만 올리고 이 파일을 빠뜨리면 매 주기 실패합니다.**
  - 🔴 **감시자에는 HTTP 표면이 없습니다.** 살아 있는지는 pm2 상태와 기동 로그로만 확인합니다. 빌드가 감시자 진입점을 만들지 못하면 pm2 는 "스크립트 없음"만 남기고 배포는 계속되며, **화면은 영원히 「미판정」으로 남습니다** — 배포 스크립트가 이 경우를 먼저 확인하고 멈추도록 되어 있습니다.
  - 메모리 상한은 API 와 감시자에 각각 걸려 있고(감시자 쪽이 더 낮습니다), 웹은 무중단 교체라 상한을 걸지 않습니다. **재부팅 복원은 pm2 의 저장된 프로세스 목록으로만** 되므로, 새로 띄운 프로세스는 저장해야 재부팅 뒤에도 살아납니다.
- 🔴 **스키마 반영은 `prisma migrate deploy` 가 아니라 `prisma db push` 입니다**(2026-09-13 따라가기에서 정정 · 이전 판의 이 가이드가 틀렸습니다). 기준 커밋의 `migrations/` 폴더에는 파일이 3개뿐이고, `migrate deploy` 는 그중 한글 검색 인덱스 파일에서 **트랜잭션 안에서는 실행할 수 없다는 오류로 멈춥니다.** 저장소의 배포 스크립트도 `db push` 만 쓰고, 해당 파일 머리말이 "migrations/ 는 수동 적용 전용"이라고 적습니다. 새 DB 에서 확인한 순서:
  1. MRN 시퀀스와 `pg_trgm` 확장 — `npx prisma db execute --file prisma/migrations/00000000000000_create_mrn_sequence/migration.sql --schema prisma/schema.prisma`
  2. `npx prisma db push` — 새 DB 에서 수 초
  3. 한글 검색 GIN 인덱스는 **API 가 기동할 때 스스로 만듭니다**(기동 로그 "pg_trgm GIN indexes ensured").
  - `prisma/manual/` 의 **수동 SQL 110개**(+ 안내 README)를 `db push` 직후 DB 와 대조했습니다(2026-09-13) — **57개는 이미 반영돼 적용할 것이 없고**, **34개는 `db push` 가 만들지 않는 DB 객체**(인덱스 79개 · 🔴 **검진권 이벤트를 고치지 못하게 막는 트리거 1개와 그 함수**)를, **19개는 기준 데이터 · 데이터 보정**(KCD 8차 마스터 · 간호 코드 · 고위험 약물 · 약가 등)을 담고 있습니다. 새 설치에도 뒤의 두 묶음은 필요합니다. 파일마다 적용 순서 · 다시 돌려도 되는지 · 시드와의 선후가 달라, **전체 순서는 저장소에 없습니다.** 여기까지는 확인했습니다(기준 커밋에서 셈 · 2026-09-17).
    - **110개 중 96개**는 다시 돌려도 안전한 형태(`IF NOT EXISTS` · `IF EXISTS` · `ON CONFLICT` · `CREATE OR REPLACE`)를 쓰고, **14개**는 그런 표현이 없어 **두 번 돌리면 어떻게 되는지 파일을 열어 봐야 합니다.**
    - 순서 안내가 있는 것은 **검진권 묶음 하나뿐**입니다(`prisma/manual/README-voucher-migrations.md` — 11단계를 번호로 적어 두었고 모두 재적용 안전). 나머지 묶음에는 그런 안내가 없습니다.
    - 이 파일들이 `db push` 밖에 있는 이유도 그 안내가 적고 있습니다 — 한 기능의 미적용 스키마 변경이 `db push` 전체를 막아, 우회로 손으로 넣게 된 것입니다. **새 설치에서는 그 막힘이 없을 수 있으므로**, 넣기 전에 해당 객체가 이미 있는지부터 봅니다.
  > ⚠️ `prisma migrate dev` 를 운영 DB 에 쓰지 않습니다. 개발용 명령은 스키마가 어긋나면 **데이터베이스를 다시 만들자고 제안**합니다.
- 기본 시드는 **가상 병원 데이터**이고, 특정 기관명이 들어 있습니다. 가상 데이터는 S7 리허설까지 쓰고 S8 에서 격리합니다.
- 🔴 **첫 관리자 계정을 만드는 경로가 기본 시드뿐입니다.** 초기 관리자를 만드는 스크립트나 환경 변수가 없고, 기본 시드는 직원 계정 88개 · 환자 30명을 **공용 비밀번호**로 만듭니다(따라가기 2026-09-13). 시드로 들어가 → 기관 관리자 계정을 만들고 → 시드 계정을 정리하는 순서가 됩니다(정리 스크립트는 없음 → [S8](S8-go-real.md)).
- 🔴 **기본 시드는 결정 없이 기능을 켭니다** → [S6 1단계](S6-ai.md). 시드를 돌린 뒤에는 `/admin/config` 에서 켜진 것부터 확인합니다.
- 시드 스크립트는 **형 검사를 통과하지 못합니다**(지금 스키마에 없는 필드 · 소스 폴더 import). 실행은 형 검사를 끄고(`TS_NODE_TRANSPILE_ONLY=true`) 하면 끝까지 돕니다(따라가기 2026-09-13).
- 운영 환경 파일의 키 이름(설정 예시 파일 기준): `DATABASE_URL` · `REDIS_URL` · `DB_PASSWORD` · `REDIS_PASSWORD` · `AUTH_SECRET` · `AUTH_REFRESH_SECRET` · `ENCRYPTION_KEY` · `PUBLIC_URL` · `NEXT_PUBLIC_API_URL` · `TZ` · `LOG_LEVEL`. 비밀값은 설치 때 새로 만들고 서버의 환경 파일에만 둡니다.
- **전체 목록은 HIS 저장소 안에 있습니다** — `docs/05-reference/configuration-manual.md`(기준 커밋 · 553줄). 이 문서는 목록을 **코드에서 수집해** 만든 것이라고 스스로 적습니다. 위 설정 예시 파일에는 **6개만** 들어 있고, 기준 커밋의 API·웹 소스가 실제로 읽는 환경 변수는 **50개**입니다(`process.env.*` 를 세어 확인 · 2026-09-17). 예시 파일만 보고 설치하면 모자랍니다.
- 그 문서는 **설정이 네 군데에 나뉘어 산다**고 정리합니다 — ① 환경 변수(접속 정보 · 비밀값 · 위험을 여는 스위치 · 재시작 반영) ② 런타임 설정(병원 정보 · 표기 · 임상 정책 — 화면에서 바꾸고 **즉시 반영**) ③ 안전 게이트(②의 부분집합 · 끔/경고/차단) ④ 빌드 시점 상수(`NEXT_PUBLIC_*` — **재빌드·재배포해야 반영**). **①과 ②를 섞지 않는 것**이 규칙입니다.
- **없으면 API 가 아예 뜨지 않는 값이 넷** 있습니다 — DB 접속 주소 · 인증 서명 비밀 · 인증 갱신 비밀 · 필드 암호화 키. 길이·형식 검증까지 하고, 통과하지 못하면 기동을 멈춥니다(`apps/api/src/common/env.validation.ts`).
- 🔴 **필드 암호화 키를 바꾸면 기존 암호문을 복호할 수 없습니다**(단일 마스터키 설계). 키 파생에 쓰는 값도 같습니다 — 바꾸려면 전 필드 재암호화가 함께 가야 합니다. 설치 때 정하고 그대로 둡니다.

### 코드 마스터 반입

코드 마스터는 이 저장소에도 소스에도 없습니다. **기관이 배포 기관에서 직접 받아 반입합니다**([THIRD_PARTY.md §4](../THIRD_PARTY.md#4-코드-마스터기준-데이터)).

|---|---|---|
| 약제급여목록 · 약가(의약품 표준코드 포함) · 저가약 대체조제 목록 | 건강보험심사평가원 | 이용 조건 확인 필요 |
| 수가 · 치료재료 코드(EDI 행위 · 검사 코드) | 건강보험심사평가원 · 보건복지부 고시 | 이용 조건 확인 필요 |
| KCD(한국표준질병·사인분류) | 국가데이터처(구 통계청) | **제9차가 2026-01-01 부터 시행 중**이고, 생태계 코드의 KCD 표기는 기준일에 제8차입니다 |
| DUR 금기 정보 · 의약품 개요정보 | 식품의약품안전처(공공데이터포털) | AI Server 도 씁니다 → [S6](S6-ai.md) |
| 법정감염병 목록 | 질병관리청 | |
| LOINC · SNOMED CT | Regenstrief Institute · SNOMED International(국내 배포 센터 등록) | 조건이 있는 라이선스 |

- **반입 화면과 형식**(HIS 기준 커밋 코드 · 2026-09-13 확인): `코드 마스터`(`/admin/codes`)의 **「고시 개정 일괄 반영」** 패널입니다.
  - 종류는 **진단 · 행위(수가) · 약품** 셋, 파일은 **CSV/TSV 본문을 붙여넣기**(헤더 포함 · **8MB 상한** — 넘으면 나눠 올림), 필수 열 `code` · `nameKo` · 선택 열 `category` · `unitPrice`(진단 제외), 그리고 **시행일**(YYYY-MM-DD).
  - 🔴 **미리보기는 아무것도 저장하지 않습니다** — 차이 리포트를 먼저 보고, 사람이 확인한 뒤 반영합니다. 반영할 때 **수가는 새 버전으로 쌓이고, 나머지는 덮어씁니다.**
  - 약품 보험코드 매핑은 `/admin/drug-mapping` 에서 따로 봅니다. 🔴 **파일을 올려 반입하는 자리는 기준 커밋에 없습니다**(2026-09-17 확인) — 그래서 "원본 파일을 어떤 열 형식으로 바꾸나"라는 질문 자체가 성립하지 않습니다. 이 화면이 주는 길은 셋입니다: ① 자동 매칭 결과를 **미리 보고** 적용 ② 한 건씩 손으로 짝짓기 ③ ERP 에서 **확정된 매핑을 당겨오기**(이 경로는 따라가기에서 끝까지 확인했습니다 → [S5](S5-management.md)). 기관이 가진 원본 파일에서 출발하려면 **그 파일을 ①②③ 중 하나가 읽는 형태로 넣어 주는 일을 기관이 따로** 해야 합니다.
- 🔴 **코드 마스터 반입에는 국가 축이 없습니다**(2026-09-17 확인). 기준 커밋의 반입 엔드포인트는 **한국 기준 데이터**(고시 코드 · 수가 · 약가 · 중증도 점수 등)로 고정돼 있고, 나라를 골라 다른 마스터를 넣는 자리는 없습니다. 국가 축(`hospital.country`)은 **보유·파기 기간과 표기 쪽에만** 있습니다 — 다른 나라에 세울 때 코드 마스터는 기관이 따로 마련해야 하고, 그 반입 경로도 없습니다.
- 다른 시스템에서 들어오는 마스터도 있습니다 — ERP 의 수가 · 비급여 · 재료대 마스터 적재와 약품 코드 매핑([S5](S5-management.md)), LIS 의 검사코드 카탈로그([S3](S3-clinical-departments.md)). 모두 `구현·미검증` 입니다.

### 부서 · 병상 · 직원 · 역할

- 사용자 역할은 14종입니다(임상 4 · 지원 9 · 관리자 1 — 스키마의 역할 열거값 수 · 2026-09-11 확인).
- 기준 커밋에는 직원 관리 · 역할 권한 · 진료과 카탈로그 · 시설 관리 화면(`/admin/staff-management` · `/admin/rbac` · `/admin/dept-catalog` · `/admin/facility`)이 있습니다.
  - 🔴 **병동 · 병상을 등록하는 화면도 API 도 기준 커밋에 없습니다**(2026-09-17 확인). `/admin/facility` 는 **등록된 것만 보여 주는 화면**이라고 스스로 적고, 병상 화면은 **상태를 바꾸는 것만** 할 수 있습니다(빈 병상 · 사용 중 · 예약 등). 병동 · 병상 자료 구조는 있고 **시드가 만들어 넣습니다.**
  - 그래서 기관 고유의 병동 · 병상은 **시드를 고치거나 DB 에 직접 넣어야 합니다.** 진료과도 같은 모양입니다(더하는 API 없음 → [S0](S0-prepare.md)). 입력 순서는 **병동 · 병상이 먼저**입니다 — 직원 · 입원 배정이 그 위에 붙습니다.
- 직원 등록은 뒤 단계의 기반입니다. 그룹웨어(Clinic) · 교육(edu) · ERP 가 HIS 직원 명부를 받아 갑니다([S5](S5-management.md)).

### 🔴 코드에 고정된 병원명

HIS 저장소에는 병원명이 **고정 문자열**로 남은 파일이 118개 있습니다(2026-09-17 기준 커밋에서 다시 셈에서 다시 셈 · 09-10 값과 같음 · 09-10 분해: 웹 68 · 공개 홈페이지 36 · API 11 · 공용 3). 설정값으로 옮기는 작업이 진행 중이며, **끝나기 전까지는 코드를 고쳐야** 자기 병원명이 나옵니다.

- **고칠 파일 목록** → [바꿔야 할 코드 기본값](replace-list.md)(자동 생성 · 기준 커밋에서 다시 셈). 병원명만이 아니라 기관 정보 · 연락처까지 `식별` 로 묶어 HIS 에서 **183파일**이 나옵니다(병원명 118 을 포함). 목록은 경로만 싣고 문구는 싣지 않습니다.
- **설정값을 읽는 길은 이미 있습니다**(2026-09-17 확인). `hospital.name` · `hospital.phone` · `hospital.address` · `hospital.code` · `hospital.ceo` · `hospital.country` · 진료시간 같은 키가 런타임 설정에 있고, 기준 커밋의 API 가 이 키들을 **여러 자리에서 읽고 있습니다.** 병원 정보를 내려 주는 전용 API 도 있습니다.
- 그러니 남은 118개는 "설정값을 읽게 고칠지 말지"가 아니라 **아직 그 키를 읽지 않는 자리**입니다. 순서를 정한다면 **화면에 보이는 것부터**(웹 · 공개 홈페이지가 104개) 이 키들을 읽게 바꾸고, 그 전까지는 파일의 문자열을 바꿉니다. 어느 쪽이든 **바꾼 뒤 화면에서 확인**합니다 — 목록은 경로만 알려 주고 문구가 어디에 쓰이는지는 알려 주지 않습니다.

### 🔴 설치본 주소 교체

11개 저장소 합계 299개 파일([파일 목록](replace-list.md))에 특정 설치본의 주소가 기본값으로 들어 있습니다(문서 제외 · 2026-09-17 기준 커밋에서 다시 셈). HIS 쪽에서 먼저 볼 키:

| 키 | 어디 |
|---|---|
| `PUBLIC_URL` · `NEXT_PUBLIC_API_URL` | HIS 환경 파일 |
| `ai.server.url` | HIS 설정 → [S6](S6-ai.md) |
| 공개 홈페이지 · 환자 앱의 주소 키 | → [S2](S2-patient-access.md) |

HIS 저장소 안에서 바꿔야 할 **전체 목록**은 [바꿔야 할 코드 기본값](replace-list.md#his)에 있습니다 — HIS `주소` **73파일**(기준 커밋 · 생태계 전체는 [한눈에](replace-list.md#한눈에) 표). 바꾼 뒤에는 격리 상태에서 밖으로 나가려는 요청이 없는지 확인합니다.

**확인은 로그를 뒤지기 전에 제품 안에서 먼저 합니다.** HIS 에는 **외부로 나가는 호출 지점의 목록**이 코드에 정본으로 들어 있고, 그것이 대외 발신 관제 화면(`/admin/outbound-channels`)에 함께 나옵니다. 목록은 경로마다 **무엇이 어디로 어떤 성격의 데이터를 보내는지**를 적고, 목적지가 설정으로 바뀌는 것은 「설정으로 정해짐」으로 구분합니다(운영 설정값을 추정해 적지 않습니다). 코드 스캔 가드가 **실제 호출 지점 수와 이 목록을 대조**하므로, 새 호출이 생기거나 사라지면 검사에서 드러납니다.

- 그래서 순서는 ① 이 목록에서 **바깥으로 나가는 경로가 무엇인지** 확인 → ② 그 경로의 목적지 설정을 원내 주소로 바꿨는지 확인 → ③ 그래도 남는 것만 방화벽 · 프록시 기록으로 확인, 입니다.
- 🔴 이 목록은 **나라별 허용 · 금지를 판정하지 않습니다**(국가 프로파일이 사람 결정이라 「판정 없음」이라고 화면이 말합니다). 국외 이전 판단은 기관이 합니다.

### 암호화 키 · 백업 · 인프라

- **개인식별정보 암호화 키**(`ENCRYPTION_KEY`)는 설치 때 새로 만듭니다. Go-Live 관제가 기본값이거나 비어 있는 키를 "준비 안 됨"으로 표시합니다.
- **백업**은 저장소의 백업 셸 스크립트(`infra/scripts/backup.sh`)를 **운영체제의 정기 작업(크론)에 한 줄로 등록**해 돌립니다. 보존 기간은 스크립트 안의 `RETENTION_DAYS`(기본 **30일**)이고, 지난 파일은 스크립트가 지웁니다. 배포 직전 자동 백업도 같은 방식으로 암호화하며, Go-Live 백업 판정은 **정기 백업만** 셉니다.
  - 🔴 **암호화는 조건부입니다.** 암호문(패스프레이즈) 파일이 있을 때만 암호화본을 만들고, 없으면 **평문 백업만 남습니다.** Go-Live 의 백업 판정은 **암호화본이 만들어진 시각**을 읽으므로, 평문만 있으면 화면이 `준비 안 됨` 으로 말합니다 — 이것이 정상 동작입니다 → [취지 1](../overview/02-principles.md).
  - 🔴 **크론 시각은 서버 시간대를 탑니다.** 같은 `0 3` 이 서버 시간대에 따라 새벽 3시가 되기도, 한낮이 되기도 합니다. **서버를 옮기면 크론 시간대부터 다시 봅니다** → [형제 시스템 히스토리 장면 ①](../DESIGN-HISTORY-SYSTEMS.md).
  - 등록 절차의 세 가지 순서: ① **손으로 한 번 돌려 되는 것을 확인한 뒤** 자동화한다 ② 등록 전에 **이미 등록돼 있는지 먼저 본다**(중복 등록이 실제로 있었습니다) ③ **복원까지 한 번 돌려 봅니다** — 백업 파일이 생기는 것과 그 파일로 되살아나는 것은 다른 사실입니다(S7).
  - 근거: HIS 기준 커밋의 백업 스크립트와 백업·키 교체 참조 문서 · 2026-09-12 확인.
- **Redis 메모리 한도와 축출 정책**은 compose 기본값이 **`maxmemory 512mb` · `allkeys-lru`** 입니다. 상한 없이(`noeviction`) 두면 세션·캐시가 쌓여 메모리가 터지고 **인증 전체가 멎기 때문에** 상한을 두었습니다. ⚠️ `allkeys-lru` 는 **만료 시간이 없는 세션 · 패스키 값도 밀어낼 수 있으므로**, 기관의 평상시 사용량보다 넉넉하게 올려 잡습니다(기관 규모별 값은 리허설에서 측정 · `확인 필요(따라가기)`).
- **한글 검색용 GIN 인덱스** — 적용 SQL 이 수동 SQL 묶음 안에 있습니다(파일 이름에 `search-trgm` 이 들어갑니다). Go-Live 항목은 **사람이 완료로 적을 수 없고** 시스템이 `pg_indexes` 를 조회해 판정합니다. 🔴 **DB 를 다시 만들면 다시 적용해야 합니다** — 스키마 반영(`db push`)이 이 인덱스를 만들지 않습니다.
- **PostgreSQL 튜닝은 권장 값이 저장소에 없습니다.** 없는 이유가 적혀 있습니다 — 이 생태계는 **PostgreSQL 인스턴스를 여러 시스템이 함께 쓰는** 구성을 전제로 하고 있어서, 한 시스템이 단독으로 바꿀 값이 아니라 **함께 쓰는 쪽과 합의할 값**으로 두었습니다. Go-Live 에도 **개시를 막지 않는 수동 항목**으로 들어 있습니다.
  - 기관이 시스템마다 DB 를 따로 두면 이 제약은 없어집니다. 그때의 권장 값은 기관의 부하로 정합니다 — **이 자료는 재 보지 않은 값을 권장 사양으로 적지 않습니다.**
  - 다만 접속 수는 저장소가 판단을 남겨 두었습니다 — 연결 풀이 최대 접속 수에 견주어 여유가 있어 **따로 올릴 필요가 없다**고 결론 내렸습니다.

### 병원 규정

병원 규정 값은 코드가 아니라 **설정 화면**에서 바꿉니다. 어휘 · 수치 정책 · 상태 라벨은 한 곳(공용 정본)에서 나오므로, 규정을 바꿀 때 한 곳만 고칩니다. 안전 게이트(DUR · CDSS · 조영제 등)는 이 단계에서 존재를 확인하고, 목표 모드는 [S7](S7-rehearsal.md) 리허설에서 경고로 운영해 본 뒤 올립니다.

## ⑦ 흔한 함정

- **시드를 넣은 채 격리를 푸는 것.** 기본 시드는 가상 병원이고 특정 기관명이 들어 있습니다. 주소 교체와 격리 확인이 먼저입니다.
- **데이터 손실을 허용하는 옵션으로 스키마를 밀어 넣는 것.** 저장소가 금지합니다. 스키마가 바뀌는 배포는 자동 백업을 거치는 경로를 씁니다.
- **저장소의 배포 스크립트를 그대로 쓰는 것.** 실행한 작업 디렉터리를 그대로 서버에 동기화하므로, 커밋하지 않은 변경도 함께 올라가고 두 곳에서 동시에 배포하면 서로를 덮어씁니다.
  - 🔴 **기준 커밋의 배포 스크립트는 다른 기관에 그대로 쓸 수 없습니다**(2026-09-17 확인). 대상 서버 · ssh 포트 · 원격 디렉터리 · 원격 Node 실행 경로가 **스크립트 본문에 값으로 박혀 있고**, 이를 밖에서 덮어쓸 설정 파일이나 환경 변수가 **없습니다.** 기준 커밋에서 환경 변수로 열려 있는 것은 셋뿐입니다 — 홈페이지가 부를 API 주소 · 홈페이지 공개 주소 · 운영 모드.
  - 그래서 새 기관은 **이 스크립트를 복사해 고쳐 쓰거나, 자기 배포 방식을 따로 마련해야 합니다.** 고쳐 쓴다면 위 네 값과 [바꿔야 할 코드 기본값](replace-list.md) 의 `주소` 분류를 함께 봅니다.
  - 배포 원천이 **로컬 작업 디렉터리뿐**이라는 점도 그대로입니다 — 저장소에서 내려받아 배포하는 경로 · 지속적 통합 · 컨테이너 레지스트리 경로가 없습니다. 서버에 올라가는 것이 *어느 커밋인가*가 아니라 *누구의 작업 디렉터리인가*로 정해지므로, **배포하는 사람을 한 명으로 정합니다.**
- **`HIS_MODE` 를 비워 두는 것.** 비어 있으면 **REAL 로 동작**합니다(기동 로그가 경고합니다). 리허설 서버는 `HIS_MODE=REHEARSAL` 을 명시하고, 웹 빌드에도 `NEXT_PUBLIC_HIS_MODE` 를 줍니다 — 비워 두면 테스트 계정 패널이 빠진 REAL 빌드가 됩니다(모르는 값이면 막는 기본값).
- **격리를 확인하지 않고 여는 것.** 따라가기에서 HIS API 는 기동 뒤 **스스로 기관 공개 사이트의 최신성을 확인하려고 밖으로 나갔습니다**(격리 네트워크가 막음 · 기동 로그 "공개 사이트 최신성 확인 차단"). 기관 정보의 공개 사이트 주소를 자기 기관 값으로 바꾸기 전에는 격리를 풀지 않습니다.
- **웹 빌드 인자 `PUBLIC_URL` 을 빠뜨리는 것.** 운영 compose 는 비어 있으면 **특정 설치본 주소**를 API 주소로 넣어 빌드합니다.
- **"기본값"을 정한 값으로 오해하는 것.** `/admin/config` 에서 "기본값"은 아무도 정하지 않은 값입니다.
- **컨테이너 헬스체크를 그대로 믿는 것.** 운영 compose 의 API 헬스체크는 컨테이너 안에서 `localhost` 로 확인하는데, 이름이 IPv6 로 먼저 풀려 **모든 주소로 열어 둔 API 를 "비정상"으로 판정**할 수 있습니다(따라가기 2026-09-13). 헬스체크 주소를 IPv4 로 고정하면 넘어갑니다.
- **웹 컨테이너 메모리 한도를 예시값 그대로 두는 것.** 따라가기에서는 기본 한도(512MB)에서 웹이 메모리 부족으로 재시작을 반복해 한도를 올려 띄웠습니다. 다만 이 값은 위 ⑥의 빌드 우회와 얽혀 있어, **한도만 올리면 되는지는 기관 빌드에서 다시 봅니다.**
- **요양기관 기호에 개발용 자리표시가 남는 것.** 기호 · 사업자번호 · 대표자는 인허가 뒤에 원무가 확정합니다. Go-Live `data.hospitalInfo` 가 판정합니다.
- **백업 비밀을 서버에만 두는 것.** 서버를 잃으면 백업을 풀 수 없습니다.
- **관측 도구(Grafana 등)를 고쳐서 외부에 여는 것.** AGPL 계열의 조건을 확인합니다([THIRD_PARTY.md §5](../THIRD_PARTY.md#5-구조--링크하지-않고-별도-컨테이너로-씁니다)).

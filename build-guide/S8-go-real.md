# S8 리얼 전환 — 가상 데이터 격리 · 실데이터 이관 · 리얼 빌드 · 개시 확인

> ⚠️ 리허설 전 초안 — 새 설치본으로 따라가 보기 전입니다. `확인 필요(따라가기)` 표시는 따라가기에서 확정합니다. · 기준 2026-09-11 · [가이드 목차](README.md)

## ① 목적과 완료 조건

리허설을 끝내고 실환자를 받습니다. 순서는 **가상 데이터 격리 → 키 · 인증서 새로 만들기 → 실데이터 이관 → 리얼 빌드 배포 → 개시 확인**입니다. 리얼 전환 뒤에는 시험용 통로가 원천적으로 없어야 합니다.

완료 조건:

- [ ] 🔴 결정 등록부의 **개시 전 필수 11개**가 모두 기록됐다(아래 표)
- [ ] 🔴 Go-Live 의 **개시 차단 31개**를 하나씩 확인했고, 준비되지 못한 항목의 사유와 대체 수단을 기관 문서에 남겼다
- [ ] 🔴 가상 병원 시드 · 데모 · 시험 데이터를 **모든 시스템에서** 제거하거나 격리했다
- [ ] 🔴 리얼 빌드를 배포했다(Go-Live `security.hisMode`)
- [ ] 기관 기본정보(요양기관 기호 · 사업자등록번호 · 대표자 등)를 인허가 값으로 확정했다
- [ ] 개원일을 확정하고, **진료 · 청구 실왕복 1건**으로 개시를 확인했다

## ② 설치 — 전환 절차

### 1. 전환 전 확인

| 확인 | 어디서 |
|---|---|
| 개시 전 필수 결정 11개 기록 | `/admin/decisions` |
| 개시 차단 31개 상태 | `/admin/go-live` |
| 최근 암호화 백업 | Go-Live `security.dbBackup`(정기 백업만 셈) |
| 감시자 판정 | `/admin/sentinel` |

백업에서 실제로 복원해 보는 시험의 절차는 `확인 필요(따라가기)`.

### 2. 가상 데이터 격리 — 시스템마다

| 시스템 | 무엇을 정리하나 | 근거 |
|---|---|---|
| HIS | 가상 병원 시드 · 데모 · `TEST-` 픽스처(Go-Live `flag.demoSeedPurge`) · 데모 날짜 롤포워드 끄기(`dev.demoDateRoll` = `false`) | Go-Live |
| LIS | 운영은 `starter` 시드 · 파일럿 데이터 정리 API(요청 → 승인 두 단계) | LIS 릴리즈 요약 |
| ERP | 합성 시드(`TEST-` 접두) · **시드에 든 개발용 로그인 계정** | ERP 릴리즈 요약 |
| sign | 저장소 문서의 **초기화 절차** — 테스트 데이터와 CA 를 새로 만듭니다. 이때 **연동 시스템이 보관한 인증서도 다시 발급**받습니다. 키 보관 장치 전환 · 본인확인 사업자 연결 · 연동 키 교체도 이 시점에 함께 하도록 짜여 있습니다 | sign 릴리즈 요약 |
| 환자 앱 | 배포 빌드에서는 시드 환자용 시험 계정 안내가 나오지 않는 조건이 걸려 있습니다 — 배포 빌드로 확인 | 환자 앱 릴리즈 요약 |
| PACS · edu · twin · cerno · Clinic | 리허설 데이터 정리 방법 — PACS · edu · twin · cerno 기준 커밋에는 **정리 전용 스크립트가 없습니다**(파일 이름 purge · cleanup · reset · wipe 검색 0 · 2026-09-13). DB 를 새로 만들지, 표를 골라 지울지는 `확인 필요(따라가기)` | 각 저장소 기준 커밋 |

HIS 도 기준 커밋에 **시드 정리 스크립트 파일이 없습니다.** Go-Live 의 `flag.demoSeedPurge` 는 **수동(MANUAL) 항목**이고(담당 전산 · 원무 · 확인 화면 `데이터 품질` · 설명 "데모 환자 · 리허설 결재 · LIS 종단검증 픽스처 파기 · LIS 회신 수신 후 실행"), 정리 명령과 순서는 `확인 필요(따라가기)`. 리허설에 쓴 직원 · 시험 계정의 정리도 같은 시점에 합니다. 각 시스템의 계정 · 세션 회수를 따로 확인합니다(시스템마다 회수 방식이 다릅니다 — 따라가기에서 절차 확정).

### 3. 키와 가명화

- **개인식별정보 암호화 키** — 운영 키가 자리표시 값이 아닌지 Go-Live `security.encryptionKey` 가 판정합니다. 키 파생을 통일하고 키 교체를 언제 할지는 결정 `security.keyDerivationUnify`(시드 정리와 함께 · 지금 · 실환자 등록 직전까지 보류)로 정합니다.
- **환자번호 가명화 컷오버** — Go-Live `cutover.phase0.pseudonym`(법무 · CPO 승인과 실행 기록 · `/admin/phase0-cutover`).
- **데이터 보유 · 실파기 개시** — Go-Live `legal.retention`(법무 승인).

### 4. 실데이터 이관

- 기존 시스템에서 환자 · 진료 · 원무 데이터를 옮기는 도구와 절차는 공개 자료에 없습니다 — `확인 필요(따라가기)`.
- ERP 는 전환 때 HIS 의 청구 라인 · 미청구 진행분 · 재원 정보를 **일괄 적재**하는 경로가 있습니다(`구현·미검증`).
- v4.12.0 이전 HIS 데이터를 가져오는 경우 여권 · 외국인등록번호 암호화 백필이 필요하고, 여권번호 검색이 정확 일치로 바뀝니다(HIS 릴리즈 요약).

### 5. 리얼 빌드 배포

- Go-Live `security.hisMode` 는 **빌드의 운영 모드 상한**을 읽습니다. 관리 화면에서 설정만 바꿔서는 이 항목이 끝나지 않고, 리얼 빌드를 배포해야 끝납니다.
- 리얼 빌드는 배포 스크립트에 **모드를 명시해서** 만듭니다 — `./infra/scripts/deploy.sh --all --mode real`([S7 에 사용법](S7-rehearsal.md)). 🔴 **`--mode` 를 생략하면 서버의 현재 값(리허설)을 그대로 이어받습니다.** 개시 배포에서는 반드시 명시합니다.
- **시험 계정이 산출물에 남았는지는 가드 테스트가 봅니다.** HIS 웹에는 *"테스트 계정은 운영 번들에 실리지 않는다"* 는 테스트가 있어, 소스 트리를 훑어 테스트 계정 목록이 운영 빌드에 들어갈 수 있는 자리에 있는지 검사합니다. 이 테스트가 남긴 문장이 규칙을 그대로 말합니다.

  > **"숨긴 것과 없는 것은 다른 사실이다. 조건부 렌더만 하면 번들에 남아 그대로 검색된다."**

  실제로 2026-08 에 로그인 화면 두 곳이 테스트 계정 목록을 그리고 있었고, 공용 비밀번호가 소스에 문자열로 남아 있었으며, **목록 정본이 두 벌**이었습니다. 그래서 진입점을 **빌드 때 접히는 상수 분기 안의 지연 로딩 하나로 좁히고**, 그 구조가 유지되는지를 테스트로 고정했습니다 → [취지 8](../overview/02-principles.md).
- 시드 데이터가 남았는지는 별도 항목입니다(아래 시드 정리). 새 기관의 배포 경로 구성은 `확인 필요(따라가기)`.

### 6. 개시

- `open.opening.date` — 개원일을 확정합니다. 🔴 확정 전까지 시스템은 어떤 절대 날짜도 계산에 쓰지 않습니다.
- `open.opening.confirm` — 🔴 "설정을 켰다"가 아니라 **"실제로 한 바퀴 돌았다"**를 확인합니다(진료 · 청구 실왕복 1건).
- 개시 뒤 대외 발신은 채널마다 세 조건(구현 + 설정 + 승인)대로 나갑니다. 켤 채널만 켭니다(`/admin/outbound-channels`).

## ⑦ 흔한 함정

- **설정 화면 토글만으로 리얼이 됐다고 믿는 것.** Go-Live 는 빌드의 상한을 읽습니다. 리얼 빌드를 배포해야 합니다.
- **시드 정리 전에 실환자를 등록하는 것.** 가상 데이터와 실데이터가 섞이면 되돌리기 어렵습니다.
- **리허설 CA · 인증서를 운영에 가져가는 것.** sign 을 초기화하면 연동 시스템의 인증서도 다시 발급받아야 합니다.
- **ERP 시드의 개발용 로그인 계정을 남기는 것.**
- **개원일을 확정하지 않는 것.** 확정 전까지 시스템은 절대 날짜를 계산에 쓰지 않습니다.
- **"설정을 켰다"를 개시 확인으로 삼는 것.** 진료 · 청구 실왕복 1건이 확인입니다.
- **"기록 없음"을 "미완료"로, "결정함"을 "적용됨"으로 읽는 것.** 개원 단계와 결정 등록부는 이 둘을 따로 보여 줍니다.
- **리허설에 쓴 계정을 남기는 것.** 각 시스템의 계정 · 세션 회수를 시스템별로 확인합니다.

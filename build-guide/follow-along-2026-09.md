# 새 설치본으로 따라가 본 결과
**What a first follow-along install showed (2026-09-13 ~ 2026-09-16)**

> [구축 가이드 목차](README.md) · [README 요약](../README.md#새-설치본으로-따라가-본-결과--요약) · 연결별 확인일은 [연결 상태](../RELEASES/draft/compatibility.md)

> **EN** — Each system was unpacked from its **pinned base commit** and installed from its own production container files on **one development PC** (Apple Silicon arm64, 8 GB VM, **no GPU**) inside a network that **could not reach the outside**. Calls were made **only between these new installs** — no production server was called. Result: **27 of 113 connections are now `검증됨` (verified)** with a date; 23 of them were also tested by **deliberately injecting a fault** (tampered tokens, wrong keys, forged webhook signatures, replays, mismatched targets). Many production install files **did not work as-is** (build memory, missing dependencies, schema commands, loopback-only binding, a missing sentinel service); every workaround is written into the stage chapters. Not done yet: x86/GPU reference hardware and throughput, real-data volumes, the actual switch to *real* mode, PACS worklist/viewer completion, Clinic and Jitsi installs.

**어떻게 했나** — 11개 저장소의 **고정한 기준 커밋**을 풀어 각 저장소의 **운영용 설치 파일**로 올렸습니다. 장비는 개발 PC 한 대(Apple Silicon · arm64 · 가상 머신 8GB · **GPU 없음**)이고, 모든 컨테이너는 **외부로 나가지 못하는 네트워크**에 두었습니다. 시스템 사이 호출은 **새 설치본끼리만** 했고 운영 중인 서버는 부르지 않았습니다. 비밀값은 전부 새로 만들었고, 데이터는 가상 병원(위루비병원) 데이터입니다. 저장소 파일은 사본에서만 고쳤고, 고친 곳은 모두 해당 단계 장에 적었습니다.

> ⚠️ **기준 장비가 아닙니다.** 처리량 · 응답 시간 · AI 품질은 이 결과로 판단하지 않습니다. AI 는 CPU 에서 아주 작은 대체 모델로 **호출 경로만** 확인했습니다.

### 좋았던 것 — 가드가 실제로 막았다

- **실패를 말합니다**: AI 서버 주소가 허용 목록에 없으면 "설정이 없어 보내지 않았다"로 · 감시자가 없으면 "스윕 기록 없음 · 정지 의심"으로 · 표본이 모자라면 "산출 불가(0 이 아닙니다)"로 표시했습니다.
- **직무 분리**: 결과를 적용한 직원은 자기 결과를 검증할 수 없고 · LIS 관리자는 검체 접수 · 결과 입력을 할 수 없으며 · 시드 정리는 요청자 본인이 승인할 수 없습니다.
- **리허설 모드**: 화면 위쪽 배지 · 문자 · 메일 · 연동 발송 보류(보내지 않고 대기) · 외부로 나가지 못하는 네트워크에서도 기동이 멈추지 않음.
- **복원해 본 백업**: 암호화 백업을 다른 DB 에 복원해 행 수가 일치하는 것까지 확인했습니다.

### 일부만 확인한 연결 · 코드에 고정돼 막힌 경로

실제로 호출했지만 **연결 전체를 확인하지는 못해 `검증됨` 을 붙이지 않은** 연결입니다(상태는 `구현·미검증`).

| 연결 | 확인한 범위 | 남은 것 · 막힌 이유 |
|---|---|---|
| HIS → AI Server 임상 보조 | 요약 경로 하나 · 키 검사 | 수십 개 기능의 묶음이라 나머지는 미호출 · 기준 모델 · GPU 아님 |
| HIS → AI Server 생성형 도우미(번역 · 약품집 초안 등) | 번역 · 약품집 AI 초안 2개 · 키가 틀리면 번역은 "원문 + 실패 표시", 초안은 오류로 알림 | 나머지 도우미(데이터 품질 · 거버넌스 · 고객 의견 · 복약 설명 · 환자 안내) · 기준 모델 · GPU 아님 |
| edu → AI Server 학습 도우미 | 시험 문항 AI 생성 · 키가 틀리면 사유와 함께 실패 알림 | 학습 자료 색인은 임베딩 모델 필요(기준 장비) · 튜터 질의는 호출부 없음 · 녹취 분석 미시험 |
| HIS → ERP 직원 셀프서비스 | 연차 잔여 · 급여명세 조회 2개 · 대상 토큰 거부 5종 | 원천징수 · 증명서 등 나머지 조회와 급여 신원 등록 |
| ERP → HIS 직원 사번 매핑 | HIS 직원 목록 조회 · 사번 기록 쓰기 | ERP 가 부를 수 있는 HIS 주소가 **코드에 고정** · 매핑 작업은 **Clinic 연동이 먼저** 필요 |
| ERP → HIS 수가 마스터 반입 | HIS 수신(수가 코드 일괄 등록) | ERP 반입 스크립트가 운영 이미지에 없고 보낼 주소가 **코드에 고정** |
| HIS → ERP 운영 이벤트 | 장비 점검 불합격 1건이 ERP 경로로 대기열에 쌓임 · 리허설 모드에서 보류 · ERP 수신 키 거부 | 실제 발송은 **리얼 전환 뒤**(사람 결정) · 이벤트 전달 설정은 설치 뒤 꺼져 있음 |
| ERP → AI 공시 색인 보내기 | 등록 · 폐지 · 틀린 키 거부 · 내용 해시 검사 · 개인정보 모양 차단(시험용으로 주소 제한만 풀고) | AI 주소가 **코드에 고정** · 연동 워커에 AI 설정 없음 · 색인 완료는 임베딩 모델 필요(기준 장비) |

ERP → AI 공시 검색도 AI 주소가 코드에 고정돼, 원내 AI 로 설정하면 ERP 자체 검색으로 넘어갑니다. 이런 경로는 각 단계 장에 "코드 수정 또는 프로젝트 협의가 필요"로 적었습니다.

### 장비 · 디스크 참고 (기준 장비 아님)

> 요약과 "무엇이 비용을 만드는가"는 [README 「규모 — 지금 말할 수 있는 것」](../README.md#규모--지금-말할-수-있는-것)에 있습니다. 아래는 그 근거가 된 실측입니다.


- 여러 시스템을 함께 띄운 조합(HIS · ERP · PACS 코어 · AI Server + 작은 모델)에서 가상 머신 메모리 사용은 약 **2.9GB** 였습니다(가상 데이터 · 사용자 없음 · 2026-09-15).
- 🔴 **디스크가 먼저 모자랐습니다.** 60GB 가상 머신이 빌드 이미지와 모델로 **두 번 가득 찼고**, 그때 같은 호스트의 DB 가 잠시 복구 모드에 들어갔습니다. 이미지만 HIS API 약 4GB · HIS 웹 약 4.7GB · AI 의존성 약 4.6GB · 모델 서버 약 7GB 입니다. 구축 서버는 **200GB 이상**을 권하고, 옛 빌드 이미지를 정리하는 절차를 둡니다.

### 아직 하지 않은 것

| 무엇 | 왜 |
|---|---|
| x86 · GPU(RTX 5080) 기준 장비에서의 설치 · 처리량 · 응답 시간 · AI 품질 | 이 따라가기는 개발 PC(arm64 · GPU 없음)에서 했습니다 |
| 리얼 모드 전환(개시 순간 나가는 것 · 달라지는 화면) | 운영 배포에 해당하는 동작이라 사람 결정 뒤에 합니다 |
| HIS → PACS 영상 워크리스트 등록 · 영상 조회 완료 | 설치는 됐지만 HIS 와의 이 연결은 끝까지 확인하지 못했습니다(판독 서명 · 병리 워크리스트는 확인) |
| Clinic 설치 · Jitsi 재구성 · 환자 앱 · 공개 홈페이지 · twin · cerno | 설치하지 않았습니다 |
| 실데이터 규모의 이관 · 백업 시간 | 가상 데이터 규모만 재 봤습니다 |
| 시스템 담당의 사실 확인 | 따라가기에서 나온 사실은 각 프로젝트에 전달했고 회신을 기다립니다 |
| HIS 가 보내는 운영 이벤트의 실제 전달(수납 · 청구 · 재고 · 인사 이벤트 → ERP) · 서명 완료본 회수 | 리얼 모드에서만 나가는 경로라 리얼 전환 뒤에 확인합니다(대기열에 쌓이고 보류되는 것까지 확인) |
| AI 학습 자료 · 보험 공시 **색인** 완료 | 임베딩 모델이 있는 기준 장비가 필요합니다(호출 경로와 실패 처리까지 확인) |
| PACS 가 HIS 데이터베이스에 직접 쓰고 읽는 두 경로 | 전용 계정을 만들어야 확인할 수 있어, 이번에는 보내는 문장이 HIS 표와 맞는지까지만 대조했습니다 |
| 🔵 **막힌 것이 아니라 아직 부르지 않은 것** — 직원 셀프서비스의 나머지 조회 · 재검 오더 승인 폴링 · 환자 포털의 영상 내보내기와 본인 영상 조회 · 촬영 장비 워크리스트 · 외부 영상 서버 연계 · edu 자체 로그인 | 준비가 더 필요해서가 아니라 **1차에서 시간이 닿지 않았습니다.** 설치본과 설정은 그대로 두면 부를 수 있는 것들입니다 |

이 따라가기는 **2026-09-16 에 여기까지 하고 멈췄습니다.**

🔵 **읽을 때 하나만 갈라 주십시오 — "못 부른 것"과 "부르지 않은 것"은 다릅니다.** 위 표의 대부분은 기준 장비 · 사람 결정 · 미설치 시스템 · 담당 회신에 묶여 **못 부른** 것이지만, 마지막 줄은 **막힌 데 없이 시간이 닿지 않아 부르지 않은** 것입니다. 그래서 `검증됨` 이 아닌 연결을 전부 "안 되는 것"으로 읽으시면 안 됩니다 — `구현·미검증` 은 **양쪽 코드가 맞물려 있다**는 뜻이고, 그중 일부는 다음 회차에 그대로 부르면 되는 자리입니다.

> **EN** — Integration contract card: **Jitsi → AI Server**. None of these 1 have been called end to end yet — they are wired in code only. Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/draft/compatibility.md).

**무엇을 주고받나** — 원격 상담 녹화를 AI 서버에 넘겨 회의록 **초안**을 받는 경로였습니다. 화상 서버 자체가 `중단` 상태라 이 경로도 지금은 동작하지 않습니다.

## 연결

| 목적 | 프로토콜 | 인증 | 상태 | 확인일 |
|---|---|---|---|---|
| 원격 상담 녹화 회의록 자동 분석(서명 URL 제출 · 콜백 · 상태) | HTTPS REST(JSON) + AI Server → Jitsi 콜백 | Bearer(AI_API_KEY) | `중단` | — |

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `AI_SERVER_URL`
- `AI_API_KEY`
- `AI_AUTO_ANALYZE`
- `AI_CALLBACK_URL`
- `AI_PRESIGNED_URL_EXPIRY`

## 여는 순서

1. 화상 서버를 새로 세운 뒤에야 의미가 있습니다 — 「HIS → Jitsi」 카드의 안내를 먼저 보십시오.
2. 다시 세울 때는 녹화 파일을 어디에 두고 얼마나 보관할지부터 정하십시오. 🔴 **녹화는 진료 내용 그 자체입니다.**

## 따라가기에서 확인한 것

이 방향은 **아직 실제로 불러 보지 않았습니다.** 상태는 양쪽 코드를 대조한 판정입니다.

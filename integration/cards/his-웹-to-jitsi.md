> **EN** — Integration contract card: **HIS 웹 → Jitsi**. None of these 1 have been called end to end yet — they are wired in code only. Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/2026.09/compatibility.md).

**무엇을 주고받나** — 원격진료 녹화를 목록에서 보고 메모하고 내려받고 지우는 경로였습니다. 화면이 화상 서버의 관리 API 를 직접 부릅니다. 화상 서버가 `중단` 이라 멈춰 있습니다.

## 연결

| 목적 | 프로토콜 | 인증 | 상태 | 확인일 |
|---|---|---|---|---|
| 원격진료 녹화 목록·메모·삭제·다운로드(Jitsi API `/meet-api/recordings*`) | REST(JSON) · 브라우저에서 직접 호출(동일 출처 프록시 경로) | X-API-Key(Jitsi API 키 · 역할 admin/operator/read | `중단` | — |

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `NEXT_PUBLIC_TELEHEALTH_RECORDINGS_KEY`
- `API_KEY(Jitsi)`

## 여는 순서

1. 화상 서버를 새로 세우고 관리 API 키를 발급합니다 — 역할이 갈립니다(보기만 할지, 지울 수도 있게 할지).
2. 🔴 이 키는 **브라우저까지 내려갑니다.** 지울 수 있는 키를 화면에 두지 말고 보기 전용 키를 쓰십시오.
3. 녹화 보관 기간과 접근 권한을 기관 규정으로 정한 뒤 켭니다.

## 따라가기에서 확인한 것

이 방향은 **아직 실제로 불러 보지 않았습니다.** 상태는 양쪽 코드를 대조한 판정입니다.

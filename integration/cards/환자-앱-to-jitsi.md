# 환자 앱 → Jitsi

> 연동 계약 카드 — [카드 목록](README.md) · [연동 지도](../README.md) · 상태의 정본은 [연결 상태 표](../../RELEASES/2026.09/compatibility.md)입니다.

> **EN** — Integration contract card: **환자 앱 → Jitsi**. None of these 1 have been called end to end yet — they are wired in code only. Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/2026.09/compatibility.md).

**무엇을 주고받나** — 환자 앱에서 원격진료 방을 여는 경로였습니다. 앱은 대기실 입장을 기록한 뒤 **방 주소만 외부 브라우저로 엽니다** — 앱 자체는 토큰을 받지 않습니다. 화상 서버가 `중단` 이라 함께 멈춰 있습니다.

## 연결

| 목적 | 프로토콜 | 인증 | 상태 | 확인일 |
|---|---|---|---|---|
| 환자 앱 원격진료 입장 — 대기실 입장 기록(PATCH portal/telehealth/:id/join) 후 Jitsi URL 을 외부 열기 | 딥링크/브라우저 열기 | 없음 — 앱은 JWT 를 받지 않고 `<base>/<roomId>` 만 연다 | `중단` | — |

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `EXPO_PUBLIC_TELEHEALTH_URL`

## 여는 순서

1. 화상 서버를 새로 세웁니다.
2. 🔴 앱이 여는 주소에는 **토큰이 붙지 않습니다.** 방 주소를 아는 사람이 들어올 수 있으므로, 서버 쪽에서 입장 통제를 어떻게 할지 먼저 정하십시오.
3. 앱에 화상 주소를 넣고 환자 한 명으로 확인합니다.

## 따라가기에서 확인한 것

이 방향은 **아직 실제로 불러 보지 않았습니다.** 상태는 양쪽 코드를 대조한 판정입니다.

Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/2026.09/compatibility.md).

**무엇을 주고받나** — LIS 가 확정한 검사 수량을 ERP 로 보내 **청구 산정**에 넣습니다. ERP 는 받는 즉시 계산하지 않고 접수만 해 두고(인박스), LIS 가 나중에 상태를 물어봅니다. 늦게 처리되는 것이 정상 동작입니다.

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `lis env: ERP_BILLING_URL`
- `lis env: ERP_BILLING_SECRET`
- `erp: lis_billing_secret (없으면 inbound_webhook_secret)`
- `erp: inbound_webhook_max_skew`

## 여는 순서

1. ERP 에 검사 청구 수신용 공유 비밀을 넣습니다. 따로 두지 않으면 공통 수신 비밀로 내려갑니다.
2. LIS 에 ERP 수신 주소와 **같은 비밀**을 넣습니다.
3. 시각 어긋남 허용 폭을 확인합니다 — 서명에 보낸 시각이 들어가므로 **양쪽 시계가 맞아야** 합니다.
4. 검사 한 건으로 끝까지 — LIS 확정 → ERP 접수(즉시 처리 아님) → 상태 조회로 산정 결과 확인.

> 연동 계약 카드 — [카드 목록](README.md) · [연동 지도](../README.md) · 상태의 정본은 [연결 상태 표](../../RELEASES/2026.09/compatibility.md)입니다.

> **EN** — Integration contract card: **검사 장비(분석기) → LIS**. None of these 1 have been called end to end yet — they are wired in code only. Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/2026.09/compatibility.md).

**무엇을 주고받나** — 검체 검사 장비가 낸 결과를 LIS 가 받아 검사 코드로 옮기고 자동 평가까지 태우는 경로입니다. LIS 에는 결과를 받는 창구와 장비 코드 매핑이 **이미 있습니다**. 없는 것은 장비가 흔히 쓰는 **직렬 · TCP 직결 수집기**로, 기관이 장비와 LIS 사이에 중계 하나를 두어야 합니다.

## 연결

| 목적 | 프로토콜 | 인증 | 상태 | 확인일 |
|---|---|---|---|---|
| 장비 결과 자동 수집(ASTM E1394 레코드 · 계기 CSV) → 코드 매핑 → 자동 평가 파이프라인 | HTTP POST(본문에 ASTM/CSV 원문) — ASTM 저수준 전송(E1381 | LIS JWT(결과 쓰기 권한 · 장비 서비스 계정) | `미구현` | — |

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `LIS: 장비 코드 매핑(`GET api/v1/instruments/mappings`)`

## 여는 순서

1. LIS 에 장비별 **코드 매핑**을 등록합니다(장비가 쓰는 코드 ↔ LIS 검사 코드).
2. 장비 전용 서비스 계정을 만들어 **결과 쓰기 권한만** 줍니다.
3. 장비와 LIS 사이에 중계를 둡니다 — 장비의 직렬·TCP 출력을 받아 LIS 수집 창구로 넘기는 작은 프로그램입니다. 표준 레코드(ASTM)나 계기 CSV 를 **그대로 본문에 실어** 보내면 됩니다.
4. 결과 한 건으로 끝까지 — 장비 출력 → 중계 → LIS 수집 → 코드 매핑 → 자동 평가.
5. 🔴 **매핑이 없는 항목은 결과가 들어와도 검사에 붙지 않습니다.** 장비를 붙이기 전에 매핑이 얼마나 덮는지 먼저 보십시오.

## 따라가기에서 확인한 것

이 방향은 **아직 실제로 불러 보지 않았습니다.** 상태는 양쪽 코드를 대조한 판정입니다.

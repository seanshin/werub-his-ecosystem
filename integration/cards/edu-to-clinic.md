# edu → Clinic

> 연동 계약 카드 — [카드 목록](README.md) · [연동 지도](../README.md) · 상태의 정본은 [연결 상태 표](../../RELEASES/draft/compatibility.md)입니다.

> **EN** — Integration contract card: **edu → Clinic**. None of these 1 have been called end to end yet — they are wired in code only. Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/draft/compatibility.md).

**무엇을 주고받나** — 미이수 독촉 같은 교육 알림을 edu 가 직접 보내지 않고 **그룹웨어를 통해** 보냅니다(직원이 이미 보고 있는 곳으로 모으는 것입니다). 한 건씩도, 여러 건을 묶어서도 보낼 수 있습니다.

## 연결

| 목적 | 프로토콜 | 인증 | 상태 | 확인일 |
|---|---|---|---|---|
| 교육 알림(미이수 독촉 등) 단건·대량 발송 — Clinic 이 그룹웨어 허브로 중계 | REST POST(설정된 전체 endpoint · 대량은 `/bulk`) → Cli | x-api-key(테넌트별 groupware.apiKey) · Idempotency | `구현·미검증` | — |

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `GROUPWARE_BASE_URL(groupware.baseUrl)`
- `GROUPWARE_API_KEY(groupware.apiKey)`
- `GROUPWARE_SENDER_ID`

## 여는 순서

1. 그룹웨어에서 edu 용 키를 발급합니다.
2. edu 테넌트 설정에 그룹웨어 주소 · 키 · 보내는 사람 표시를 넣습니다.
3. 같은 알림이 두 번 가지 않도록 **중복 방지 키**를 붙여 보냅니다 — 재시도해도 한 번만 가는지 확인하십시오.
4. 한 사람에게 한 건 → 여러 사람에게 묶음 순으로 늘려 확인합니다.

## 따라가기에서 확인한 것

이 방향은 **아직 실제로 불러 보지 않았습니다.** 상태는 양쪽 코드를 대조한 판정입니다.

> 연동 계약 카드 — [카드 목록](README.md) · [연동 지도](../README.md) · 상태의 정본은 [연결 상태 표](../../RELEASES/2026.09/compatibility.md)입니다.

> **EN** — Integration contract card: **PACS → 검사 장비(모달리티)**. None of these 1 have been called end to end yet — they are wired in code only. Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/2026.09/compatibility.md).

**무엇을 주고받나** — 촬영 장비가 PACS 에 「오늘 이 환자를 찍으면 된다」를 물어보고(촬영 목록), 촬영을 시작·종료할 때 상태를 알리고, 찍은 영상을 보냅니다. 표준 DICOM 통신이라 장비 쪽에 개발할 것은 없고, **장비에 PACS 의 주소와 이름표(AE 타이틀)를 등록하는 일**이 전부입니다.

## 연결

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `PACS: MWL_AE_TITLE`
- `PACS: MWL_BIND`
- `PACS: MWL_PORT`
- `PACS: ORTHANC_AET(orthanc_aet)`
- `PACS: ORTHANC_URL`

## 여는 순서

1. PACS 의 촬영 목록 응답기와 영상 수신기를 켜고, 각각의 **이름표 · 주소 · 포트**를 적어 둡니다.
2. 장비마다 그 값을 등록하고, 장비 쪽 이름표도 PACS 에 등록합니다(양방향으로 서로를 알아야 합니다).
3. 연결만 먼저 확인합니다 → 촬영 목록 조회 → 시험 영상 한 장 전송 순으로 하나씩 늘립니다.
4. 🔴 DICOM 통신에는 계정·비밀번호가 없습니다. **이름표와 망 구성이 사실상 유일한 경계**이므로 촬영망을 따로 두십시오.
5. 장비가 없어도 확인은 됩니다 — DICOM 명령을 보내는 도구 한 벌이면 촬영 목록 응답까지 볼 수 있습니다.

## 따라가기에서 확인한 것

이 방향은 **아직 실제로 불러 보지 않았습니다.** 상태는 양쪽 코드를 대조한 판정입니다.

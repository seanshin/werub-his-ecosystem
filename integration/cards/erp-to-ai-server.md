# ERP → AI Server

> 연동 계약 카드 — [카드 목록](README.md) · [연동 지도](../README.md) · 상태의 정본은 [연결 상태 표](../../RELEASES/draft/compatibility.md)입니다.

> **EN** — Integration contract card: **ERP → AI Server**. None of these 2 have been called end to end yet — they are wired in code only. Config keys are listed by **name only** — values are generated by the institution. Authoritative status lives in the [connection table](../../RELEASES/draft/compatibility.md).

**무엇을 주고받나** — 보험 · 수가 공시를 AI 서버에 색인해 두고, 청구를 넣기 전에 그 공시를 근거로 **사전 점검 초안**을 받습니다. 색인 발신은 즉시 나가지 않고 대기열에 쌓였다가 워커가 보냅니다.

## 연결

| 목적 | 프로토콜 | 인증 | 상태 | 확인일 |
|---|---|---|---|---|
| 보험·수가 공시(notice) 수명주기 색인 발신 — 등록·철회·색인 상태 조회·동기화 검증(아웃박스 큐) | HTTPS REST(JSON) — 비동기 큐 워커 | Bearer(WEVE_AI_API_KEY) | `구현·미검증`(일부만 확인) | — |
| 청구 사전심사 — 공시 RAG 검색(유형·시행일 필터) · 코드 진단 | HTTPS REST(JSON) | Bearer(weve_ai_api_key) | `구현·미검증` | — |

## 양쪽에 넣는 설정 — **키 이름만**

값은 기관이 새로 만듭니다. 이 자료는 값을 담지 않습니다.

- `WEVE_AI_API_BASE`
- `WEVE_AI_API_KEY`
- `weve_ai_api_base`
- `weve_ai_api_key`

## 여는 순서

1. ERP 에 AI 서버 주소와 키를 넣습니다. 🔴 **환경 변수와 데이터베이스 설정 두 군데**에 같은 이름이 있으니, 실제로 읽는 쪽을 확인하고 채우십시오.
2. 대기열을 처리하는 워커가 떠 있는지 확인합니다 — 워커가 없으면 **쌓이기만 하고 나가지 않습니다**.
3. 🔴 검색이 되려면 색인이 먼저 끝나야 하고, 색인에는 임베딩 모델이 필요합니다.
4. 공시 한 건으로 끝까지 — 등록 → 색인 상태 조회 → 검색에 걸리는지 확인 → 철회.

## 따라가기에서 확인한 것

이 방향은 **아직 실제로 불러 보지 않았습니다.** 상태는 양쪽 코드를 대조한 판정입니다.

일부만 확인한 연결이 **1개** 있습니다(표의 "일부만 확인").

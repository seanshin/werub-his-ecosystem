> 요약 범위: RELEASE-v3.11.0 ~ RELEASE-v4.18.0 중 최근 14개(v4.6.0 ~ v4.18.0 · 2026-08-20 ~ 2026-09-10)에서 이 앱에 닿는 기록 4개(v4.6.0 · v4.12.0 · v4.15.0 · v4.17.0) + 같은 기간 `apps/mobile` 커밋 이력 · 작성 2026-09-11

## 1. 한 줄 정의와 계층

- **정의**: 환자가 자기 예약 · 진료 기록 · 검사 · 영상 · 검진 결과 · 복약 · 수납 · 동의서를 보고, 예약 · 문진 · 서명 · 보호자 위임을 처리하는 모바일 앱입니다. HIS 의 환자 포털 API 를 쓰는 클라이언트입니다.
- **계층**: ② 환자 접점
- **구현 상태**: `개발` — 스토어 미배포 · 매니페스트 입력 기준 · 시스템 담당 확인 전
- **구성**: HIS 저장소의 `apps/mobile` — Expo(React Native) · expo-router. 공용 패키지를 앱 번들러가 따라가지 못해, 필요한 정본(검사 판정 규칙 · 안내 문구 등)은 복제본으로 두고 저장소 검사가 원본과 대조합니다.
- **규모**: 화면 32 — `data/scale-snapshot.json` 의 `systems.patient-app.counts.screens`(2026-09-11 계측 · 센 방법은 `rule`: 라우트 파일 중 레이아웃 파일 제외)

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**로그인 · 계정**
- 전화번호 · 비밀번호 로그인, 기기의 생체인증을 쓰는 PIN 로그인
- 프로필 · 알림 설정 · 보호자 관리(위임 요청)

**예약 · 진료**
- 예약 조회 · 취소, AI 예약 도우미(대화로 예약을 돕습니다 — AI 가 만든 참고 정보이며, 화면 표기는 `AI(WeRU.B)`)
- 진료 기록 목록, 입원 여정(타임라인 · 입원 상세: 진료 · 회진 · 검사 기록)
- 원격진료 예약 · 조회 · 입장(화상 연결은 별도 시스템 — §5)

**검사 · 영상 · 검진**
- 검사 결과(정상 · 이상 · 위급 판정은 공용 판정 규칙을 따름), 영상검사 목록과 판독 리포트
- 검진 결과 상세(종합 판정 · 항목), 회차별 검진 결과 비교, 검진 셀프 예약

**건강 관리**
- 검사 추이 · 알레르기 · 수술 전 체크리스트 · 건강 메모
- 만성질환 추이와 자가측정 기록(혈당 등 — 추세 판정은 서버 결과를 그대로 보여줌)
- 복약 관리(서버가 준 복약 시간대를 그대로 표시)
- AI 건강 요약 · 재진 권고 · 약물 상호작용 확인 — AI 가 만든 참고 정보입니다. 검증된 산출 도구가 없으면 점수를 만들지 않고 그 사유를 보여줍니다.

**문서 · 동의 · 수납**
- 동의서 확인과 전자 서명, 문진표 작성, 제증명 · 서류 신청과 발급 상태 조회
- 수납 내역 · 수납 요약(미수납 · 연간)

**소통 · 알림**
- 담당의 메시지 확인 · 답장, 알림 목록(읽음 처리), 공지사항

**내 정보 보호**
- 내 기록 접근 이력 — 누가 언제 내 기록을 열었는지, 긴급 접근(Break-the-Glass) 사유와 사후 승인 여부까지 보여줍니다.

## 3. 최근 변경

**v4.17.0** (2026-09-08)
- 앱을 스토어에 배포할지를 결정 등록부의 허가권자 결정 항목으로 올렸습니다. 앱 화면은 서버 배포와 무관하게 앱 빌드 · 스토어 심사를 거쳐야 실기기에 반영되기 때문입니다.

**v4.15.0** (2026-09-03)
- 서버에 이미 있던 기능 3개를 앱 화면에 연결했습니다: 만성질환 추이와 자가측정, 검진 결과 비교와 셀프 예약, 내 기록 접근 이력. 표시 어휘는 웹 정본의 복제본이며 대조 검사 2종이 붙어 있습니다.

**v4.14.0 범위** (2026-09-02 · 커밋 이력 · 릴리즈 기록에 별도 항목 없음)
- 예방접종 기록이 조회되지 않을 때 "기록 없음"으로 단정하지 않는 문구를 웹 포털에 이어 앱에도 적용했습니다.

**v4.12.0** (2026-09-01)
- 환자 토큰으로 앱이 부르는 조회 API 의 실제 응답과 화면이 읽는 필드를 대조했습니다. 공지 날짜와 완료된 검사의 상태를 잘못된 필드에서 읽던 두 화면을 바로잡았고(커밋 이력), 나머지 주요 화면은 서버 계약과 맞는 것으로 확인했습니다(릴리즈 기록).

**v4.11.0 범위** (2026-08-27 · 커밋 이력 · 릴리즈 기록에 별도 항목 없음)
- 조회 실패를 "없음 · 0원 · 이상 없음"으로 보여주던 4화면(약물 상호작용 · 동의서 · 수납 · 원격진료)이 실패를 실패로 말하게 했습니다. 진짜 빈 목록은 그대로 "없습니다"로 둡니다.

**v4.6.0** (2026-08-20 ~ 21)
- 서버 쪽 환자 앱 푸시 알림 7종 중 4종의 발행 지점을 연결했습니다(기본 꺼짐). 나머지 3종은 발행 근거가 없어 연결하지 않았습니다. 환자 앱 알림 통로의 상태는 HIS 의 대외 발신 관제 화면에서 봅니다.

## 4. 연동 변경 (릴리즈 기록상)

- 환자 앱은 **HIS API 만** 부릅니다(환자 포털 · 환자 인증 · 예약 대화). 형제 시스템과의 직접 연결은 원격진료 입장 시 화상 회의 주소를 여는 것뿐입니다.
- 푸시 알림 발행이 서버 쪽에서 연결됐습니다(기본 꺼짐 · v4.6.0).

HIS 와의 연결 상태와 원격 화상 연결 상태는 통합 릴리즈의 `compatibility.md` 에서 판정합니다.

## 5. 알려진 한계

- **스토어 미배포** — 실기기에 설치할 수 있는 배포본이 없습니다. 배포 여부는 결정 등록부의 허가권자 결정 항목이며, 개인정보 처리방침 고지 · 심사 요건은 기관이 정합니다.
- **신규 가입** — 본인인증(CI) 연동이 없어 앱에서 가입할 수 없습니다. 가입 화면은 가입이 안 되는 이유와 대안을 안내합니다.
- **본인확인 문자** — 문자 발송 제공자가 등록돼 있지 않아 모의 발송입니다.
- **푸시 알림 수신** — 앱 쪽 수신 코드는 있지만 알림 패키지가 아직 앱 의존성에 들어 있지 않아 동작하지 않습니다(앱 코드 주석 · 2026-09-11 확인). 서버 쪽 발행도 기본 꺼짐입니다.
- **PIN 로그인** — 이 기기에서 한 번 로그인해 전화번호가 저장돼 있어야 쓸 수 있습니다.
- **원격진료 화상** — 별도 시스템(Jitsi)에 기댑니다. Jitsi 현재 설치본은 동작하지 않아 구축 기관이 새로 구성해야 합니다.
- **다국어** — 앱 화면에는 다국어 적용이 없습니다(한국어 · 2026-09-11 코드 확인).
- **시험 범위** — 앱 폴더의 시험은 서버 계약 · 소스 대조 검사(Node 내장 러너)이며, 실기기 화면 시험은 없습니다.

## 6. 설치 · 업그레이드 시 주의

- 앱은 HIS 서버 배포 스크립트와 **무관**합니다. 앱 변경은 앱 빌드와 스토어(또는 기관 배포 경로)를 거쳐야 사용자 기기에 반영됩니다.
- HIS API 주소(`EXPO_PUBLIC_API_URL`)와 원격진료 화상 주소(`EXPO_PUBLIC_TELEHEALTH_URL`)는 앱 빌드 환경변수로 지정합니다. 지정하지 않으면 코드에 적힌 기본 주소로 연결되므로, 반드시 자기 기관의 주소를 넣고 빌드합니다.
- 스토어 배포 전에 결정 등록부의 앱 배포 항목을 기관이 정합니다(개인정보 처리방침 고지 주체 · 수집 항목 · 동의 범위 검토).
- 푸시를 쓰려면 앱에 알림 패키지와 설정을 추가하고, HIS 에서 환자 앱 푸시 발행을 켭니다(기본 꺼짐 · 대외 발신 세 조건).
- 신규 가입을 열려면 본인인증 업체 연동과 문자 발송 제공자 등록이 먼저 필요합니다.
- 개발 빌드의 로그인 화면에는 시드 환자용 시험 계정 안내가 나옵니다. 배포 빌드에서는 나오지 않는 조건이 걸려 있습니다.
- 공용 판정 규칙 · 안내 문구를 바꾸면 앱의 복제본도 함께 바꿔야 합니다(저장소 대조 검사가 어긋나면 실패).

## 7. 버전 표기와 근거

- **정본**: HIS 와 같은 `HIS_VERSION`(v4.18.0)을 씁니다. 환자 앱만의 릴리즈 번호는 없습니다.
- **어긋남**(매니페스트 `version.mismatchWith`):
  - `apps/mobile/package.json` 1.0.0 · `apps/mobile/app.json` 의 앱 버전 1.0.0 — 스토어 배포 전이며 앱 버전은 초기값 그대로입니다. 스토어에 올릴 때는 앱 버전 체계를 따로 정해야 합니다.
  - git 태그는 이제 **v4.18.0 이 있습니다** — 기준 커밋보다 3커밋 앞의 커밋에 붙어 있고, **2026-09-13 에 만든 주석 태그**입니다(재계측에서 확인 · 그전에는 v3.46.0(2026-07-11)에서 멈춰 있었습니다).
- **근거**: HIS 의 `docs/04-report/RELEASE-v*.md` 107개(마지막 v4.18.0 · 2026-09-09 ~ 10) 중 요약 범위 14개에서 이 앱에 닿는 기록 4개, 그리고 같은 기간 `apps/mobile` 커밋 이력으로 교차 확인했습니다. v4.18.0 이후 기준 커밋까지의 커밋 3개는 이 앱을 건드리지 않습니다.

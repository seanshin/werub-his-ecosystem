# AI Server — 릴리즈 요약

> 기준 버전 **2.125.41** (정본 위치: `app.py VERSION`) · 기준 커밋 `55acaee90068` (2026-09-09)
> 요약 범위: 릴리즈 문서 v2.71.0 ~ v2.125.41 중 최근 16개(v2.125.26 ~ v2.125.41 · 2026-08-31 ~ 2026-09-09), 그중 생태계 관련 12개 · 작성 2026-09-11
> 사실 확인: 미확인 — 생태계 자료 측 조사 기준(시스템 담당 확인 전)

## 1. 한 줄 정의와 계층

- **정의**: 생태계의 AI 연산을 한 곳에서 맡는 온프레미스 GPU 서버입니다. 의료 데이터 정본 조회 · 진료 문서 초안 · 증상 분류 보조 · 약물 상호작용(DUR) 점검 보조 · 근거 문서 질의(RAG) · 음성 인식 · 영상 소견 초안을 다른 시스템에 API 로 제공합니다. 이 요약은 병원 생태계에 쓰이는 의료 기능만 다룹니다.
- **계층**: ⑥ AI 계층(연산 중심)
- **구현 상태**: `통합`(의료 기능 · 매니페스트 기준 · 시스템 담당 확인 전)
- **규모**: API 핸들러 654 · 테스트 선언 1,930 — `data/scale-snapshot.json` 의 `systems.ai-server.counts`(2026-09-11 계측 · 저장소 전체 기준 · 센 방법은 각 항목의 `rule`)
- **스택**: Flask · Ollama(모델 서빙) · ChromaDB(벡터 검색) · SQLite(데이터셋 · 작업 큐)

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**의료 데이터 정본 조회**
- 공공기관이 배포하는 의약품 안전사용(DUR) 기준으로 병용금기 · 임부금기 · 연령금기 · 노인주의 · 용량주의 · 투여기간 · 효능군 중복 · 서방정 분할을 점검하도록 **보조**합니다. 실시간 처방 차단 시스템이 아니라 참고 정보를 내는 자문 보조입니다(저장소 문서 기준).
- 약가 · 제품 코드 대조, 저가약 대체조제 조회, 환자용 의약품 정보, 질병분류 · 수가 코드(KCD · EDI) 조회와 매핑, 청구 규칙 · 삭감 사유 참조를 제공합니다.
- **의료 데이터 카탈로그**(`GET /api/medical/catalog`) — 보유 데이터셋마다 건수 · 최신성 · 마지막 동기화 상태 · 그 데이터를 내는 API 를 기계가 읽는 형태로 알려 줍니다. 연동하는 시스템의 출발점입니다. 집계만 내고 환자 정보는 싣지 않습니다.
- 공공 데이터 동기화는 전량을 받아 건수를 맞춰 본 뒤에만 교체하고, 실패하면 기존 데이터를 그대로 둡니다. 셀 수 없는 값은 0 이 아니라 `null` 로 표시합니다.

**진료 보조(초안)**
- 진료 기록 요약(SOAP 형식) · 의무기록 초안 · 환자 설명문과 교육 자료 초안을 만듭니다.
- 증상 분류(triage)를 보조합니다 — 증상을 뽑아 진료과 후보를 제시하고 응급 신호를 표시하며, 필요한 추가 질문을 만듭니다.
- 의료진용 임상 질의 · 약물 정보 설명 · 영→한 의학 번역을 보조합니다.
- 의료 영상 소견 초안과, 이전 영상과 비교한 초안을 만듭니다.
- 의료 응답에는 면책 고지가 응답 **필드**로 붙습니다. 최종 판단은 의료진에게 있습니다.

**근거 문서 질의(RAG)**
- 의료 지식 검색은 벡터 검색과 키워드 검색을 합칩니다. 법령 > 고시 > 상대가치 > 발간물 순의 권위 위계로 하위 문헌이 상위 근거를 밀어내지 않게 합니다.
- 의료 법령 · 고시 근거 질의는 근거 인용을 함께 내고, 근거가 없으면 `has_evidence: false` 로 신뢰도가 낮다는 것을 알립니다. 인용은 모두 실제 검색 결과에서 나오며, 모델이 인용 문자열을 만드는 경로는 없습니다(저장소 문서 기준).
- ERP 의 청구 사전심사에 고시 색인 · 검색 · 삭감 위험 평가 보조를 제공합니다.
- 기관(테넌트) 단위로 지식 저장소를 나눠, 다른 기관의 문서가 검색되지 않게 합니다.

**음성 인식(STT)**
- 진료실 음성 기록용 실시간 음성 인식과 녹음 파일 일괄 인식을 제공합니다. 모든 인식은 서버 안에서 합니다.

**twin 연산 지원**
- twin 시스템이 요청하는 비식별 연산(생리 반응 시뮬레이션 · 의료 영상 → 장기 3D 메시 · 심장 전기생리 시각화)을 처리합니다.

**모델 운용 · GPU 스케줄링**
- 호출하는 쪽은 모델 이름이 아니라 **역할 이름(task)** 을 부릅니다. 역할 → 모델 라우팅 표가 한 곳에 있고, 등록되지 않은 역할은 다른 모델로 흘러가지 않고 바로 실패합니다.
- 약물 상호작용 · 대체조제 · 의약품 정보 · 의료 법령처럼 안전과 직결되는 질의는 모델을 거치지 않고 공공 데이터를 먼저 조회하며, 모델은 그 결과를 문장으로 다듬는 역할에 머뭅니다.
- 16GB GPU 한 장을 나눠 쓰는 방식(상주 / 요청할 때 적재 · 동시 적재 한도 · 우선순위 · 시간대별 프로파일 · 음성 인식과의 공유)은 저장소 [README 의 "AI 는 소비자용 GPU 한 장으로" 절](../../../README.md)과 같습니다.
- 모델 호출에는 적응형 타임아웃 · 서킷 브레이커 · 같은 요청 병합이 걸려 있고, 대화 요청은 전체 · 사용자별 동시 처리 한도가 있는 공정 대기열을 거칩니다.

**데이터 보호 정책**
- 의료 · 개인건강정보 · 규제 관련 역할은 `local_only` 정책으로 묶여 있어, 외부 AI 제공자로 보내려 하면 코드가 거부합니다(실패하면 막는 쪽). 외부 제공자 연결 자리는 있지만 기본은 모두 꺼져 있습니다.

**거버넌스 · 감독**
- API 키(Bearer)로 호출자를 구분하고, 키에는 만료일이 있으며 신 · 구 키를 함께 쓰며 교체할 수 있습니다. 키 발급과 관리 기능은 서버 로컬에서만, 관리 기능은 관리자 요청에서만 열립니다.
- 약물 데이터 정제 파이프라인은 자동 수집 → 모델 정제 → 검증 → **스테이징**을 거치고, 사람이 승인하거나 거부해야 반영됩니다. 레코드마다 출처 이력을 조회할 수 있습니다.
- 품질 평가 — 서버 안의 모델이 채점하는 충실도(근거와 맞는지) · 검색 품질 · 채점기 일관성 등의 축으로 자기 품질을 계측합니다. 측정하지 않은 것과 0 을 구분합니다.
- 모든 응답이 자기 버전을 헤더로 알립니다(`X-API-Version` 빌드 · `X-API-Contract` 하위 호환이 깨질 때만 오르는 계약 버전 · `X-API-Commit`). 오류는 빈 결과로 감추지 않고 오류로 돌려줍니다. Prometheus 지표를 냅니다.
- 새 모델은 라이선스 · 하드웨어 적합성 · 근거 기반 비교(A/B)로 현재 구성보다 낫다는 것을 먼저 보인 뒤 들인다는 도입 절차가 저장소에 있습니다.

**규제 관련 표기** — 저장소는 LLM 기반 디지털의료기기 가이드라인에 대응하는 체계(근거 없는 생성 방지 · 모델 판본 고정 · 파라미터 재현성)를 갖췄다고 적습니다. 이 요약에서는 `대응 설계` 단계로 적습니다.

## 3. 최근 변경

범위: v2.125.26 ~ v2.125.41(16개 · 2026-08-31 ~ 2026-09-09) 중 생태계 관련 12개(v2.125.26 ~ v2.125.32 · v2.125.35 ~ v2.125.38 · v2.125.41).

- **인증 경계 확인** — 앞단 프록시가 같은 서버에 있어도, 전달 헤더가 붙은 요청은 외부 요청으로 보고 API 키를 요구한다는 것을 확인하고 회귀 테스트로 고정했습니다(기준 버전 v2.125.41).
- **유입 경로 점검 방식 설정** — 서버 앞단 구성에 맞춰 유입 경로 점검 방식(`ingress_mode`: `ssh_tunnel` · `proxy` · `none`)을 고를 수 있게 했습니다. 상태 점검 API 와 감시 스크립트가 같은 설정을 봅니다(v2.125.41).
- **고비용 경로 호출 한도** — 대화 생성 · 근거 검색 · 질의처럼 비용이 큰 경로마다 호출 한도를 두었습니다. 한도는 최근 실사용 최대치를 재서 그보다 넉넉하게 정했고, 초과하면 429 를 돌려줍니다. 실시간 음성 인식은 연속 호출 특성상 제외했습니다(v2.125.38).
- **의료 법령 · 고시 근거 자료의 수집 안정화**
  - 중복 정리 규칙을 다시 짰습니다. 전문(통합본)과 일부개정은 중복이 아니라 서로 보완하는 문서로 보고, 같은 문서가 두 번 색인된 경우만 삭제 후보로 삼으며, 최신 문서를 남깁니다. 자동 실행은 미리보기만 하고, 삭제는 운영자가 명시할 때만 합니다(v2.125.27).
  - 지운 문서를 수집기가 다시 새 문서로 받아 오지 않도록 삭제 기록을 따로 남깁니다(v2.125.35).
  - 글자가 깨진 채 추출된 문서는 색인하지 않고 보고합니다. 판정 기준은 전체 자료의 분포를 재서 정했습니다(v2.125.36).
  - 글자가 깨진 PDF 는 이미지로 바꿔 OCR 로 복구를 시도하고, 결과가 같은 기준을 통과할 때만 색인합니다. 함께 검토한 "최신판 가중치"는 측정 결과 도입하지 않았습니다(v2.125.37).
- **연동 진입점과 API 명세**
  - 의료 데이터 카탈로그 API 를 새로 만들고, API 명세(Swagger)의 의료 영역을 한 덩어리로 배치했습니다(v2.125.28).
  - 응답 버전 헤더 3종을 넣었습니다. `/api/version` 은 기본으로 요약만 내고, 변경 이력은 요청할 때만 냅니다. API 명세의 인증 표기를 코드와 맞췄습니다(v2.125.29).
  - 연동에 쓰이는 의료 API 의 설명 · 상태 코드별 응답 · 코드에서 확정되는 응답 필드(의료 법령 질의의 면책 필드 포함)를 명세에 보강했습니다. 코드에서 확정할 수 없는 응답 구조는 지어내지 않고 비워 두었습니다(v2.125.30 ~ v2.125.32).
- **상태 지표 분리** — 원격 노드를 중계하다 난 오류를 이 서버 자신의 오류율과 따로 셉니다. 중계 오류는 버리지 않고 별도 지표로 냅니다(v2.125.26).

## 4. 연동 변경 (릴리즈 기록상)

실제로 동작하는지는 통합 릴리즈의 `compatibility.md` 에서 판정합니다. 아래는 릴리즈 기록에 적힌 구현 내용입니다.

| 대상 | 변경 | 버전 |
|---|---|---|
| 호출하는 모든 시스템 | 응답 헤더 `X-API-Version` · `X-API-Contract` · `X-API-Commit` 추가. 연동 코드는 계약 버전으로 분기할 수 있습니다 | v2.125.29 |
| 호출하는 모든 시스템 | `/api/version` 기본 응답이 요약형으로 바뀜(변경 이력은 옵션 지정 시에만) | v2.125.29 |
| 호출하는 모든 시스템 | 의료 데이터 카탈로그 API 신설 — 데이터셋과 그 데이터를 내는 API 목록 | v2.125.28 |
| 호출하는 모든 시스템 | 고비용 경로에 호출 한도(초과 시 429). 실시간 음성 인식 경로는 제외 | v2.125.38 |
| 앞단 프록시를 거치는 호출 | 전달 헤더가 있는 요청은 외부로 보고 API 키를 요구(동작 변경이 아니라 확인 · 회귀 고정) | v2.125.41 |
| ERP (청구 사전심사) | 고시 근거 자료의 중복 정리 · 재색인 방지 · 깨진 문서 차단 · OCR 복구 — 검색되는 근거 자료의 품질에 영향 | v2.125.27 · v2.125.35 ~ v2.125.37 |

릴리즈 기록에서 AI Server 를 호출하는 쪽으로 여러 번 확인되는 생태계 시스템은 HIS · ERP · twin 입니다. 그 밖의 시스템과의 연결을 포함해, 어느 시스템이 실제로 AI Server 를 부르는지와 연결별 상태는 `compatibility.md` 에서 판정합니다.

## 5. 알려진 한계

저장소 문서가 스스로 밝힌 것입니다.

- **자문 보조** — 의료 응답은 자문 보조이며, 실시간 처방 차단 시스템이 아닙니다. 의료기기 해당성 판단과 인허가는 구축 기관이 합니다([의료 면책 고지](../../../DISCLAIMER.md)).
- **16GB GPU 의 한계** — 한 번에 올려 두는 모델은 한두 개입니다(모델 서빙 설정 `OLLAMA_MAX_LOADED_MODELS` · 저장소 문서에 1개와 2개 기록이 함께 있음 · 1개면 모델을 바꿀 때마다 다시 적재하는 시간이 붙습니다). 음성 인식 여러 건의 동시 처리 · 영상과 대화 모델의 동시 적재 · 학습과 서빙의 동시 운용은 더 큰 GPU 가 있어야 풀린다고 저장소 문서가 적습니다.
- **동시 처리** — 단일 워커 구성은 개발 단계의 의도적 선택이며, 동시 사용자가 늘면 구성을 바꿀 계획이 백로그에 있습니다. 모델 서빙 런타임도 동시 요청이 많을 때 병목이 될 수 있어 다른 런타임 전환을 검토 대상으로 적고 있습니다. 동시 사용자 수에 따른 처리량은 아직 공개할 계측이 없습니다.
- **국내 자료 기준** — 의료 데이터 정본(의약품 · DUR · 코드 · 수가)과 의료 법령 · 고시 근거 자료는 한국 공공기관 자료입니다. 다른 나라에서는 그 나라의 기준 데이터와 근거 문서를 새로 붙여야 합니다.
- **카탈로그 · 명세의 범위** — 의료 데이터 카탈로그는 집계 스냅샷이며 컬럼 정의(스키마)는 싣지 않습니다. API 명세의 응답 구조는 코드에서 확정되는 것만 적었고, 확정할 수 없는 경로는 비어 있습니다.
- **모델 약관** — 모델 가중치는 모델마다 약관이 다르고, 일부는 임상 사용 전 승인 · 검증을 요구합니다([THIRD_PARTY.md](../../../THIRD_PARTY.md)).
- 연결별 동작 상태는 `compatibility.md` 에서 판정합니다.

## 6. 설치 · 업그레이드 시 주의

- **모델** — 모델 가중치는 저장소에 들어 있지 않습니다. 구축 기관이 약관을 확인하고 직접 받아 모델 서빙(Ollama)에 올립니다. 역할 → 모델 라우팅 표를 자기 기관이 받은 모델에 맞춥니다.
- **API 키** — 생태계 시스템은 API 키로 붙습니다. 키 발급은 서버 로컬에서만 할 수 있습니다. 키에 만료일이 있으므로 만료 전에 교체 일정을 잡습니다(신 · 구 병행 가능).
- **배치** — AI Server 와 같은 서버에 다른 서비스를 함께 올릴지는 저장소 운영 문서의 배치 기준을 따릅니다(따라가기에서 확정).
- **`ingress_mode`** — 기본값은 `ssh_tunnel` 입니다. 앞단 구성이 다르면 `proxy` 또는 `none` 으로 바꿔야 상태 점검이 거짓 경보를 내지 않습니다. 감시 스크립트도 같은 설정을 봅니다.
- **호출 한도** — 호출하는 시스템은 429 응답을 받으면 기다렸다 다시 시도하게 만듭니다.
- **공공 데이터 동기화** — 의료 데이터 정본은 공공 데이터 API 에서 받아 옵니다. 인터넷 연결이 제한된 환경에서 어떻게 반입하는지는 확인해 구축 가이드에 싣습니다.
- **업그레이드(v2.125.25 이하 → v2.125.41)**
  - `/api/version` 의 변경 이력을 읽던 호출자는 옵션을 붙여 불러야 합니다(v2.125.29).
  - 고비용 경로에 호출 한도가 생겼습니다(v2.125.38).
  - `ingress_mode` 설정이 새로 생겼습니다(v2.125.41).
  - 의료 법령 근거 자료의 중복 정리는 자동 실행 시 미리보기만 합니다. 실제 삭제는 운영자가 저장소 스크립트로 명시 실행합니다(v2.125.27).
- **배포 절차** — 저장소의 배포 스크립트는 코드 가져오기 → 실제 DB 대상 사전 점검 → 회귀 테스트 → 재기동 → 스모크 게이트 순서로 돌고, 게이트를 통과하지 못하면 멈춥니다.

# Clinic — 릴리즈 요약

> 기준 버전 **1.4.0** (정본 위치: `packages/hospital-web/package.json version`) · 기준 커밋 `2b20a89b7c3a` (2026-09-09)
> 요약 범위: v1.1.0 ~ v1.4.0 중 최근 7개(병원 서비스 릴리즈 기록 전부 · 2026-08-10 ~ 2026-08-19) · 작성 2026-09-11
> 사실 확인: 미확인 — 생태계 자료 측 조사 기준(시스템 담당 확인 전)

> **EN** — **Clinic** is hospital groupware — handover, rosters, ward status, medication, the surgery board and alerts in one set of screens — displaying data it receives from HIS and accepting the approval requests HIS sends. At base commit `2b20a89b7c3a` the declared version is **1.4.0**, status `통합` (integration); this summary covers only the **hospital service** inside that repository. Recent releases were largely a retroactive tidy-up of earlier changes (floor layout persistence, roster views, handover notes, medication completion, the surgery board, alert acknowledgement, shift requests) plus remembering which hospital a user logged into and gating screens that require a login. Clinic was **not installed** in the follow-along — a deliberate decision, since it needs the whole main application — so every connection status here comes from **code comparison only** (2026-09-11). Not yet confirmed by the owning project.

## 1. 한 줄 정의와 계층

- **정의**: 병원 그룹웨어입니다. 인수인계 · 근무표 · 병동 현황 · 투약 · 수술판 · 알림을 한 화면 묶음으로 제공하고, HIS 의 자료를 받아 보여줍니다. HIS 가 보내는 결재 요청도 받습니다.
- **계층**: ⑦ 협업 · 교육 계층
- **구현 상태**: `통합`(매니페스트 기준 · 시스템 담당 확인 전)
- **범위**: 이 요약은 저장소 안의 **병원 서비스**만 다룹니다.
- **규모**: 화면 16 · HIS 연동 API 경로 44 — `data/scale-snapshot.json` 의 `systems.clinic.counts`(2026-09-11 계측 · 센 방법은 각 항목의 `rule`)

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**대시보드**
- 의사 · 간호 · 관리자 역할별 대시보드를 제공합니다.

**병동 · 동선**
- 층별 병동 현황(혼잡도 · 대기 · 정원 · 의료진 부재)을 주기적으로 갱신해 보여주고, 대기 초과 · 정원 초과 · 의료진 부재 알림을 띄웁니다. 혼잡도 등급은 HIS 가 판정한 값을 그대로 씁니다.
- 층 배치 편집기가 있고, 배치는 서버에 저장돼 기기 · 브라우저가 달라도 이어집니다.

**근무**
- 근무 캘린더(월 · 주 · 일 보기 · 시간 지정 일정 · 부서별 참석자)와 당직표 · 교대 요청을 다룹니다.

**인수인계**
- 병동을 골라 특이사항을 기록하고 이력을 봅니다. 인수자를 지정할 수 있고, 인수자는 "수신 확인"을 남깁니다.

**투약 · 수술**
- 투약 일정과 완료 표시, 수술판 상태를 다룹니다. 사용자가 바꾼 상태는 Clinic 쪽에도 저장해 다시 들어오거나 자동 갱신돼도 유지됩니다.

**알림**
- 긴급 알림 · 알림함 · 브라우저 알림(종류별로 끄기 · 같은 알림 반복 억제).

**병원 가입 · 계정**
- 병원 등록 마법사(사용할 기능 선택) · 병원 코드로 가입(선택적 승인제) · 로그인한 병원을 기억 · 로그인이 필요한 화면의 진입 게이트.

**HIS 연동 API**
- HIS 가 부르는 API 로 조직 · 직원 동기화, 알림 · 긴급 알림, 웹훅 등록, SSO 티켓 로그인, 근무 · 당직 · 근태 · 휴가, 수술 일정, 체크리스트, 결재 요청(결재 화면은 병원 서비스 밖의 저장소 공용 화면), 역할 매핑을 받습니다. HIS 는 **범위를 지정한 API 키**로 인증합니다.

**출처 표시**
- HIS 에서 자료를 받지 못한 화면은 예시 데이터로 대신 채우고, 화면에 데이터 출처(데모) 배지를 붙입니다.

## 4. 연동 변경 (릴리즈 기록상)

실제로 동작하는지는 통합 릴리즈의 `compatibility.md` 에서 판정합니다.

| 상대 | 변경 | 버전 |
|---|---|---|
| HIS (층 계획) | 인수인계 병동 목록을 HIS 의 층 계획에서 받습니다. 받지 못하면 예시 층 목록을 쓰고 "데모" 배지를 붙입니다 | v1.4.0 |
| HIS (병동 현황) | 혼잡도 등급은 HIS 판정값을 씁니다. Clinic 설정 화면의 혼잡도 임계값은 저장만 되고, HIS 로 전달하는 연동이 생긴 뒤에 반영된다고 적혀 있습니다 | v1.4.0 |
| HIS (투약 · 수술판 · 알림 · 당직 교대) | 상태 변경을 Clinic 쪽에 먼저 저장하고 HIS 에도 보냅니다. HIS 전송이 실패하면 교대 요청은 대기 상태로 남겨 둡니다 | v1.1.0 |

HIS 연동 API(2절)는 저장소 공용 영역에 있어 이 서비스의 릴리즈 기록에 변경이 적히지 않습니다. 이 API 의 변경 이력은 이 요약의 범위 밖입니다.

## 5. 알려진 한계

저장소 문서가 스스로 밝힌 것과, 생태계 차원에서 알려진 것입니다.

- **HIS 와의 인증은 API 키 방식**입니다. 다른 여러 시스템처럼 HIS 토큰을 공개키로 검증하는 방식이 아니므로, 키 발급 · 보관 · 교체를 따로 관리해야 합니다.
- **예시 데이터 대체** — HIS 에서 자료를 받지 못하면 예시 데이터로 채웁니다. 운영에서는 화면의 출처 배지를 확인해야 합니다.
- **혼잡도 임계값**은 설정 화면에 저장되지만 아직 판정에 쓰이지 않습니다(4절).
- **병원 코드 가입은 기본적으로 승인 없이 합류**합니다. 승인제는 병원을 등록할 때만 켤 수 있고, 이미 등록된 병원은 설정 값을 직접 넣어야 합니다(관리 화면은 후속으로 적혀 있음).
- **AI 지식 기능**은 준비 중입니다(구현 없음).
- 이 서비스는 다른 서비스와 한 저장소에 있어, HIS 연동 API · 인증 · 알림 같은 공용 부분은 이 서비스 버전과 따로 바뀝니다.
- 연결별 동작 상태는 `compatibility.md` 에서 판정합니다.

## 6. 설치 · 업그레이드 시 주의

- **병원 화면 패키지만으로는 동작하지 않습니다.** 저장소 공용 API(병원 · HIS 연동 경로)와 인증 구성요소가 함께 있어야 합니다. 함께 설치해야 하는 구성요소의 정확한 범위는 소스 링크를 정리할 때 확정해 싣습니다.
- **HIS 쪽 준비** — Clinic 에서 범위를 지정한 API 키를 발급해 HIS 에 등록하고, 웹훅 서명용 비밀값을 설정한 뒤 조직 · 직원 동기화를 실행합니다.
- **병원 등록 시 정할 것** — 사용할 기능 · 병원 코드 가입 승인제 사용 여부.
- **설정 탭** — 갱신 주기(3초 미만 값은 기본값으로 바뀜) · 알림 종류별 사용 여부.
- **DB 변경** — 로컬 상태 저장(투약 완료 · 수술판 · 알림 확인 · 교대 요청 · 인수인계) 테이블은 저장소의 SQL 스크립트로 추가됩니다. 업그레이드할 때 스크립트 적용 순서를 확인합니다.
- **버전 고정** — 서비스 전용 태그가 없으므로 설치본은 커밋 해시로 고정합니다.

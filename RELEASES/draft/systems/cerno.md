> 기준 버전 **0.1.0** (정본 위치: `services/cerno-api/cerno/api/main.py FastAPI(version=…)` · 릴리즈 기록과 태그는 v0.1.8 — 7절) · 기준 커밋 `4f5c22b331fc` (2026-08-04)
> 요약 범위: v0.1.0 ~ v0.1.8 중 최근 9개(전체 · 2026-07-30 ~ 2026-08-04) · 작성 2026-09-11
> 사실 확인: 미확인 — 생태계 자료 측 조사 기준(시스템 담당 확인 전)

## 1. 한 줄 정의와 계층

- **정의**: 의료진별로 개인화된 임상 지식 질의 서비스입니다. 병원 안의 AI Server 를 써서 근거 문서를 찾아 답변 초안을 만들고, **근거가 없으면 생성하지 않습니다.**
- **계층**: ⑥ AI 계층(의료진 개인화 RAG)
- **구현 상태**: `파일럿`(섀도우 · 비임상 범위 · 매니페스트 기준 · 시스템 담당 확인 전)
- **역할 분담**: 검색 · 임베딩 · 생성 · 약물 상호작용 점검(DUR) 같은 AI 연산은 AI Server 가 맡고, cerno 는 신원 결속 · 서고(지식 문서 관리) · HIS FHIR 조회 · 질의 화면을 맡습니다.
- **규모**: API 핸들러 11 · 화면 3 · 테스트 선언 255 — `data/scale-snapshot.json` 의 `systems.cerno.counts`(2026-09-11 계측 · 센 방법은 각 항목의 `rule`)

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**진료 중 질의**
- HIS 차트에서 SMART on FHIR 로 실행하면 그 환자의 맥락이 질의에 붙습니다. 화면에서 다른 환자로 바꾸는 기능은 두지 않았습니다.
- 서고 세 층(개인 · 그룹 · 공용)을 함께 검색해 합치고, **근거 게이트**를 통과한 경우에만 답변 초안을 만듭니다. 답변의 `[n]` 인용에서 출처 문서로 바로 갈 수 있습니다.
- 근거가 부족하면 오류가 아니라 "근거로 확인되지 않습니다"라는 상태로 알리고, 서고에 문서를 올리는 곳으로 안내합니다.
- 이어서 질문할 수 있습니다(직전 문답 일부를 문맥으로 쓰되 저장하지 않음 · 근거 게이트는 현재 질문으로만 판정).
- 환자 맥락으로 **추천 질문**을 만들어 보여줍니다(분류 · 위험도 · 근거 표시 · 숨기기 · 추가 생성).

**안전 신호**
- 고위험 표지(용량 · 응급 · 금기 · 소아·임신 · 항암)와 DUR 결과를 **근거 유무와 따로** 표시합니다. 근거가 없어 답변을 만들지 않더라도 안전 신호는 보입니다.

**서고와 개인화**
- 서고 관리 화면에서 문서를 올리고 나눠 담습니다. 적재 전에 거버넌스 검사를 거치며, 직접 식별자가 든 문서는 거부합니다.
- 개인화는 모델을 새로 학습하지 않고, 버전이 매겨진 프롬프트 레지스트리 · 개인 서고 가중 · 예시 선별로 합니다.
- 다른 의료진의 개인 서고와 질의 기록은 보이지 않습니다(질의 기록은 "환자 × 본인" 단위).

**검수와 관측**
- 답변 카드에서 세 문항으로 검수 결과를 남기고, 오도율을 셉니다(파일럿 중단 판단의 입력).
- 지표: 근거 통과율 · 검수 비율 · 대기 시간 · AI 키 만료 경보 · 임베딩 상태 점검. 지표는 매일 스냅샷으로 남깁니다.
- 평가 하니스(성능 기준선 · 충실도 표본)와 주간 회귀 스크립트가 있습니다. 실패하거나 개인 자료가 섞이면 종료 코드 1 을 내므로 CI 검사로 쓸 수 있습니다.

## 5. 알려진 한계

저장소 문서가 스스로 밝힌 것입니다.

- **비임상 범위** — 저장소는 "의료기기가 아니며 진단·처방을 자동 확정하지 않는다"고 적습니다. 임상 사용 범위는 결정되지 않았고, 결정 전에는 비임상 한정이 기본값입니다. 규제 판단은 구축 기관이 합니다([의료 면책 고지](../../../DISCLAIMER.md)).
- **파일럿 결과 미반영** — 릴리즈 기록이 파일럿 시작 시점에서 멈춰 있습니다.
- **자연어 프롬프트 인젝션** — LLM 특성상 완전히 막을 수 없다고 문서가 밝힙니다. 다른 의료진의 서고와 다른 환자의 자료는 검색 단계의 소유자 필터로 막고, 나머지는 여러 겹의 방어로 관리합니다.
- **환자별 질의 기록** — "환자 정보를 저장하지 않는다"는 원칙의 명시적 예외입니다. 임상 범위로 넓히려면 보존 기간 · 암호화 · 감사 로그를 다시 정해야 한다고 문서가 적습니다.
- **공용 서고 기본 문서** — AI 가 작성한 요약본(원 지침 출처 표기)입니다. 검수 대상이며 원문으로 바꾸기를 권장합니다.
- **검색 순위** — 개인 노트 가중치 때문에 개인 노트가 공용 지침보다 위에 오는 경향이 있어, 재조정 예정으로 적혀 있습니다.
- **동시 처리** — AI Server 호출은 키 단위로 순서대로 처리되므로, 동시에 쓸 수 있는 규모는 키 구성에 따라 달라집니다.
- **보류된 것(현 사양 밖)** — 어댑터 학습 · 증류, 멀티모달, 전자의무기록 화면 안 임베드.
- 연결별 동작 상태는 `compatibility.md` 에서 판정합니다.

## 6. 설치 · 업그레이드 시 주의

- **구성** — 웹(Next.js) · API(FastAPI) · Redis. 외부에 여는 것은 웹 하나입니다. API 와 Redis 는 포트를 열지 않습니다(API 가 직접 노출되면 웹 프록시의 신원 서명을 우회할 수 있다고 문서가 경고합니다).
- 필수 환경값이 비어 있으면 컨테이너가 뜨지 않도록 돼 있습니다.
- **HIS 쪽 준비** — SMART 앱 등록(EHR launch · JWKS 공개). 참여 의료진의 식별자를 설정 파일에 등록합니다.
- **AI Server 쪽 준비** — 호출 키. 의료진별 키 매핑(`CERNO_AI_KEYS`)은 JSON 형식이어야 하며, 형식이 틀리면 기동하지 않습니다.
- **서고** — 기본 제공 공용 문서는 기관의 원문 지침으로 바꾼 뒤 쓰기를 권장합니다.
- **데이터** — 검수 기록 · 질의 기록 · 지표 스냅샷이 데이터 볼륨에 쌓입니다. 일일 백업 스크립트(7일 보관)가 있습니다. 질의 기록 보존 기간은 기관이 정합니다.
- **업그레이드** — 코드의 버전 선언이 0.1.0 에 머물러 있어 버전 문자열로 설치본을 구분할 수 없습니다. 기준 커밋 해시로 구분합니다.

## 7. 버전 표기와 근거

- **버전 표기의 어긋남**(매니페스트 등급 `주요`)
  - 코드 선언(API · 웹 패키지)은 0.1.0 입니다. 저장소 태그는 v0.1.0 ~ v0.1.8 이 있고, 릴리즈 기록(`CHANGELOG.md`)의 첫 제목도 v0.1.8 입니다. 즉 v0.1.1 이후 릴리즈에서 코드 선언을 올리지 않았습니다.
  - 정본 규칙상 코드 값(0.1.0)을 기준 버전으로 두었고, 매니페스트의 릴리즈일(2026-07-30)도 태그 v0.1.0 의 날짜입니다. 이 요약의 내용은 기준 커밋(v0.1.8 태그와 같은 커밋) 기준입니다.
  - 공개 자료에 어느 표기를 쓸지는 시스템 담당 확인 뒤 정합니다. 그 전까지 **0.1.0(코드 선언) · v0.1.8(릴리즈 기록 · 태그)** 을 함께 적습니다.
- **근거 기록**
  - `CHANGELOG.md` — 9개(v0.1.0 ~ v0.1.8) · 마지막 2026-08-04. 이 요약은 9개 전부를 썼습니다.
  - 이 요약과 수치는 기준 커밋의 내용만 봅니다(작업 트리의 커밋하지 않은 변경은 들어가지 않습니다 — `data/base-commits.json`).

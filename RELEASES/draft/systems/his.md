## 1. 한 줄 정의와 계층

- **정의**: 외래 · 입원 · 수술 · 응급 · 진료지원(약제 · 검사 · 영상 · 병리 · 혈액) · 검진 · 원무 · 청구 · 경영지원을 한 코드베이스에서 다루는 통합 병원정보시스템입니다. 환자 · 진료 · 오더 · 간호 · 원무 · 청구 정보의 정본을 가집니다.
- **계층**: ① 코어. 생태계의 **신원 허브**입니다 — 직원 로그인 토큰을 HIS 가 발급하고 형제 시스템이 검증합니다.
- **구현 상태**: `통합` — 리허설 모드(가상 병원 데이터) · 매니페스트 입력 기준 · 시스템 담당 확인 전
- **구성**: 웹(Next.js 15) · API(NestJS · Prisma) · PostgreSQL 16 · Redis 7 · 공용 패키지(상태 라벨 · 수치 정책 · 역할 목록의 정본). 같은 저장소 안에 공개 홈페이지와 환자 앱이 있으며, 각각 [homepage.md](homepage.md) · [patient-app.md](patient-app.md) 에 따로 요약합니다.
- **역할**: 사용자 역할 14종(임상 4 · 지원 9 · 관리자 1 — 스키마의 `UserRole` 열거값 수 · 2026-09-11 확인)
- **규모**: 데이터 모델 562 · API 핸들러 3,251(+ 실시간 스트림 15) · 웹 화면 450 — `data/scale-snapshot.json` 의 `systems.his.counts.dataModels` · `apiEndpoints` · `apiEndpointsSse` · `pages`(2026-09-11 계측 · 센 방법은 각 항목의 `rule`). API 수는 고유 경로 수가 아니라 핸들러 수이고, 웹 화면 수에 공개 홈페이지 앱은 들어가지 않습니다.

## 2. 이 버전에서 할 수 있는 것 (도메인별)

기준 커밋의 화면 메뉴 구성과 서버 모듈에서 읽은 기능 범위입니다. 화면이 있다는 것이 실운영 검증을 뜻하지는 않습니다. 다른 시스템과의 연결 상태는 통합 릴리즈의 `compatibility.md` 에서 판정합니다.

**외래**
- 접수 · 진료실 대기 · 예약 · 환자 관리(외국인 환자 등록 · 신원 미확인 응급 환자 등록 포함)
- 처방 · 오더 입력(CPOE) — 약속처방(오더세트) · 원내 처방집 · 처방 규칙(CDSS)과 함께 동작
- 진료과별 전문 진료 화면(내과 · 정형외과 · 신경외과 · 산부인과 · 소아청소년과 · 정신과 · 안과 · 이비인후과 · 피부과 · 치과 · 성형외과 · 비뇨의학과)
- 협진 의뢰 · 회신 · 의뢰서, 통합 상황판 · 역할별 대시보드

**입원 · 간호**
- 입원 환자 · 병상 현황 · 회진 · 인수인계 · 퇴원
- 간호 워크스테이션(입원 · 외래) · 스테이션 보드 · 투약 기록(MAR)과 바코드 투약 확인
- 낙상 · 욕창 재평가, 활력징후 경보 임계값 관리, 급식 · 영양

**수술 · 중환자 · 응급**
- 수술 일정 · 수술 준비 · 수술 기록 · 회복실(PACU)
- 응급실(분류 · 병상 · 보드) · Code Blue / 신속대응팀 호출
- 중환자실

**특수 치료**
- 투석 · 항암(치료 주기) · 방사선종양 · 재활 · 장기이식 · 호스피스

**진료지원**
- 약제: 조제 · 약국 보드 · 약사 임상활동 · 무균조제 · 마약류 관리
- 검사: 검사실 · 결과 입력 · 참고치 관리 / 영상: 영상 오더 · 판독 대기 · 영상 조회(PACS 는 HIS 서버를 거쳐 조회)
- 병리 · 혈액은행, 비대면 진료 예약 · 진행 화면(화상 연결은 별도 시스템 — §5)

**검진**
- 검진센터 운영: 접수 · 대기 · 동선 안내(QR) · 검진 스테이션 · 문진표 · 검진 프로그램 · 프로토콜 · 예약 · 소견 · 단체 검진 · 추적 관리 · 통계
- 검진 결과서 발급

**의무기록**
- 기록 검색 · 동의서 · 사본 발급 · 진단서와 제증명 · 미비기록 관리 · 보유 · 파기 관리

**원무 · 청구**
- 수납(분할 납부 포함) · 중간정산 · 원무 보드
- 보험 청구서 작성(EDI 서식) — 대외 기관 전송은 구현돼 있지 않습니다(§5)
- 코드 마스터 · 비급여 관리 · 약품 보험코드 매핑 · 수가 계산기

**경영지원**
- 인사 · 직원 관리 · 진료표 · 당직표 · 전자결재 현황
- 자재 · 재고 · 중앙공급 · 장비 관리
- 원가 분석 · 경영 대시보드 · 운영 통계 · 의료 질 지표

**환자안전 · 질관리 · 연구**
- 환자안전 사고 보고 · 감염관리 · 직원 노출 사고 · 질 향상(QI) · 위원회와 정책 관리
- 임상경로 · 다학제 진료 · 암 등록 · 임상 연구(IRB) · OMOP CDM

**전원 · 상호운용성**
- 전원 의뢰 · 수신 · 이력
- FHIR R4 외부 표면 · SMART on FHIR 클라이언트 등록 · 진료정보교류(HIE) 문서 · 연동 기관 관리와 연동 모니터링

**AI 보조** — 화면의 AI 표기는 공용 상수 하나(`AI(WeRU.B)`)로 통일돼 있고, 면책 문구를 함께 보여줍니다. AI 산출물은 초안이며, 사람이 승인해야 기록이 됩니다.
- 증상 분류(triage)를 보조합니다.
- 진료 대화 · 음성으로 진료 기록 초안을 만듭니다.
- 환자용 약물 설명 · 검진 결과 설명의 초안을 만들고, 사람이 감수 · 승인하는 화면을 거칩니다.
- 환자 문의 · 예약을 돕는 대화(컨시어지 · 예약 도우미)를 제공합니다.
- 감독 장치: AI 제안 원장(생성 → 승인 · 수정 · 거부) · 모델 릴리즈 기록 · AI 호출 기록 · 환자를 지목한 AI 조회의 감사 기록

**거버넌스 · 구축 관리**
- 개원 · 운영 단계 관리, 운영 전환(Go-Live) 관제, 사람이 정할 것을 모은 결정 등록부(항목은 [`checklist/`](../../../checklist/) 참조)
- 운영 모드(개발 / 리허설 / 리얼) · 안전 게이트(끔 / 경고 / 차단) · 대외 발신 관제 · 시스템 설정(값의 출처를 DB / 기본값 / 미설정으로 구분해 표시)
- 상시 감시자(별도 프로세스): 데이터 정합성 · 파이프 생존(백업 · 예약 작업 · 배포 최신성) · 연동 계약 어긋남 · 흐름 완결성의 네 축과 1분 단위 실시간 지표
- 감사 로그 · 긴급 접근(Break-the-Glass) 검토 · 오더 서명 로그 · 전자인증서 · 단말 보안
- 국가 축(현재 한국 · UAE)의 기관 프로파일, 화면 문구 언어팩과 번역 사람 검수 흐름

**환자 접점 관리**
- 웹 환자 포털, 공개 홈페이지 콘텐츠 관리(CMS · 공지 · 배너 · 미디어 · 검색 노출 설정 · 발행)

## 3. 최근 변경

## 4. 연동 변경 (릴리즈 기록상)

- **FHIR R4**: 외부에서 환자를 만드는 요청에 정본 입력 검증을 적용했습니다(v4.13.0).
- **진료정보교류(HIE)**: 문서 종류별 LOINC 문서 코드를 확정 매핑했습니다(v4.15.0).
- **연동 계약 관측**: 외부 응답의 형태가 약속과 다를 때 감시자 원장에 남기는 관측점을 여러 연결로 넓혔습니다(v4.15.0).
- 대외 발신은 계속 세 조건(구현 + 설정(기본 꺼짐) + 승인)을 따릅니다.

각 연결이 실제로 동작하는지(5단계)는 통합 릴리즈의 `compatibility.md` 에서 판정합니다.

## 5. 알려진 한계

- **대외 기관 전송**(청구 · 자격조회 · 법정 보고 등) — 전송 모듈이 구현돼 있지 않습니다. 청구서는 작성까지이며, 기관이 전송 모듈을 붙이거나 기존 청구 소프트웨어와 함께 씁니다.
- **문자 발송 제공자** — 등록돼 있지 않아 환자 본인확인 문자는 모의 발송입니다.
- **기관명 설정** — 병원명이 고정 문자열로 남은 파일이 저장소에 118개 있습니다(웹 68 · 공개 홈페이지 36 · API 11 · 공용 3 — 병원명 고정 문자열이 든 파일 수 · 2026-09-10 계측 · 2026-09-11 기준 커밋에서 다시 세어 같음). 설정값으로 옮기기 전까지는 자기 병원명을 넣으려면 코드를 고쳐야 합니다.
- **로그인 방식** — HIS 가 발급한 토큰을 시스템마다 다른 방식으로 검증합니다(공개키 5곳 · 공유 비밀키 2곳 · API 키 1곳). 공유 비밀키 쪽은 키 관리가 따로 필요합니다.
- **비대면 진료의 화상 연결** — 별도 시스템(Jitsi)에 기댑니다. Jitsi 현재 설치본은 동작하지 않아 구축 기관이 새로 구성해야 합니다.
- **화면 번역** — 카탈로그는 전부 AI 초안이고, 사람 검수를 마친 키는 아직 없습니다. 안전 관련 문구를 번역할지는 결정 등록부의 미결 항목입니다. 서버가 조립해 보내는 한국어 문장 일부는 번역되지 않습니다(늘지 않게만 막아 둔 상태). 아랍어 오른쪽→왼쪽 화면은 "준비"이지 지원이 아닙니다.
- **영상 AI 사전판독** — 사용 매뉴얼상 "사용 불가"입니다.
- **오더세트 금기 조건** — 자동으로 평가되지 않고 "금기 수동 확인"으로 표시됩니다.
- **처방전 유효기간** — 설정값이 아니라 코드 값으로 동작합니다. 근거 확인과 설정 연결은 결정 등록부 항목입니다.
- **감시자의 흐름 완결성 축** — 과거 표본이 쌓이기 전에는 판정하지 않고 "관측 불가"로 둡니다.
- **오프라인 동기화** — 범위 밖입니다(저장소 README 의 제외 항목).

## 6. 설치 · 업그레이드 시 주의

- **설치 순서**(저장소 안내): 의존성 설치 → 데이터베이스 · 캐시 컨테이너 기동 → 마이그레이션 → 시드 → 실행. 기본 시드는 가상 병원 데이터이고 특정 기관명이 들어 있습니다(§5 기관명 설정).
- **스키마 반영**: 데이터 손실을 허용하는 옵션으로 스키마를 밀어 넣지 않습니다(저장소 금지 사항). 스키마가 바뀌는 배포는 자동 백업을 거치는 경로를 씁니다.
- **v4.14.0 이전에서 올릴 때**: 상시 감시자가 API 와 별도 프로세스로 돌기 때문에 프로세스가 하나 늘고, 감시자 원장 모델이 추가됩니다.
- **v4.18.0 으로 올릴 때**: 번역 검수 원장 테이블이 추가되므로 스키마 반영이 필요합니다. 검수 흐름을 쓰려면 설정에서 검수자를 지정합니다.
- **v4.12.0 이전 데이터가 있을 때**: 여권 · 외국인등록번호 암호화 백필이 필요하고, 여권번호 검색은 부분 검색에서 정확 일치로 바뀝니다.
- **암호화 키**: 개인식별정보 암호화 키는 설치 때 새로 만듭니다. Go-Live 관제가 기본값이거나 비어 있는 키를 "준비 안 됨"으로 표시합니다.
- **배포 스크립트**: 실행한 작업 디렉터리를 그대로 서버에 동기화합니다. 커밋되지 않은 변경도 함께 올라가고, 두 곳에서 동시에 배포하면 서로를 덮어씁니다.
- **실운영 전환**: 개발 → 리허설 → 리얼 순서이며, 리얼 전환(가상 데이터 격리 · 리얼 빌드)은 구축 가이드 S8 을 따릅니다.
- **설치 뒤 기관이 채울 것**: 개원 준비 · 개시 점검 · 사람 결정 항목은 [`checklist/`](../../../checklist/) 에 있습니다. 설정 화면에서 "기본값"으로 표시되는 값은 아직 아무도 정하지 않은 값입니다.

## 7. 버전 표기와 근거

- **정본**: 공용 패키지 상수 `HIS_VERSION` = v4.18.0. 릴리즈 기록과 이 상수는 함께 올라가며, 저장소의 검사가 둘을 대조합니다(v4.17.0 기록).
- **어긋남**(매니페스트 `version.mismatchWith`):
  - 루트 `package.json` 1.0.0 · `apps/api` · `apps/web` 의 `package.json` 1.5.0 — 릴리즈마다 올리는 값이 아닙니다.
  - git 태그는 이제 **v4.18.0 이 있습니다** — 기준 커밋보다 3커밋 앞의 커밋에 붙어 있고, **2026-09-13 에 만든 주석 태그**입니다(재계측에서 확인 · 그전에는 v3.46.0(2026-07-11)에서 멈춰 있었습니다). v3.46.0 과 v4.18.0 사이의 릴리즈에는 태그가 없습니다.
- **기준 커밋과 릴리즈 기록의 차이**: 기준 커밋은 v4.18.0 릴리즈 기록 뒤의 커밋 3개를 포함합니다. 코드 상수는 v4.18.0 그대로이므로, 이 조합의 HIS 는 "v4.18.0 + 기록 없는 커밋 3개"입니다(§3 끝).
- 저장소 README 의 "최신 릴리즈 문서" 안내는 v4.17.0 에 머물러 있습니다.
- **근거**: `docs/04-report/RELEASE-v*.md` 107개(v3.11.0 ~ v4.18.0) · 마지막 기록 v4.18.0(2026-09-09 ~ 10). 릴리즈 기록에 적힌 규모 · 테스트 수치는 옮기지 않았고, 규모는 계측 스냅샷을 따릅니다.

## 8. 새 설치본으로 세워 본 결과 (2026-09-13~16)

기준 커밋을 풀어 **새 설치본**을 세우고, 다른 새 설치본과만 호출해 봤습니다(개발 PC 한 대 · arm64 · GPU 없음 · 외부로 나가지 못하는 네트워크 · 가상 병원 데이터). **기준 장비가 아닙니다** — 처리량 · 응답 시간 · AI 품질은 이 결과로 판단하지 않습니다.

- 🔴 **저장소의 운영용 컨테이너 파일로는 그대로 설치되지 않았습니다.** 빌드가 메모리로 멈추고, 선언되지 않은 의존성이 있고, 스키마 반영 명령이 문서와 달랐고, API 가 컨테이너 안에서 자기 자신에게만 붙었습니다. 첫 관리자 계정은 기본 시드로만 만들어집니다. 우회한 순서는 [S1](../../../build-guide/S1-core-his.md)에 적었습니다.
- HIS 가 한쪽 끝인 연결 가운데 **18개**를 실제로 호출해 `검증됨` 을 붙였습니다(2026-09-14~15) — 검사 오더 전달(→ LIS) · 직원 서명(→ sign) · 직원 SSO(→ ERP) 등.
- HIS 화면에서 PACS 를 부르는 영상 경로(워크리스트 등록 · 영상 조회 · 판독 작성 · 뷰어 진입)는 **완료를 확인하지 못했습니다** — 코드 수정이나 프로젝트 사이 협의가 필요합니다.
- 무엇을 어떻게 확인했고 무엇이 남았는지는 [따라가 본 결과](../../../build-guide/follow-along-2026-09.md)에 있습니다.

## 1. 한 줄 정의와 계층

- **정의**: 병원 운영 · 기기 · 환자를 모델로 옮겨 위험 점수 카드 · SBAR · What-if 시뮬레이션 · 3D 시각화를 제공하는 디지털 트윈 서비스입니다. HIS · PACS · AI Server 의 자료를 **읽어서** 쓰는 별도 서비스입니다. HIS 에 쓰는 것은 write-back(위험 평가 · SBAR · 임상의가 작성한 SOAP)뿐이며, 사용자별 토큰으로 보냅니다.
- **계층**: ⑥ AI 계층(위험 예측 · 시뮬레이션)
- **구현 상태**: `통합`(매니페스트 기준 · 시스템 담당 확인 전)
- **규모**: API 핸들러 107 · 화면 15 · 테스트 선언 881 — `data/scale-snapshot.json` 의 `systems.twin.counts`(2026-09-11 계측 · 센 방법은 각 항목의 `rule`)

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**운영 트윈**
- 병상 · 중환자실 · 응급실 · 수술실의 점유 · 회전 · 부하 지표를 모읍니다.
- 이산사건 시뮬레이션으로 병상 증설 · 응급실 인력 변경의 What-if 를 돌리고, 필요한 최소 인력 · 병상 수를 찾는 스윕을 제공합니다.
- 병동 단위 위험 분포(집단 트윈)와 기기 트윈(예지 정비 위험 · 점검 준수 · 실제 사용 기록 반영)을 봅니다.

**환자 위험 점수 카드**
- 공표된 임상 점수 · 위험 모델을 카드로 보여줍니다. 영역: 심혈관(PCE · PREVENT · 한국인 모델 K-CVD · SCORE2-AP · UKPDS) · 신장(eGFR · KDIGO) · 조기 경보(NEWS2) · 정맥혈전색전증(Padua · Caprini · Wells) · 폐색전증 중증도(PESI · sPESI · 임상 분류) · 간(FIB-4 · MELD · Child-Pugh) · 폐렴(CURB-65) · 심방세동(CHA₂DS₂-VASc · HAS-BLED) · 소화기 출혈(Glasgow-Blatchford) · 급성 췌장염(BISAP).
- 카드마다 계산식 · 변수 · 등급 · 적용 범위 · 원 논문 인용을 펼쳐 볼 수 있습니다. 모든 모델은 모델 카탈로그에 등재돼야 하고, 빠지면 CI 가 실패합니다.
- 자동으로 채운 입력값을 임상의가 화면에서 고칠 수 있습니다(그 조회에만 적용 · 저장하지 않음). 빠진 입력은 0 으로 채우지 않고 "입력 필요"로 표시합니다.
- 금연 · 혈압 · 혈당 · 스타틴 같은 치료 중재의 What-if 를 여러 모델로 비교합니다.

**임상 문서 · HIS 반영**
- SBAR 는 규칙 기반으로 생성합니다(LLM 을 쓰지 않음). 위험 평가 · SBAR · SOAP 를 FHIR 자원으로 HIS 에 write-back 할 수 있고, 보내기 전에 FHIR 규격 검증을 거칩니다. 동의가 필요하다는 응답을 받으면 저장하지 않고 그 사유를 표시합니다.
- CDS Hooks 카드로 HIS 차트에 위험 정보를 보냅니다.

**AI 보조**
- AI Server 의 모델로 임상 설명 초안 · 영상 판독 초안 · 근거 문서 인용을 만듭니다. 이 출력은 `machine-generated` 로 표시되고 **의무기록에 직접 기록되지 않습니다**(저장소 문서 기준).
- 위험 점수 · NEWS2 · eGFR 같은 정량 산출은 LLM 을 거치지 않습니다.
- 환자 아바타(다장기 메시 · 심장 전기생리 시각화)와 생리 엔진 예후 What-if 는 무거운 연산을 AI Server 또는 별도 컨테이너에 맡깁니다.

**외부 질의(선택)**
- 트윈의 읽기 기능을 MCP(Model Context Protocol) 도구로 노출할 수 있습니다. 기본은 꺼져 있고, 켜면 응답의 직접 식별자를 가립니다(기본값).

**거버넌스 · 관측**
- 환자 상세는 조회할 때 HIS 에서 받아 오고, 트윈 DB 에는 파생 지표 · 집계만 둡니다. 환자 정보 조회는 감사 로그에 남습니다.
- Prometheus 지표 · 요청별 지연과 HIS 호출 수 계측 · 사용하는 LLM 모델의 교체 감지 알림을 제공합니다.
- 규제 산출물: SBOM · SOUP 목록 · V&V 프로토콜 · FMEA · 변경 계획(PCCP) 초안 — 표기 수준 `대응 설계`.

## 3. 최근 변경

범위: v1.20.73 ~ v1.20.88(16개 · 2026-08-26 ~ 2026-09-03).

- **새 위험 영역** — 폐색전증 중증도(PESI · sPESI · 2026 임상 분류, v1.20.73) · 소화기 출혈(v1.20.83) · 급성 췌장염(v1.20.85)을 추가했습니다. PREVENT 에 요 알부민·크레아티닌 비를 반영하는 모델을 연결하고, 공개된 참조 예제로 계산을 검증했습니다(v1.20.82).
- **근거 표시** — 카드의 근거 보기를 변수 · 등급 · 적용 범위 · 원 논문 링크 단위로 세분화했습니다(v1.20.74). 모델 카탈로그를 만들고 등재를 CI 로 강제했습니다(v1.20.73).
- **성능 · 화면** — 요청 계측을 넣고, 차트 탭을 다시 열 때 재조회하지 않게 했으며, 위험 카드를 한 번에 받아 HIS 호출을 줄였습니다. 8개 위험 카드 모두에 임상 입력 폼을 붙이고, 실패한 카드는 사라지지 않고 재시도 안내를 보이게 했습니다(v1.20.75 ~ v1.20.78).
- **계산 정확성** — 위험 엔진 점검에서 확인한 계산 결함 10건을 고쳤습니다(v1.20.81). 예: 성별을 모를 때 eGFR 을 남성 계수로 계산하던 것을 "산출 안 함"으로 · 공표 연령 범위 밖의 30년 위험 산출 차단 · 임신이 감지되면 심혈관 모델을 산출하지 않고 사유 표시 · 인식하지 못한 등급을 조용히 낮추던 것을 경고로 표시.
- **정리 · 문서** — 중복 코드 · 쓰지 않는 코드를 걷어냈고(v1.20.84, 동작 변화 없음), SBOM 에 빠진 구성요소를 등재했으며(v1.20.79), 문서 버전이 코드보다 뒤처지면 CI 가 실패하는 검사를 넣었습니다(v1.20.80 · v1.20.86).
- **HIS FHIR 조회 채널 전환** — 4절을 보세요(v1.20.87 · v1.20.88).

## 5. 알려진 한계

저장소 문서가 스스로 밝힌 것입니다.

- **의료기기 해당성** — 안전 등급 분류는 예비 단계이고, 의료기기 해당성 · 유형 판단은 확정되지 않았습니다. 판단과 인허가는 구축 기관이 합니다([의료 면책 고지](../../../DISCLAIMER.md)).
- **위험 분석상 남은 항목** — 저장소의 FMEA 는 AI 관련 고장 모드 중 자동화 편향 · 데이터 편향 두 항목을 "조치 필요"로 분류합니다(원인: 정량 검증 미실시).
- **장기 · 생체 3D 트윈** — 설계 단계입니다. 별도 GPU · 고성능 연산 자원이 있어야 진행할 수 있습니다.
- **트윈 서버 자체에는 GPU 가 없습니다.** 환자 아바타 · 영상 메시 · 심장 전기생리 연산은 AI Server 가 있어야 동작합니다.
- **자동 입력 범위** — 수술·시술 세부 · 혈전성향 검사 · 중증도 등급 · 이동성 같은 일부 입력은 자동으로 채워지지 않을 수 있습니다. 이때는 임상 입력으로 받거나 "미평가"로 표시합니다. 흡연 상태가 없으면 가정값을 쓰고 가정했다는 표시를 붙입니다. 사회박탈지수(SDI)만 쓰는 추가 모델은 구현되지 않았습니다.
- **근거 원문 링크** — AI 가 인용한 근거 문서의 URL · DOI 표시는 AI Server 쪽 근거 자료 구성에 따라 달라집니다.
- 연결별 동작 상태는 `compatibility.md` 에서 판정합니다.

## 6. 설치 · 업그레이드 시 주의

- **구성** — API · 워커 · PostgreSQL · Redis 가 기본이고 웹 화면은 선택입니다. 트윈 서버에는 GPU 가 필요 없습니다(무거운 연산은 AI Server).
- **Redis 비밀번호는 필수**입니다. 설정하지 않으면 기동하지 않습니다.
- **기본값이 꺼져 있어 운영 전에 켤지 정해야 하는 설정**
  - `patient_require_consent` — 환자 동의 요구(저장소 설정 주석: 동의 운영을 확인한 뒤 켜기를 권장)
  - `twin_identity_enforce` — 웹 프록시가 붙이는 신원 헤더의 서명 검증 강제
  - `mcp_enabled` — MCP 질의 서버(켜면 `mcp_deidentify` 기본값으로 응답 비식별)
  - `pulse_enabled` — 생리 엔진 예후 What-if(별도 컨테이너)
- **HIS 쪽 준비** — SMART 클라이언트 등록(시스템 범위 읽기 · 사용자 launch) · 서비스 계정 · 동의 조회 API. 새 버전에서는 HIS 가 발급하는 id_token 에 iss · aud · exp 가 있어야 합니다.
- **AI 모델 고정** — 채팅 모델 이름과 digest 를 설정으로 고정하고, 6시간마다 AI Server 와 대조해 바뀌면 알립니다. 다른 모델을 쓰려면 설정을 바꾸고 저장소의 변경 절차(PCCP)에 따라 검증 스크립트를 다시 돌립니다.
- **업그레이드** — DB 는 Alembic 마이그레이션으로 올립니다. 설치 뒤 `/health/deps` 에서 FHIR 검증기 상태를 확인합니다. 의존성이 어긋나면 write-back 전 규격 검증이 꺼질 수 있어, 해당 의존성을 버전 고정해 두었습니다.

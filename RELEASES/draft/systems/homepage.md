## 1. 한 줄 정의와 계층

- **정의**: 병원의 공개 웹사이트입니다. 병원 · 진료 · 검진 · 이용 안내를 보여주고, AI 예약 도우미로 진료 예약을 돕습니다. 내용은 HIS 의 공개 API 와 HIS 관리 화면에서 편집한 CMS 콘텐츠를 읽어 그립니다.
- **계층**: ② 환자 접점
- **구현 상태**: `운영` — 공개 사이트로 쓰이는 중 · 매니페스트 입력 기준 · 시스템 담당 확인 전
- **구성**: HIS 저장소의 별도 Next.js 앱(`apps/homepage`)입니다. HIS 웹 안의 `(homepage)` 라우트 그룹과는 다른 앱이며, **격리 빌드**라 저장소의 공용 패키지를 직접 쓰지 않습니다(필요한 정본은 복제본 + 대조 검사로 맞춥니다).
- **규모**: 화면 50 — `data/scale-snapshot.json` 의 `systems.homepage.counts.pages`(2026-09-11 계측 · 센 방법은 `rule`). HIS 웹 화면 수에는 들어가지 않습니다.

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**병원 소개**
- 병원 소개 · 시설 · 오시는 길 · 갤러리 · 사회공헌 페이지
- 병원 소식 · 채용 공고 · 사이트 검색

**진료 안내**
- 진료과 · 진료센터 · 의료진 소개(각 상세 페이지 포함) · 진료 일정표 · 비급여 항목 안내
- 진료시간은 CMS 에 등록한 값을 읽고, 없을 때만 코드 기본값을 씁니다.

**건강검진**
- 검진 프로그램 목록 · 상세 · 검진 절차 · 자주 묻는 질문, 검진 수용 현황 조회

**예약 (AI 보조)**
- AI 예약 도우미 — 증상을 대화로 받아 진료과 후보를 제안하고, 날짜 · 시간을 골라 예약까지 진행합니다. 진료과 제안은 AI 가 만든 참고 정보이며 면책 문구가 함께 나옵니다. 화면의 AI 표기는 `AI(WeRU.B)` 입니다.
- 본인 확인을 마친 환자에게는 자기 진료 · 검사 · 복약 · 수납 · 예약 요약 카드를 보여줍니다(환자 포털 인증을 씁니다).

**이용 안내 · 고객 지원**
- 입원 · 제증명 발급 · 식사 · 문서 보안 · 응급 · 장례 · 주차 · 환자 권리 · 면회 안내, 건강정보
- 자주 묻는 질문 · 고객의 소리(VoC), 개인정보처리방침 · 이용약관

**국제 진료 · 협력**
- 해외 환자 보험 · 협력 기관 · 상호운용성(FHIR R4) 안내
- 협력 기관 신청서 — HIS 의 공개 접수 API 로 보내고 접수번호를 안내합니다.
- 영어 · 일본어 · 중국어 소개 페이지

**운영 · 발행** (HIS 관리 화면과 함께)
- 콘텐츠 편집: HIS 의 홈페이지 관리 화면(CMS · 공지 · 팝업 · 배너 · 미디어 라이브러리 · 검색 노출 설정)
- CMS 편집 화면이 "이 항목이 공개 화면 어디에 표시되는지"와 "공개 화면이 읽는데 비어 있는 항목"을 알려주고, 브랜드 표현 프리셋(명암 대비를 검사한 색 조합)을 고를 수 있습니다.
- 발행: HIS 관리 화면의 홈페이지 배포에서 사람이 발행합니다. 반영 여부는 사이트에 실린 빌드 스탬프로 판정합니다.
- 사이트맵 · 검색엔진 안내 파일 자동 생성, 콘텐츠 캐시 재검증 경로, 상태 확인 경로

## 3. 최근 변경

**v4.15.0** (2026-09-03)
- 발행 여부 감지 기준을 페이지 본문 표본에서 **빌드 스탬프 파일**로 바꿨습니다. 관리 화면 · 배포 스크립트 · 감시자가 같은 기준을 씁니다. 스탬프가 없을 때(404)만 "낡음"으로 말하고, 연결 실패는 판정하지 않습니다.

**v4.14.0** (2026-09-03)
- HIS 상시 감시자의 파이프 생존 축이 공개 사이트 배포 최신성을 봅니다.
- 통계 카드의 라벨 · 값 배치를 공용 부품에서 정리했고, 공개 사이트의 다국어 · 국제 진료 소개 페이지에도 함께 반영됐습니다.
- 협력 기관 신청서가 실제 접수 API 로 연결됐고, 근거가 확인되지 않은 사회공헌 통계 문구를 내렸습니다(커밋 이력 · 릴리즈 기록에 별도 항목 없음).

**v4.13.0** (2026-09-02)
- 입력 정화(XSS 방어) · 공개 조회 모듈의 복제본이 웹 정본과 어긋나면 실패하는 대조 검사를 추가했습니다. 웹에서 고친 보안 수정이 공개 사이트에만 빠지는 일을 막기 위한 것입니다.

**v4.12.0** (2026-09-01)
- 예약 도우미의 환자 요약 카드를 바로잡았습니다 — 포털 인증 결과를 조회에 쓰고, 존재하는 API 로 다시 연결했습니다.
- 검진 프로그램 조회를 공개 전용 경로로 옮겨 로그인 없이 볼 수 있게 했습니다.
- 웹 쪽만 고쳐지고 공개 사이트 복제본이 뒤처져 있던 페이지를 맞췄습니다.

**v4.6.0** (2026-08-20 ~ 21)
- CMS 정밀화: 카테고리별 필드 정본, 구조화 편집기, 비어 있는 항목 표시, 브랜드 표현 프리셋 5종, 공개 사이트 복제본과 프리셋의 대조 검사.

## 4. 연동 변경 (릴리즈 기록상)

- 공개 홈페이지는 **HIS API 만** 부릅니다(공개 조회 · 환자 포털 인증 · 예약 대화 · 협력 기관 접수). 형제 시스템과의 직접 연결은 릴리즈 기록상 없습니다.
- 검진 프로그램 조회가 HIS 의 공개 전용 경로로 바뀌었습니다(v4.12.0).

HIS 와의 연결 상태는 통합 릴리즈의 `compatibility.md` 에서 판정합니다.

## 5. 알려진 한계

- **기관 정보가 코드에 있습니다** — 병원 이름 · 연락처 · 주소는 사이트 정보 상수 파일에, 일부 소개 문구 · 수치는 페이지 소스에 들어 있습니다. 병원명 고정 문자열이 든 파일이 이 앱에 36개 있습니다(HIS 저장소 전체 118개 중 · 병원명 고정 문자열이 든 파일 수 · 2026-09-10 계측). 자기 기관 정보로 바꾸려면 코드를 고쳐야 합니다. 사이트 정보 상수를 HIS 의 병원 정보 API 로 덮어쓰는 방식은 코드 주석상 "향후" 과제입니다.
- **격리 빌드** — 공용 패키지를 쓰지 못해 복제본을 둡니다. 대조 검사가 있는 모듈(입력 정화 · 공개 조회 · 표현 프리셋) 밖의 페이지는 웹 쪽 수정이 자동으로 오지 않습니다.
- **다국어** — 영어 · 일본어 · 중국어는 소개 페이지 한 장씩이고, 나머지 페이지는 한국어입니다.
- **발행은 별도 경로** — HIS 웹 · API 배포와 따로 발행하며, 발행은 사람이 합니다.

## 6. 설치 · 업그레이드 시 주의

- 기관 정보 상수와 페이지 소스의 기관 고유 문구를 먼저 바꿉니다(§5).
- 브라우저에서는 HIS API 를 **상대 경로**로 부릅니다. 공개 사이트와 HIS API 를 같은 출처 뒤(리버스 프록시 등)에 두는 구성을 전제로 합니다.
- 공용 표현 프리셋을 바꾸면 복제본을 동기화하는 저장소 스크립트(`sync:cms-style`)를 돌립니다. 동기화하지 않으면 대조 검사가 실패합니다.
- 콘텐츠는 HIS CMS 에 넣습니다. 편집 화면의 "비어 있는 항목" 표시를 채우지 않으면 공개 화면의 해당 자리가 비거나 기본 모양으로 나옵니다.
- 발행 뒤에는 빌드 스탬프로 새 빌드가 실렸는지 확인합니다.

## 7. 버전 표기와 근거

- **정본**: HIS 와 같은 `HIS_VERSION`(v4.18.0)을 씁니다. 공개 홈페이지만의 릴리즈 번호는 없습니다.
- **어긋남**(매니페스트 `version.mismatchWith`):
  - `apps/homepage/package.json` 1.0.0 — 릴리즈마다 올리는 값이 아닙니다.
  - git 태그는 이제 **v4.18.0 이 있습니다** — 기준 커밋보다 3커밋 앞의 커밋에 붙어 있고, **2026-09-13 에 만든 주석 태그**입니다(재계측에서 확인 · 그전에는 v3.46.0(2026-07-11)에서 멈춰 있었습니다).
- **근거**: HIS 의 `docs/04-report/RELEASE-v*.md` 107개(마지막 v4.18.0 · 2026-09-09 ~ 10) 중 요약 범위 14개에서 이 앱에 닿는 기록 5개, 그리고 같은 기간 `apps/homepage` 커밋 이력으로 교차 확인했습니다. v4.18.0 이후 기준 커밋까지의 커밋 3개는 이 앱을 건드리지 않습니다.

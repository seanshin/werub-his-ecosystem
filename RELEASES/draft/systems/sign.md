## 1. 한 줄 정의와 계층

- **정의**: 의료 문서(동의서 · 판독 보고서)와 일반 계약서에 대해 "누가 · 언제 · 무엇에 서명했고, 그 뒤로 바뀌지 않았다"를 검증할 수 있게 만드는 독립 전자서명 서비스입니다. 자체 PKI(2단 CA) · RFC 3161 타임스탬프 · PAdES-LTA · CMS(CAdES) · 감사 해시체인으로 이루어집니다.
- **계층**: ④ 신뢰 계층 — 구축 단계 S4 에서 붙입니다. HIS · PACS 같은 연동 시스템은 개인키를 갖지 않고, 인증서 발급은 sign 한 곳에서만 합니다.
- **구현 상태**: `통합`(매니페스트 기준 · 시스템 담당 확인 전)
- **규모**: 데이터 모델 14 · API 오퍼레이션 162 · API 핸들러 162 · 화면 38 — `data/scale-snapshot.json` 의 `systems.sign.counts`(2026-09-11 계측 · 센 방법은 각 항목의 `rule`)

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**서명 · PKI**
- 2단 CA(Root · Issuing)가 서명자별 X.509 인증서를 발급합니다. 서명은 CMS(CAdES-BES)와 PAdES-LTA 로 만들고, RFC 3161 타임스탬프(자체 TSA)를 붙입니다. 기본 알고리즘은 RSA-3072 · SHA-256 입니다.
- 검증은 공개키로 실제 서명을 확인하고, **서명 시점 기준**으로 폐기 여부(CRL · OCSP)를 봅니다. PAdES-LTA 는 검증 자료를 PDF 안에 넣어 인증서 만료 뒤에도 검증할 수 있게 합니다.
- CA · TSA 키의 회전과 이력을 관리합니다.

**위변조 증거**
- 모든 행위(생성 · 발송 · 열람 · 서명 · 폐기)를 append-only 감사 해시체인에 쌓고, 체인의 머리를 타임스탬프로 봉인(앵커)합니다.
- 앵커에 **외부 RFC 3161 TSA 토큰을 함께 받아 둘 수 있습니다**(선택). 외부 토큰은 운영자도 위조할 수 없어서, 제3자가 sign 없이 표준 도구(`openssl ts -verify`)로 "그 시각에 그 체인이 있었다"를 검증할 수 있습니다.

**키 수탁**
- 기본은 소프트웨어 수탁(마스터키로 암호화한 파일 볼트)입니다. 키 연산을 앱 프로세스와 분리하는 프록시 구성이 있습니다.
- HSM 어댑터(온프레미스 PKCS#11 · 클라우드 KMS)가 있고, 범위는 CA 두 키로 한정합니다. 말단 서명키와 TSA 키는 소프트웨어로 둡니다.
- 인증서 개인키가 소프트웨어에 있었는지 HSM 에 있었는지(`assuranceLevel`)를 발급 · 검증 응답에 함께 실어, 검증하는 쪽이 신뢰 수준을 스스로 판단하게 합니다.

**서명 채널**
- 연동 시스템이 서명값을 만들어 제출하는 방식(모델 A), sign 이 1회용 링크를 발급해 서명자가 브라우저에서 서명하는 방식(모델 B), 의료진 SSO 서명(HIS 가 발급한 토큰을 검증하고 서명자와 결속), 대리 서명을 지원합니다.
- 본인확인은 위험도별 방식(휴대폰 본인확인 · 앱 추가 인증 · 대면 · 의료진 SSO)을 서명에 결속하는 구조입니다. 본인확인 사업자 연결은 어댑터만 있고 기관이 계약해 붙입니다(5절).

**연동 API**
- HIS · PACS 가 한 번의 호출로 인증서 발급과 서명 요청을 만들 수 있습니다.
- 웹훅: 이벤트 ID 멱등 · HMAC 서명 · 재시도 뒤 실패 확정(DEAD) · 재발송 · 폐기 · 소비자별 시크릿 분리. 다자 서명의 중간 진행도 웹훅으로 알립니다.
- 의료진 행위 인증 로그 — 연동 시스템이 처방 · 판독 승인 같은 행위를 해시체인과 타임스탬프로 봉인해 둘 수 있습니다.
- 전체 API 는 OpenAPI 명세와 API 카탈로그로 제공합니다.

**일반 전자계약** (기능 플래그로 켬)
- 준비(PDF 업로드 · 서식 작성 · 서식 편집기 · 한글 PDF 조판) → 발송(접근암호 · 잠금) → 체결(내부 · 외부 서명, 순차 · 동시) → 관리(보관 · 리마인더 · 교부 링크 · QR 진위 확인)까지 다룹니다.
- 서명자가 입력란에 직접 기재한 값은 봉인하고 표시용으로만 합성해, 원본 문서의 해시는 바뀌지 않습니다.

**콘솔 · 운영**
- 인증서 발급 · 폐기 · OCSP, 역할 기반 권한(admin · operator · viewer), TOTP 2단계 인증, 비활동 로그아웃과 동시 세션 제한을 서버에서 강제합니다.
- 기계 키(연동 시스템용 API 키)는 끊김 없이 회전할 수 있습니다.
- 능동 탐지: 백업 신선도 · 감사 체인 무결성 · 로그인 실패 급증 · 웹훅 실패 확정 · 준비 상태를 주기적으로 점검하고 운영자에게 이메일로 알립니다.
- 백업 자동화 스크립트(암호화 · 세대 보관 · 오프사이트)와 복구 리허설 절차가 있습니다.

**기본 꺼짐으로 두는 기능**
- 전자결재 · 포털 문서 미리보기 — 저장소 문서상 보안 검토 서명을 기다리는 기능입니다.
- 계약 첨부의 보존 기간 파기 — 설정하지 않으면 영구 보관합니다.

**규제 표기**
- 전자의무기록(EMR) 인증 기준의 보안성 항목과 sign 구현을 대응시킨 표가 저장소에 있습니다 — `대응 설계`. 외부 인증 · 승인 증빙은 없습니다.
- 전자서명의 법적 효력에 관한 판단(본인확인 사업자 연결 포함)은 구축 기관과 법무가 합니다.

## 5. 알려진 한계

저장소 문서가 스스로 밝힌 것과, 생태계 자료가 구축 기관에 미리 알리는 것입니다.

- **CA 키는 소프트웨어로 보관합니다.** HSM 어댑터는 있지만 적용되지 않은 상태이고(`assuranceLevel` 은 소프트웨어 수준), HSM 을 쓰려면 기관이 장비나 클라우드 키 관리 서비스를 마련해야 합니다.
- **공인 타임스탬프 기관과 연결돼 있지 않습니다.** 서명에는 자체 TSA 를 쓰고, 외부 교차 앵커는 선택입니다. 공인 TSA 를 계약하면 주소 설정만 바꾸면 되도록 짜여 있습니다.
- **본인확인 사업자와 알림(문자 · 메시지) 사업자 연결은 모의 상태입니다.** 어댑터는 있고, 기관이 계약해 연결합니다.
- 마스터키 교체(회전) 절차는 저장소 보안 강화 계획의 남은 항목입니다. 설치할 때 새로 만들고 서버 밖에도 안전하게 보관합니다.
- 장기 보관 문서의 재타임스탬프(아카이브 타임스탬프 갱신) 작업이 아직 없습니다. 인증서 · TSA 수명보다 문서 보존 기간이 긴 경우에 해당합니다.
- 콘솔 2단계 인증은 TOTP 이며, 피싱에 강한 방식(패스키)은 계획 항목입니다. 기계 인증의 mTLS 결선, 업로드 파일 악성코드 검사도 계획 항목입니다.
- 한 기관(단일 테넌트)을 전제로 합니다. 여러 기관을 한 설치본에서 격리하는 구조는 없습니다.
- 콘솔 · 포털 다국어는 아직 없습니다(한국어).
- 암호 모듈은 표준 알고리즘을 쓰며, 국내 검증필 암호모듈(KCMVP)은 쓰지 않습니다. 필요한지는 기관 유형에 따라 구축 기관이 판단합니다.

## 6. 설치 · 업그레이드 시 주의

- 운영 구성은 서비스(API) · 웹 · PostgreSQL 컨테이너입니다. 컨테이너가 기동할 때 DB 마이그레이션을 자동으로 적용합니다. 마스터키 같은 비밀값은 설치할 때 새로 만들어 넣습니다.
- **1.26.0 이전에서 올릴 때** — 1.26.0 에서 들어온 동시성 보호용 마이그레이션은 감사 체인에 이미 분기가 있으면 일부러 실패합니다. 배포 전에 저장소 운영 가이드의 읽기 전용 점검을 먼저 돌립니다. 데이터가 매우 많으면 인덱스를 먼저 따로 만듭니다.
- **1.28.0** — CSP 는 관찰 모드가 기본입니다. 위반 보고를 본 뒤 차단 모드로 바꿉니다.
- **1.29.0** — 알림 수신처를 설정하지 않으면 경보가 로그에만 남습니다. 백업 스크립트가 성공 신호를 보내게 설정하지 않으면 백업 신선도 경보가 계속 납니다.
- **1.30.0** — 운영 하드닝을 켠 상태에서 허용 출처(CORS)를 설정하지 않으면 교차 출처 요청을 거부합니다. 콘솔이나 API 를 다른 출처에서 부르면 허용 목록을 넣습니다.
- 외부 TSA 교차 앵커는 주소를 설정해야 켜집니다. 설정하지 않으면 자체 앵커만 씁니다.
- **실운영 전환 전** — 저장소 문서는 테스트 데이터와 CA 를 새로 만드는 초기화 절차를 두고 있습니다. 이때 연동 시스템이 보관한 인증서도 다시 발급받아야 합니다. HSM 전환 · 본인확인 사업자 연결 · 연동 키 회전도 이 시점에 함께 하도록 짜여 있습니다.
- 백업 암호화 비밀은 서버 밖에도 보관합니다. 서버에만 있으면 서버를 잃었을 때 백업을 풀 수 없습니다.

## 7. 버전 표기와 근거

# PACS — 릴리즈 요약

> 기준 버전 **v13.48** (정본 위치: `docs/releases/v*.md 파일명(가장 높은 번호)`) · 기준 커밋 `532a8ed13e87` (2026-09-10)
> 요약 범위: `docs/releases/` 의 v11.0 ~ v13.48 중 최근 8개(v13.41 ~ v13.48 · 2026-08-03 ~ 2026-09-10) · 작성 2026-09-11
> 사실 확인: 미확인 — 생태계 자료 측 조사 기준(시스템 담당 확인 전)

## 1. 한 줄 정의와 계층

- **정의**: 영상 서버(Orthanc) · 웹 뷰어 · 판독 워크플로 · 관리 화면 · AI 연동을 갖춘 웹 PACS 입니다. 모달리티 워크리스트와 HL7 v2 오더 수신으로 검사 흐름을 잇고, 판독 서명은 sign 에 맡깁니다.
- **계층**: ③ 임상 부서 계층 — 구축 단계 S3 에서 붙입니다. 이미 쓰는 PACS 가 있으면 표준 프로토콜로 연결하는 선택도 있습니다.
- **구현 상태**: `통합`(매니페스트 기준 · 시스템 담당 확인 전)
- **규모**: API 핸들러 475 + 웹소켓 3 · 관리 화면 47 · 백엔드 테스트 선언 166 · E2E 테스트 선언 132 — `data/scale-snapshot.json` 의 `systems.pacs.counts`(2026-09-11 계측 · 센 방법은 각 항목의 `rule` · 테스트 수는 선언 수이지 통과 수가 아님)
- **웹 뷰어는 제3자 소스로 빌드합니다** — OHIF Viewer(v3.12.0 태그) 소스를 받아 패치 · 자체 확장 · 화면 설정 · 한국어 번역을 얹어 빌드하고, Cornerstone3D 는 고치지 않은 채 함께 묶습니다. 두 구성요소 모두 MIT 이며, 원 저작권 고지와 확인 상태는 [THIRD_PARTY.md §2](../../../THIRD_PARTY.md#2-소스를-가져와-고친-제3자-코드)에 있습니다. 영상 서버 Orthanc 와 그 플러그인은 GPL · AGPL 계열로, 별도 컨테이너로 씁니다([THIRD_PARTY.md §1](../../../THIRD_PARTY.md#1-별도-서비스로-쓰는-제3자-서버)).

## 2. 이 버전에서 할 수 있는 것 (도메인별)

**영상 저장 · 교환**
- DICOM DIMSE(C-STORE · C-FIND · C-MOVE · C-ECHO)와 DICOMweb(QIDO-RS · WADO-RS · STOW-RS)를 제공합니다. DICOMweb 은 토큰 게이트 뒤에 있습니다.
- 모달리티 워크리스트(MWL) · MPPS · Storage Commitment 를 제공하고, HL7 v2 MLLP 로 영상 오더(ORM)와 ADT 를 받아 워크리스트로 잇습니다.
- 주요 영상 표시(KOS), 외부 PACS 조회 · 가져오기, 업로드 센터 · 환자 업로드 포털 · 키오스크(CD/USB), 기관 간 교환용 IHE XDM 패키지 내보내기가 있습니다.
- 모달리티 구간 DICOM TLS 는 선택 구성입니다(기본 꺼짐).

**비표준 DICOM 검증 · 정규화**
- 검증 규칙과 자동 수정(원본 백업 · 되돌리기 · 이력)을 관리 화면에서 설정합니다. 들어온 영상의 출처(원내 · 외부 · 환자 · 키오스크 · 연구 등)를 분류해 판독 대기열에 표시합니다.
- 압축 파일(ZIP · CD) 해제에는 전체 · 항목별 · 개수 상한이 있고, 설정으로 조정합니다(v13.45).

**판독 워크플로**
- 워크리스트 · 판독 배정(근무표 기반 · 부하 분산) · SLA 상향 · 예비판독(전공의 → 전문의) · 재촬영 요청 · 판독문 서식 · 협진 · 응급 보드 · 위급 소견 실시간 알림 · 판독 소요 시간 통계.
- 확정 판독문의 잠금 해제 · 환자 매핑 변경 · 공유 링크 발급 · 취소 · 로그인은 감사 기록에 남습니다(v13.46).

**웹 뷰어**
- 2D 판독 · MPR · 측정 · 주석 · 행잉 프로토콜(이전 검사 비교) · 3D 볼륨 렌더링.
- 판독문 패널(작성 · 서명 · 서식)과 AI 패널을 뷰어 안에 둔 판독 모드, 판독 대기 다음 검사로 이동 · 두 번째 모니터 창.
- 병리 슬라이드(WSI) 현미경 모드와 DICOM 표준 주석(Microscopy Bulk Simple Annotations) 저장 · 표시.

**AI 보조** (AI 연산은 AI Server 가 맡습니다)
- **판독문 초안 자동 생성** — 검사가 끝나면 AI 가 예비 판독문 초안을 만듭니다. 기본 꺼짐이며, 대상 모달리티를 설정합니다. 설정 변경은 전후 값과 함께 감사 기록에 남습니다(v13.47).
- 뷰어 AI 패널 — 영상 분석 · 이전 검사 비교 · 소견 설명 초안. AI 결과를 판독문 초안으로 옮길 수 있고, 판독의가 고쳐 확정합니다.
- AI 결과를 표준 DICOM(구조화 보고 SR · 분할 SEG)으로 저장합니다.
- 영상이 들어오면 AI 가 자동으로 선별해, 조치가 필요할 수 있는 소견만 알림으로 올립니다(기본값은 6절).
- AI 거버넌스 — 모델별 성능 추세 · 판독의 수용률 · 드리프트 감지. 드리프트가 확인되면 모델을 자동으로 격리하는 기능은 기본 꺼짐입니다.

**보안 · 감사**
- 역할 기반 접근 제어. 환자 정보를 돌려주는 조회는 임상 역할 공용 정의로 묶고, 연구 역할은 뺍니다(v13.41).
- 응급 열람(Break-the-Glass)은 임상 조회에 한정하고, 관리 · 반출 · 삭제 경로는 응급 열람 세션으로 쓸 수 없습니다(v13.44).
- 감사 기록은 append-only(DB 트리거)입니다. 국제 표준 감사 메시지(IHE ATNA) 송신은 선택입니다(기본 꺼짐).
- 비식별화 엔진 · 연구 코호트 · IRB 승인 등록부.

**연동**
- HIS: 환자 매핑(MRN ↔ DICOM PatientID) · 영상 오더 동기화 · 환자 병합 재귀속 · FHIR R4 자원 래퍼 · HIS 공통 SSO(RS256 · JWKS).
- sign: 판독문 전자서명과 환자 동의서 서명. 판독 서명에는 sign 이 알려 준 키 수탁 수준을 함께 봉인하며, PACS 는 키를 갖지 않습니다.
- LIS: 병리 워크리스트 수신 · 서비스 계정의 영상 조회(환자 정보를 돌려주지 않는 도달 확인 API 포함) · 슬라이드 영상 표시.
- 환자 결과 내보내기 — 외부 포털이 일회용 게이트웨이에서 암호화 패키지(영상 + 확정 판독문)를 가져가는 방식입니다.

**운영**
- 백업 · 재해 복구 스크립트(DB 암호화 백업 · DICOM 하드링크 증분 스냅샷 · 복구 리허설).
- 모니터링(Prometheus · Grafana · Alertmanager · exporter)은 compose 프로필로 켜는 선택 구성입니다.
- 프레임 캐시와 예측 프리페치(배정 · 이전 검사 기준), 운영 BI 보고(판독 KPI · 월간 자동 보고).

**규제 표기**
- 의료기기(의료영상저장전송장치) 인허가를 목표로 한 품질 · 위험관리 · 사용적합성 · 사이버보안 · 기술 문서가 저장소에 있습니다 — `대응 설계`. 허가 · 인증을 받은 제품이 아니며 증빙 번호가 없습니다([의료 면책 고지](../../../DISCLAIMER.md)).
- 전자의무기록(EMR) 인증 기준의 보안성 · 상호운용성 항목과 PACS 구현을 대응시킨 표가 있습니다 — `대응 설계`.

## 4. 연동 변경 (릴리즈 기록상)

- **v13.41** — LIS 연동용 서비스 계정은 워크리스트 목록 · 단건을 조회할 수 없습니다. LIS 가 자기 오더의 도달 여부를 확인할 때는 환자 정보를 돌려주지 않는 도달 확인 API 를 씁니다. 릴리즈 기록은 변경 전 감사 기록에서 서비스 계정이 영상 조회(QIDO-RS)만 써 왔음을 확인했다고 적습니다.
- **v13.44** — 판독 리포트를 HIS 로 보내는 경로는 응급 열람 세션으로 쓸 수 없습니다(일반 로그인 경로는 그대로).
- **v13.48** — LIS 워크리스트 통합 테스트가 실제 연결 경로를 동적으로 찾아 검사합니다. HL7 수신 허용 대역과 호스트 방화벽 허용 대역을 같게 두도록 저장소 운영 문서에 적었습니다(6절).
- 이 연결들이 실제로 동작하는지(5단계 연동 상태)는 통합 릴리즈의 `compatibility.md` 에서 판정합니다.

## 5. 알려진 한계

저장소 문서가 스스로 밝힌 것과, 생태계 자료가 구축 기관에 미리 알리는 것입니다.

- **인허가받은 의료기기가 아닙니다.** 인허가 대응 문서가 있을 뿐이며, 임상 사용의 적합성 판단과 인허가는 구축 기관이 합니다.
- 기관 간 영상 교환(IHE XDS-I.b)과 환자 식별 교차 참조(PIX)는 모의 도메인에서 자체 검증까지 했고, 실제 도메인 연결은 외부 조건으로 남아 있습니다.
- 응급 열람 세션으로 쓸 수 있는 임상 쓰기(판독문 작성 · 판독 배정 · 협진 응답 등)는 응급 필요성을 이유로 열어 둡니다. 새 API 를 추가할 때의 기준은 "응급에 필요한 임상 행위인가, 관리 · 반출 · 삭제인가"입니다(v13.44). 기관 정책에 따라 조정할 수 있습니다.
- 전공의 역할이 판독의 권한으로 올라가, 동료의 교육 퀴즈 진도를 볼 수 있습니다. 환자 정보는 아니며 설계 판단 영역으로 기록만 돼 있습니다(v13.43).
- 웹 뷰어 빌드 산출물에 묶이는 npm 패키지의 고지 목록은 아직 없습니다. Orthanc 이미지의 코어 · 플러그인 판본도 확인이 남아 있습니다([THIRD_PARTY.md](../../../THIRD_PARTY.md)).
- 코드에 버전 선언이 없어, 실행 중인 서비스에서 릴리즈 번호를 읽을 수 없습니다(7절).

## 6. 설치 · 업그레이드 시 주의

- **구성** — Orthanc · PostgreSQL · Redis · 백엔드 API · 비동기 작업자(Celery worker · beat) · MWL/MPPS 서버 · HL7 수신기 · 관리 화면 · 웹 뷰어 · nginx(유일한 공개 진입점)를 compose 로 올립니다. 모니터링은 프로필로 켭니다.
- **웹 뷰어는 먼저 빌드합니다** — 저장소의 빌드 스크립트가 OHIF 소스를 받아 패치 · 확장 · 번역을 얹고 정적 파일을 만듭니다. 뷰어를 다시 빌드하거나 다른 기관에 배포하면 [THIRD_PARTY.md §2](../../../THIRD_PARTY.md#2-소스를-가져와-고친-제3자-코드)의 고지 조건을 확인합니다.
- **AI 기본값을 확인합니다**(2026-09-11 코드 확인) — 판독문 자동 초안과 드리프트 자동 격리는 기본 꺼짐입니다. **영상 자동 선별은 코드 기본값이 켜짐입니다.** 생태계 원칙("AI 기능은 기관 결정으로 켬")에 맞추려면 설치할 때 끄고, 기관 결정 뒤에 켭니다.
- **설치본 주소를 바꿉니다** — 코드 기본값 가운데 특정 설치본의 주소가 들어 있는 설정(프레임 캐시 예열 기본 주소 등)이 있습니다(2026-09-11 코드 확인). 자기 기관 주소나 내부 주소로 설정합니다.
- **앞단 프록시를 한 단 더 두는 경우** — 앞에 다른 역방향 프록시가 있으면 nginx 가 보는 접속 주소가 모두 프록시 주소가 됩니다. 이때 접속 주소(IP)에 기댄 접근 규칙은 뜻대로 동작하지 않으므로, 공개 경로는 토큰 인증으로 지킵니다(저장소 운영 문서).
- **HL7 수신 허용 대역** — 앱의 허용 대역 설정과 호스트 방화벽 허용 대역을 함께 맞춥니다. 한쪽만 바꾸면 연결이 조용히 끊깁니다. 통합 테스트 스크립트로 확인합니다.
- **선택 기능** — IHE ATNA 감사 송신 · 모달리티 구간 DICOM TLS 는 기본 꺼짐입니다. 필요하면 설정합니다.
- **백업** — 오프사이트 대상은 설정해야 켜집니다. 암호화 백업의 패스프레이즈는 서버 밖에도 보관합니다. 서버에만 있으면 서버를 잃었을 때 백업을 풀 수 없습니다.
- **코드를 바꿔 배포할 때** — 비동기 작업자는 코드가 이미지에 들어가므로 작업자 코드가 바뀌면 이미지를 다시 빌드합니다(저장소 운영 문서).

  - 코드에 버전 선언이 없어, 릴리즈 기록 파일명의 가장 높은 번호(v13.48)를 정본으로 씁니다. 이 번호와 같은 이름의 태그는 없습니다.
  - 저장소의 마지막 태그는 v11.2 입니다. 태그가 v11.2 에서 멈춘 뒤의 릴리즈는 기록 파일로만 남아 있습니다.
  - 관리 화면 패키지(`admin/package.json`)는 2.0.0 으로, 릴리즈 번호와 다른 체계입니다.
  - 백엔드 API 문서가 내보내는 버전도 2.0.0 입니다(매니페스트 등급 `표면` 항목 · 스냅샷에 포함). README 배지는 v13.24 입니다(스냅샷 비교 대상 밖).

## 8. 새 설치본으로 세워 본 결과 (2026-09-13~16)

기준 커밋을 풀어 **새 설치본**을 세우고, 다른 새 설치본과만 호출해 봤습니다(개발 PC 한 대 · arm64 · GPU 없음 · 외부로 나가지 못하는 네트워크 · 가상 병원 데이터). **기준 장비가 아닙니다** — 처리량 · 응답 시간 · AI 품질은 이 결과로 판단하지 않습니다.

- 설치 스크립트를 **네 번** 돌려 끝냈습니다. 영상 서버 이미지 태그를 받을 수 없었고, TLS 파일 · 헬스체크 · 기본 테이블 생성 단계에서 차례로 멈췄습니다. 우회한 순서는 [S3](../../../build-guide/S3-clinical-departments.md)에 적었습니다.
- PACS 가 한쪽 끝인 연결 가운데 **4개**를 실제로 호출해 `검증됨` 을 붙였습니다(2026-09-15) — LIS 병리 워크리스트 · 뷰어 링크, sign 판독 서명 · 조영제 동의서 환자 서명.
- 🔴 **HIS 화면에서 PACS 를 부르는 경로**(영상 조회 · 판독 작성 · 판독 서명 · 영상 바이트 중계 · 뷰어 진입)는 **완료를 확인하지 못했습니다** — 코드 수정이나 프로젝트 사이 협의가 필요합니다.
- 무엇을 어떻게 확인했고 무엇이 남았는지는 [따라가 본 결과](../../../build-guide/follow-along-2026-09.md)에 있습니다.

# 전제와 파급 — 무엇이 먼저이고, 못 쓰면 무엇이 멈추나

**Preconditions and knock-on effects**

> **EN** — Two questions the system briefs answer only indirectly: *what has to exist before this feature works*, and *what stops if it does not*. This page pairs them. Preconditions are drawn from the build guide, the opening gates and the connection cards; the fallbacks are drawn from section 10 of each system brief, which already names an alternative for every limitation. 🔴 Where a feature is not implemented or discontinued, an alternative is always given — a limitation without an alternative is not an answer.

> 🟡 **초안** · 상태의 정본은 [연결 상태 표](../RELEASES/2026.09/compatibility.md)입니다. 여기서는 상태를 옮겨 적지 않고 **관계만** 적습니다.
> 쌍 단위의 「여는 순서」는 [연결 카드 48장](../integration/cards/)에 있습니다. 이 문서는 **기능 단위**입니다.

## 왜 이 문서가 있나

기관이 「이것만 먼저 켜고 싶다」고 할 때 답할 자리가 없었습니다. 구성서는 기능을 **시스템별로** 적고, 연결 표는 **시스템 사이**를 적습니다. **기능 하나를 켜려면 무엇이 먼저인지**는 흩어져 있었습니다.

---

## 1. 무엇보다 먼저 — 이것이 없으면 여러 기능이 동시에 막힙니다

| 전제 | 없으면 멈추는 것 | 어떻게 |
|---|---|---|
| **직원 신원(HIS 토큰)** | 형제 시스템 **전부**의 로그인 · 연동 | HIS 가 신원 허브입니다. 공개키 검증 5곳 · 공유 비밀 2곳 · API 키 1곳 → [신원 허브](../diagrams/identity-hub.md) |
| **코드 마스터**(검사 · 약가 · 수가 · 상병) | 검사 흐름 · 처방 점검 · 청구 산정 | 🔴 저장소에 들어 있지 않습니다. **기관이 배포처에서 받아 반입**합니다 → [S0](../build-guide/S0-prepare.md) · [THIRD_PARTY](../THIRD_PARTY.md) |
| **검사코드 매핑** | 검사 오더 · 결과 회신 | [반입과 매핑](detail/lab-code-catalog.md) — 따라가기에서 **시드 15 중 매핑 3** 이었습니다 |
| **PDF 렌더 서비스** | 동의서 · 계약 등 **서명 요청 전체** | 🔴 문서를 만들지 못하면 서명 요청 자체가 실패합니다 → [동의서 전자서명](detail/consent-signature.md) |
| **AI 목적지 허용 목록** | AI 기능 전부 | 비어 있으면 호출이 경계에서 막힙니다 → [S6](../build-guide/S6-ai.md) |
| **조직 결재(개통 게이트)** | 게이트가 걸린 연결 | 스위치가 아니라 결재입니다 → [연동 개통 게이트](detail/integration-gate.md) |

## 2. 기능별 전제

| 기능 | 먼저 있어야 하는 것 |
|---|---|
| 검사 결과가 차트에 붙는다 | HIS↔LIS 연결 · **검사코드 매핑** · 결과 검증 절차(입력자≠검증자) |
| 위험치가 닫힌다 | 위험치 기준 설정 · 통보 대상(당직·담당) · **복창을 기록할 사람** |
| 수혈이 나간다 | 혈액형·항체 결과 · 교차시험 · 🔴 **동의 상태 확인** · 2인 확인 체계 |
| 영상이 찍힌다 | PACS 서비스 계정(워크리스트 쓰기 권한) · 장비 AE 타이틀 등록 · 촬영망 |
| 판독이 서명된다 | 판독의 인증서 · sign 소비자 등록 |
| 동의서를 받는다 | sign 소비자 · **PDF 렌더** · 서명 채널 · 본인확인 수단 |
| 약물 점검이 돈다 | DUR·약가 데이터 반입 · AI 서버(보조 기능을 쓸 때) |
| 청구가 산정된다 | 수가·재료 코드 · HIS↔ERP 연결 · 수납 항목 |
| 직원이 교육을 듣는다 | HIS↔edu 진입(주소 등록 · 공개키) · 직원 명부 동기화 |
| AI 초안이 만들어진다 | AI 서버 · 모델 · 목적지 허용 목록 · **기관의 켜기 결정** |

## 3. 파급 — 못 쓰면 무엇이 멈추고, 무엇으로 대신하나

🔴 **한계에는 반드시 대체 수단이 붙습니다.** 대체 없는 한계는 답이 아닙니다.

| 못 쓰는 것 | 멈추는 것 | 대신 |
|---|---|---|
| **대외 기관 전송**(청구 · 자격조회 · 법정 보고) | 전자 제출 | 🔴 **기존 청구 소프트웨어 · 기존 신고 경로**를 쓰고 그 사실을 기관 문서에 남깁니다. 청구서 작성까지는 됩니다 |
| **검사 장비 자동 수집** | 결과 자동 입력 | 장비-LIS 사이에 **중계**를 두거나, 결과 파일 · 수기 입력으로 운영합니다 |
| **문자 발송 제공자** | 환자 본인확인 문자 | 🔴 지금은 **모의 발송**입니다. 제공자를 연동·계약해 붙입니다 |
| **원격 화상(Jitsi)** | 화상 진료 · 녹화 | 🔴 현재 설치본이 `중단` 입니다. 새로 구성하거나 대면·전화로 대신합니다 |
| **HIS 화면에서 영상 열기** | 차트에서 영상·판독 | **PACS 화면에서 직접** 합니다. 판독 서명은 확인된 경로를 씁니다 |
| **반사 검사 자동 추가** | 자동 추가검사 | **사람이 추가 처방**합니다 |
| **수혈 동의 자동 확인** | 자동 확인 | **사람이 확인**합니다 — 확인되지 않으면 출고가 자동 통과되지 않으므로 안전 쪽으로 닫힙니다 |
| **판독 결과 HL7 송신 · 환자 인구정보 ADT** | 표준 메시지 연동 | 이 생태계 안에서는 다른 경로를 씁니다. **다른 HIS 와 붙이려면 송신부를 추가**해야 합니다 |
| **AI 서버 가용성 감시** | 자동 감시 | AI Server 쪽 감시·모니터링으로 대신 봅니다 |
| **AI 서버가 멈춤** | AI 보조 전부 | 화면이 「폴백」 또는 「산출 불가」로 적습니다 — **빈칸으로 두지 않습니다** |
| **HL7 v2 대체 경로**(HIS↔LIS) | 이중화 | FHIR 주 경로를 쓰고, 다운타임에는 **다운타임 오더 절차** |

## 4. 이 표를 쓰는 법

1. 켜고 싶은 기능을 §2 에서 찾아 **전제를 먼저** 채웁니다.
2. 전제 중 못 채우는 것이 있으면 §3 에서 **대신할 것**을 정하고 기관 문서에 남깁니다.
3. 연결을 실제로 여는 순서는 [연결 카드](../integration/cards/)의 「여는 순서」를 따릅니다.
4. 🔴 **개시 전에** — 대체 수단으로 운영하기로 한 것은 [체크리스트](../checklist/)에 남겨, 나중에 「왜 이렇게 하고 있나」를 되짚을 수 있게 합니다.

## 5. 이 문서의 한계

- 🔴 **기능 단위 전제를 전부 적지 못했습니다.** 지금은 자주 걸리는 것과 [자세히 쓴 11편](detail/)에 해당하는 것까지입니다.
- 상태는 여기서 말하지 않습니다 — [연결 상태 표](../RELEASES/2026.09/compatibility.md)와 각 구성서 §7 · §10 이 정본입니다.

# 재활 — 평가해 둔 것을 치료 시작 전에 다시 본다

**Rehabilitation — what was assessed is looked at again before a session starts**

> **EN** — The rehabilitation module keeps three records: functional assessments (Barthel, FIM, Berg balance and others), treatment plans with a frequency, and individual therapy sessions. Its one safety feature is a **session-start gate** that compares the latest Berg score and the most recent vital signs against hold thresholds; it was added because assessment results used to be **stored but never used** when treatment actually began. The gate ships **off**; in block mode a session can still be started with an override, and the person and reason (or "reason not entered") are kept with the session. Missing vital signs are reported as "cannot judge", not as normal — but a **missing Berg score produces no fall-risk line at all**, and the base-commit screens do not send an override, so block mode can only be used from outside those screens. Therapy-type names exist in two vocabularies (billing map vs. therapy-room tabs), and the billing code written on a completed session is **not turned into a charge by any code we found**. Sits on judgment rules ① honesty, ② single source of truth, ④ gates and ⑥ human decision.

## 1. 무엇을 하나

재활의학의 **평가 · 계획 · 세션**을 기록합니다.

| 기록 | 무엇이 남나 |
|---|---|
| 재활 평가 | 진단 · 발병일 · **Barthel · FIM · Berg · MMSE · VAS** · 도수근력(MMT) · 관절가동범위(ROM) · 보행 · 삼킴 · 목표 · 평가자 |
| 치료 계획 | 진단 · 기간 · **빈도**(「주3회」 같은 글) · 치료 목록 · 처방의 · 상태 |
| 치료 세션 | 치료 유형 · 치료사 · 예정 시각 · 시작/종료 · 활동 · 활력 · 경과 · **시행 전 안전 판정** · 수가 코드 |

그 위에 **환자별 경과 추이**(Barthel · FIM · Berg · MMSE · VAS 시간순) · 오늘의 대시보드 · 통계가 붙습니다. 치료 계획은 표준 형식(FHIR CarePlan)으로도 내보냅니다.

🔴 **이 모듈이 기능 평가를 남기는 유일한 자리는 아닙니다.** 재활의학과 진료 기록(SOAP 과 기능 평가 묶음)은 **별도 저장소**에 쌓이고, 경과 추이와 안전 판정은 **이 모듈의 평가만** 읽습니다(§4).

## 2. 어떻게 도나

### ① 평가 · 계획 — 적는 대로 남긴다

평가와 계획은 입력한 대로 저장합니다. 평가 목록은 최근순 **100건**까지 보입니다. 🔴 점수의 범위(예: Berg 0~56)를 서버가 검사하는 코드는 찾지 못했습니다 — 숫자면 받습니다.

### ② 세션 만들기 — 계획의 빈도를 요일로 펼친다

세션은 하나씩 예약하거나, **계획에서 몇 주치를 한꺼번에** 만듭니다.

| 규칙 | 기준 커밋 동작 |
|---|---|
| 대상 계획 | **진행 중**인 계획만 |
| 빈도 해석 | 글에서 **숫자 하나**를 읽습니다. 「매일」은 7 |
| 요일 | 🔴 **2 · 3 · 5 · 7회만** 요일표가 있습니다(화목 · 월수금 · 평일 · 매일). 그 밖의 수(1 · 4 · 6회)는 **월수금**으로 만들어집니다 |
| 치료 유형 | 계획의 **첫 번째 치료**만 씁니다 |
| 시각 | 모두 **09:00** |
| 치료사 | 🔴 지정하지 않으면 **만들어지지 않습니다**(세션에는 치료사가 필수) |
| 중복 | 같은 기간을 두 번 만들면 **두 벌**이 됩니다 — 막는 코드는 찾지 못했습니다 |

### ③ 🔴 세션 시작 — 안전 판정

시작 요청이 오면 게이트 모드에 따라 **최신 재활 평가의 Berg**와 **최근 활력징후**를 대조합니다.

| 항목 | 판정 | 기준(기본값) |
|---|---|---|
| 낙상 고위험 | 보류 | Berg **21 미만** |
| 낙상 중위험 | 경고 | Berg 21~**40** |
| 활력 중단 기준 | 보류 | 수축기 **>180 / <90** · 맥박 **>120 / <50** · 산소포화도 **<90** · 체온 **≥38** |
| 🔴 최근 활력징후 없음 | **「판정 불가」 안내** | 조회 창 **72시간** |
| 🔴 Berg 기록 없음 | **아무 줄도 남기지 않습니다** | — |

| 모드 | 동작 |
|---|---|
| 끔(**기본**) | 판정하지 않습니다. 세션에 판정 기록도 남지 않습니다 |
| 경고 | 판정하고 **세션에 판정 내역을 남긴 채** 시작합니다 |
| 차단 | 보류 항목이 있으면 **시작을 거절**합니다. 우회 값을 싣고 다시 요청하면 시작하고, **우회한 사람과 사유**를 세션에 남깁니다 — 🔴 사유가 없으면 **「사유 미입력」**으로 적습니다 |

기준값은 설정 한 곳(`rehab.holdCriteria`)에서 고치고, 그 설정은 **위원회 개정 표면**으로 등록돼 있습니다([위원회 의결](governance-enactment.md)). 형식이 맞지 않는 값은 무시하고 **코드의 기본값으로** 판정합니다. 게이트의 모드와 30일 집계는 [안전 게이트](safety-gates.md) 관제에 나옵니다.

### ④ 세션 완료 — 수가 코드를 적는다

완료하면 활동 · 활력 · 경과 · 시간을 남기고, **치료 유형 → 수가 코드**를 붙입니다.

| 치료 유형(이름) | 수가 코드 |
|---|---|
| `PT` · `GAIT` · `HEAT` · `운동치료` | 물리치료 |
| `OT` | 작업치료 |
| `ST` | 언어치료 |
| 🔴 **표에 없는 이름** | **물리치료 코드로** 붙습니다 |

### ⑤ 화면 — 세 곳

| 화면 | 무엇을 보나 |
|---|---|
| 재활의학 | 계획 · 일정 · 평가 탭. 시작 · 완료 단추 |
| 치료실 워크스테이션의 물리 · 작업 · 언어 탭 | 오늘 세션을 **치료 유형 이름으로 걸러** 보입니다 — 거르는 이름은 `운동치료 · 도수치료 · 작업치료 · 언어치료 · 삼킴` 같은 **한국어 이름**입니다 |
| 재활 워크스테이션 | 🔴 기준 커밋에서 **업무 목록이 연결되지 않았고**, 화면이 그렇게 말합니다([HIS 화면 — 워크스테이션](../../screens/his.md#워크스테이션-28개--연결된-것-연결되지-않은-것-설정이-어긋난-것)) |

## 3. 🔴 왜 그렇게 만들었나

- 🔴 **시작 전 판정이 생긴 이유.** 코드 주석이 이 게이트를 **「평가 결과는 저장만 되고 시행에 쓰이지 않던 빈틈」**을 메우려고 만들었다고 적습니다. Berg 를 재 놓고도 낙상 고위험 환자의 보행 치료가 **아무 확인 없이** 시작될 수 있었습니다. 저장한 평가를 **실제로 쓰는 자리**가 생긴 것입니다(판정 규칙 ②).
- **활력이 없을 때 「판정 불가」를 남기는 이유.** 없는 측정을 정상으로 접으면 **판정한 척**이 됩니다. 72시간 안의 측정이 없으면 「측정을 권장 · 판정 불가」로 남깁니다(판정 규칙 ①).
- **차단 모드에서도 우회를 허용하는 이유.** 보류 기준은 **중단을 권하는 선**이지, 모든 상황에서 치료를 금하는 선이 아닙니다. 대신 **누가 · 왜** 넘었는지를 세션에 붙입니다 — 사유를 비우면 비웠다고 적고, 그럴듯한 사유를 지어 넣지 않습니다([투약](medication-administration.md)과 같은 태도).
- **기준을 설정 한 곳에 두고 위원회 표면으로 등록한 이유.** 수치 임계는 기관이 정할 값이고, 바꾸는 순간 **누가 정했는지**가 남아야 합니다([위원회 의결](governance-enactment.md) · 판정 규칙 ⑥).
- **형식이 틀린 기준값을 무시하는 이유.** 숫자가 아닌 값이 들어가 임계가 사라지면 **게이트가 조용히 열립니다.** 무시하고 코드 기본값으로 판정하는 것이 안전한 쪽입니다(주석의 표현은 「폴백 fail-safe」).
- **평가 목록 조회가 따로 생긴 이유.** 한때 화면이 부르는 목록 경로가 서버에 없어 404 가 났고, 화면이 그 실패를 삼켜 **평가 3건이 있는데 「평가 기록 없음」**이라고 말했습니다(판정 규칙 ①).
- **치료사 전용 역할이 없는 이유.** 치료실 화면 주석이 「운영 실측상 재활 실무자는 전원 간호사 역할」이라고 적습니다. 역할을 새로 두지 않고 그 운영을 따른 것입니다.
- 🔴 **찾지 못한 것**
  - 보류 기준의 수치(Berg 21 · 40 · 수축기 180/90 · 맥박 120/50 · 산소포화도 90 · 체온 38 · **72시간** 창)가 **어느 지침에서 왔는지**는 기록에서 찾지 못했습니다
  - **게이트 기본이 꺼짐인 이유**
  - 빈도 요일표가 **2 · 3 · 5 · 7회만** 있는 이유와, **표에 없는 치료 유형을 물리치료 코드로** 붙이는 이유
  - 🔴 **기관이 관할 규정과 자기 프로토콜로 다시 확인해야 하는 값**입니다

## 4. 🔴 무엇을 막나

- **평가를 저장만 하고 치료 시작에 쓰지 않는 것** — 게이트를 켜면 시작 순간에 대조합니다
- **없는 활력을 정상으로 읽는 것** — 「판정 불가」로 남깁니다
- **우회한 사실이 사라지는 것** — 사람과 사유(또는 「사유 미입력」)를 세션에 붙입니다
- **형식이 틀린 기준값이 게이트를 여는 것** — 무시하고 기본값으로 판정합니다
- **진행 중이 아닌 계획에서 세션을 찍어 내는 것** — 거절합니다
- **막지 못하는 것**
  - 🔴 **게이트 기본은 꺼짐**입니다 — 켜기 전까지는 판정도, 판정 기록도 없습니다
  - 🔴 **Berg 가 없으면 낙상 항목은 아무 표시도 없습니다.** 활력이 없을 때 「판정 불가」를 남기는 것과 **다릅니다** — 평가를 하지 않은 환자는 낙상 위험이 없는 환자처럼 지나갑니다
  - 🔴 **기준 커밋의 두 화면은 시작 요청에 우회 값을 싣지 않습니다.** 차단 모드를 켜면 보류 환자에게는 화면에 **「치료 시작 실패」만** 뜨고, 보류 사유와 우회 입력란이 나오지 않습니다 — 켜기 전에 화면을 확인해야 합니다
  - 🔴 **기능 평가가 두 곳에 남습니다.** 재활의학과 진료 기록의 기능 평가(Barthel · FIM 등)는 **경과 추이에도, 안전 판정에도 들어가지 않습니다** — 어느 쪽을 정본으로 쓸지는 기관이 정합니다
  - 🔴 **치료 유형 이름이 두 벌입니다.** 수가 매핑은 `PT · OT · ST` 같은 약어를, 치료실 화면 탭은 `작업치료 · 언어치료` 같은 한국어 이름을 봅니다. 그래서 `작업치료`로 적은 세션은 **물리치료 코드**가 붙고, `OT`로 적은 세션은 치료실의 작업치료 탭에 **나오지 않습니다** — 🔴 **기관이 쓸 이름을 한 벌로 정해야 합니다**
  - 🔴 **세션에 적힌 수가 코드를 청구 항목으로 올리는 코드는 찾지 못했습니다** — 기록으로 남을 뿐입니다. 재활 치료의 청구는 처방 · 오더 경로로 확인합니다
  - 빈도 1 · 4 · 6회는 월수금으로 펼쳐지고, 같은 기간을 두 번 만들면 두 벌이 됩니다
  - 🔴 **이 모듈은 치료의 적응 · 강도 · 금기를 판정하지 않습니다** — 처방은 의사가, 시행 판단은 치료사가 합니다

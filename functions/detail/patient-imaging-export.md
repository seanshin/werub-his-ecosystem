# 환자에게 자기 영상을 주는 길 — 환자의 브라우저는 영상 시스템에 닿지 않는다

**Giving patients their own images — the patient's browser never reaches the imaging system**

> **EN** — There are two paths, and neither lets a patient's browser touch the imaging system directly. The portal verifies the person, then asks server-to-server; the imaging system packages the archive with the **final** report only, encrypts it, and hands back a one-time link — while the decryption key travels on a different channel, so a leaked link cannot open the package. The feature ships **off by default**, and when off it answers with a distinct "disabled" status that is not confused with an auth failure. Nothing is anonymized here on purpose: this is the patient's own record. There is no path that writes a CD or USB — media can only be read in. Wired in code but **not verified by real calls**.

## 1. 무엇을 하나

환자가 「내 영상을 주세요」라고 할 때 쓰는 길입니다. 두 가지가 있고, **성격이 다릅니다.**

| 길 | 무엇을 주나 | 누가 여나 |
|---|---|---|
| **① 결과 내보내기** | 영상 원본 + **확정 판독문** 묶음 파일 | 환자 포털이 **서버 대 서버**로 요청 |
| **② 결과 열람** | 검사 목록 · 확정 판독문 · **대표 이미지 한 장** — 내려받기 없음 | 직원이 발급한 링크로 환자가 봄 |

🔴 **둘 다 환자의 브라우저가 영상 시스템에 직접 닿지 않습니다.** 병원 안쪽 망이 밖으로 여는 문은 **파일을 건네주는 한 경로뿐**입니다.

## 2. 어떻게 도나

### ① 결과 내보내기 — 본인 확인은 포털이, 봉인은 영상 시스템이

| 단계 | 무엇이 일어나나 |
|---|---|
| 본인 확인 | 🔴 **영상 시스템이 하지 않습니다.** 환자 포털이 확인하고, **그 결과를 환자번호로 봉인한 토큰**에 담아 보냅니다 |
| 요청 | 포털이 서버 대 서버로 요청합니다. 🔴 **토큰에 봉인된 환자번호와 요청한 환자번호가 다르면 거부**합니다 |
| 포장 | 그 환자의 영상과 **확정 판독문**을 묶고 **암호화**합니다 |
| 전달 | 포털이 **1회용 링크**로 받아 갑니다 — **두 번째 요청은 거부**됩니다 |
| 🔴 열쇠 | **복호 열쇠는 다른 경로로** 갑니다(인증된 상태 조회 쪽). 링크가 새어도 **내용은 열리지 않습니다** |
| 지움 | 묶음 파일은 **24시간 뒤 지워지고**, 링크와 열쇠는 **1시간**만 삽니다. 지운 사실도 기록에 남습니다 |

### ② 결과 열람 — 보여 주기만

직원(관리자)이 링크를 발급하고, 환자가 그 링크로 **검사 목록 · 확정 판독문 · 대표 이미지 한 장**을 봅니다. **원본을 내려받는 자리는 없습니다.**
링크는 만료되고, 회수할 수 있으며, **몇 번 썼는지 셉니다.** 저장소에는 링크 자체가 아니라 **그 지문만** 둡니다.

### 무엇이 묶음에 들어가지 않나

- 🔴 **아직 확정되지 않은 판독문은 들어가지 않습니다** — 두 길 모두 **확정본만** 냅니다.
- **비식별화는 하지 않습니다.** 🔵 **일부러 그렇습니다** — 이것은 **환자 본인의 기록**이라 가릴 것이 없습니다. (가려서 내보내는 길은 **연구·교육용으로 따로** 있고, 그쪽은 아예 다른 경로입니다.)

### 🔴 CD · USB 로 구워 주는 길은 없다

매체 관련 코드는 **받아 들이는 쪽에만** 있습니다. 밖에서 들어온 CD 를 읽어 들이는 길은 있지만, **환자에게 구워 주는 길은 기준 커밋에 없습니다.** 기관이 매체 제공을 해야 한다면 **따로 마련해야 합니다.**

## 3. 🔴 왜 그렇게 만들었나

- **PHI 를 꺼내는 기능은 꺼진 채로 나온다.** 이 기능은 **기본이 꺼짐**입니다. 코드가 그 이유를 적어 두었습니다 — **「이 끝점은 환자정보를 꺼내고, 공유 비밀만큼만 안전하다」.** 실제로 한동안 **설치 예시의 자리표시 비밀 그대로** 열려 있었고, 그 값을 아는 누구든 토큰을 위조할 수 있었습니다. 그 일을 겪고 **기본을 꺼짐으로 되돌렸습니다**(판정 규칙 ⑥ — 발신은 구현 + 설정(기본 꺼짐) + 승인).
- **꺼짐과 거부를 구별한다.** 🔵 **인증 검사가 스위치보다 먼저** 돕니다 — 그래서 「권한이 없다」와 「기능이 꺼져 있다」가 **다른 응답**으로 옵니다. 설치하는 쪽이 무엇이 문제인지 알 수 있습니다(판정 규칙 ①).
- **열쇠와 짐을 같은 길로 보내지 않는다.** 링크가 새는 것과 내용이 열리는 것을 **분리**했습니다.
- **비밀을 따로 둔다.** 이 기능의 서명 비밀을 신원 시스템의 것과 **분리**해서, 한쪽 키를 바꿔도 다른 쪽이 흔들리지 않게 했습니다. 🔴 **둘 다 비어 있으면 아예 거부**합니다(모르면 열지 않는다).
- **반출 기록이 비는 것은 규제 위험이다.** 그래서 기록 남기기가 실패하면 **경고가 아니라 오류로** 드러냅니다. 요청 · 준비됨 · 받아감 · 만료 **네 시점 모두** 남습니다.
- **다른 사람 것이 섞이지 않게 한다.** 요청자가 검사 번호를 지정해도, **그 환자의 것으로 먼저 추린 뒤 교집합**만 담습니다 — 남의 번호를 끼워 넣어도 들어가지 않습니다(판정 규칙 ⑤).
- **겪은 함정을 지우지 않고 적어 두었다.** 상태 값이 비어 있으면 조회가 **영원히 끝나지 않던 것**, 저장된 판독문 상태의 대소문자가 달라 **추출이 실패하던 것**이 주석과 릴리즈 기록에 그대로 남아 있습니다.

## 4. 🔴 무엇을 막나

- **환자 브라우저가 병원 안쪽 망에 닿는 것** — 문은 파일 건네주기 한 경로뿐입니다
- **다른 환자의 영상이 섞이는 것** — 환자번호 봉인 + 교집합 + 조회 때 재확인
- **링크 하나로 내용까지 열리는 것** — 열쇠는 다른 길로 갑니다
- **같은 링크의 재사용** — 1회용이고, 두 번째는 거부됩니다
- **확정 전 판독문이 환자에게 가는 것** — 확정본만 담깁니다
- **비밀이 비어 있는데 도는 것** — 비어 있으면 거부합니다
- **반출 사실이 남지 않는 것** — 네 시점이 기록되고, 기록 실패는 오류로 드러납니다
- **긴급 열람 권한으로 반출하는 것** — 직원용 반출 경로는 긴급 열람 세션을 **받지 않습니다**

## 5. 🔴 기관이 알아야 할 것

| 무엇 | 지금 상태 |
|---|---|
| **기본 꺼짐** | 켜기 전에 **전용 비밀을 제대로 넣어야** 합니다. 예시 값 그대로 켜면 안 됩니다 |
| **본인 확인 책임** | 🔴 **영상 시스템이 아니라 포털에 있습니다.** 포털을 세우지 않으면 이 길은 쓸 수 없습니다 |
| **열람 링크의 본인 확인** | 🔴 링크를 가진 사람이 봅니다 — 생년월일 같은 2차 확인은 **필요하면 기관이 붙입니다** |
| **매체(CD·USB) 제공** | 🔴 **경로 없음** — 기관이 따로 마련합니다 |
| **받아 간 뒤의 보관** | 🔵 포털 쪽 책임입니다. 영상 시스템은 **다시 만들어 줄 수만** 있습니다 |
| **자동 시험의 범위** | 🔴 **정상 흐름 시험은 기능이 꺼진 기본 환경에서 건너뜁니다.** 거부 경로(봉인 불일치 · 무인증 · 무효 링크)는 항상 돕니다 — **초록이 정상 흐름까지 덮는다는 뜻은 아닙니다** |

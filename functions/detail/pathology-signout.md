# 병리 2단계 사인아웃 — 확정된 진단문은 조용히 바뀌지 않는다

**Pathology two-step sign-out — a signed diagnosis is never quietly replaced**

> **EN** — A pathology report is written as a draft first and becomes final only when a pathologist signs it, and the signer is derived from the logged-in account, never accepted from the request body. Once signed, the report cannot be overwritten, re-signed or pushed back to draft: the only ways forward are a versioned amendment with a mandatory reason, or an addendum that leaves the diagnosis untouched. Amending a report that was already delivered re-opens the notification loop, because the requesting clinician may still be treating on the previous diagnosis. Two things the institution must decide itself: the system does **not** force the drafter and the signer to be different people, and there is **no history table**, so an amendment replaces the previous text. Wired in code but not verified by real calls, except the two links to the imaging system, which are **verified**.

## 1. 무엇을 하나

병리 진단은 **되돌릴 수 없는 결정**의 근거입니다. 「악성」 한 줄이 수술 범위를 정하고, 「양성」 한 줄이 추적을 멈춥니다. 그래서 이 흐름은 **쓰는 일과 확정하는 일을 갈라 놓습니다.**

| 단계 | 무엇 | 확정인가 |
|---|---|---|
| **초안** | 소견 · 진단을 먼저 적어 둡니다 | 아니오 — **검사번호(Accession)를 주지 않습니다** |
| **최종** | 판독의가 서명합니다 | 예 — 법적 확정 |
| **개정** | 확정된 진단을 고칩니다 | 예 — **판 번호가 오르고 사유가 남습니다** |
| **추가보고** | 진단은 그대로 두고 덧붙입니다(예: 면역염색 결과) | 진단문은 불변 |

표본이 들어와 **육안소견 → 블록 → 슬라이드 → 보고서**로 이어지는 동안, 블록과 슬라이드에는 각각 바코드가 붙고 **누가 언제 어디서 찍었는지**가 한 줄씩 쌓입니다(custody).

## 2. 어떻게 도나

### 서명자는 요청이 정하지 않는다

🔴 **서명자를 본문으로 받지 않습니다.** 로그인한 계정에 연결된 판독의를 **서버가 유도**해서 씁니다. 계정에 판독의가 연결돼 있지 않으면 **서명 자체가 막힙니다**(관리자가 먼저 연결해야 합니다).

### 확정 뒤에는 한 방향으로만

| 하려는 것 | 결과 |
|---|---|
| 서명된 보고서를 **다시 서명** | 🔴 거부 — 「개정으로 하십시오」 |
| 서명된 보고서에 **초안 저장** | 🔴 거부 — 확정 진단문이 지워지고 미서명으로 되돌아가는 것을 막습니다 |
| **개정** | 판 번호 +1 · **사유 필수** · 동시에 두 개정이 오면 뒤엣것 거부 |
| **추가보고** | 진단 · 상태는 그대로, 순번을 새로 받아 덧붙임 |

### 개정하면 임상의에게 다시 알린다

🔴 **이미 배포된 보고서를 고치면 재통보가 자동으로 나갑니다.** 의뢰한 의사가 **이전 진단으로 계속 진료하고 있을 수 있기** 때문입니다(예: 양성 → 침윤성 암). 배포되지 않은 건은 통보하지 않습니다.

### 암 보고에는 필수 항목 게이트

프로토콜을 지정한 암 케이스는 **필수 항목이 비어 있으면 서명이 막힙니다.**

### 영상(디지털 슬라이드)과의 연결

병리 검사가 접수되면 **영상 시스템의 작업목록에 슬라이드 스캔 건으로 등록**되고, 스캔이 끝나면 슬라이드에 영상 참조가 붙습니다. 판독의는 **뷰어 링크**로 그 슬라이드를 엽니다.
🔵 이 두 가지는 **새 설치본에서 실제로 불러 확인했습니다**([따라가 본 결과](../../build-guide/follow-along-2026-09.md)).

## 3. 🔴 왜 그렇게 만들었나

**전부 한 번 틀렸다가 고친 자리입니다.** 그쪽 코드 주석과 변경 기록이 무엇이 잘못이었는지를 지우지 않고 적어 두었습니다.

- **확정 진단문이 이력 없이 교체되던 경로가 넷이었다.** 더블클릭 · 시간초과 뒤 재시도 · 다른 판독의의 서명 · 전공의의 초안 저장 — 어느 쪽으로도 **법적 확정 진단문이 조용히 바뀌었고**, 이력 테이블이 없어 되돌릴 수 없었습니다. 그래서 서명본은 **개정으로만** 고치게 막고, 전이를 원자적으로 바꿨습니다(판정 규칙 ②·③).
- **서명자가 자유 문자열이었다.** 요청 본문에 이름을 적어 보내면 그대로 서명자가 됐습니다 — **다른 판독의 명의의 최종 진단**을 만들 수 있었다는 뜻이고, 그러면 부인방지가 성립하지 않습니다. 지금은 서버가 계정에서 유도하고, 연결이 없으면 서명을 막습니다(판정 규칙 ⑤).
- **초안 단계가 화면에 없어서 초안이 곧 서명이 됐다.** 전공의가 서명 단추를 누르거나, 아예 **시스템 밖(구두 · 메모)** 에서 초안이 오갔습니다. 초안을 별도 단계로 만들고 **검사번호를 주지 않음**으로써 「이것은 확정이 아니다」를 구조로 말하게 했습니다.
- **세포병리에는 그 보호가 전혀 없었다.** 외과 병리는 단단했는데 세포병리는 무방비여서, **악성 판정이 재전송만으로 양성으로 교체**될 수 있었습니다. 같은 보호를 뒤늦게 붙였습니다.
- **필수항목 검증이 죽은 코드였다.** 서명 쪽에 검증 코드가 있었지만 화면이 프로토콜을 보내지 않아 **한 번도 돌지 않았고**, 암 케이스가 필수 항목을 비운 채 최종이 될 수 있었습니다. 「있다」와 「돈다」는 다른 일입니다(판정 규칙 ②·③).
- **개정 통보가 없어 이전 진단으로 진료가 계속될 수 있었다.** 그래서 배포 이력이 있으면 폐루프로 다시 알립니다(판정 규칙 ④).
- **시드가 「보냈다」고 거짓말하고 있었다.** 영상 작업목록의 송신 상태가 시드에 **고정 문자열로 박혀 있어**, 실제로는 아무것도 나가지 않았는데 나갔다고 표시됐습니다. 시드에서 걷어내고 **그런 값이 다시 들어오지 못하게 하는 검사**를 만들었습니다(판정 규칙 ①·⑨).
- **뷰어 링크와 작업목록이 서로 다른 검사번호를 볼 수 있었다** — 판독의가 뷰어를 열면 영상을 못 찾는 상태입니다. 채번을 한 곳으로 모으고 시험으로 고정했습니다.

## 4. 🔴 무엇을 막나

- **다른 사람 명의의 최종 진단** — 서명자는 계정에서 유도하고, 본문으로 지정할 수 없습니다
- **확정 진단문의 조용한 교체** — 재서명 · 초안 회귀 · 재전송 저장 모두 거부
- **사유 없는 수정** — 개정에는 사유가 필수이고 판 번호가 오릅니다
- **동시 수정으로 한쪽이 사라지는 것** — 뒤엣것이 거부되고 「새로고침 후 다시」로 안내됩니다
- **필수 항목이 빈 암 보고의 확정** — 프로토콜을 지정하면 막힙니다
- **고친 사실이 임상의에게 닿지 않는 것** — 배포된 보고서의 개정은 다시 통보됩니다
- **검사번호가 갈라지는 것** — 작업목록과 뷰어 링크가 같은 번호를 씁니다

## 5. 🔴 기관이 정해야 하는 것 셋

**시스템이 강제하지 않는 것**이 셋 있습니다. 「있다」고 쓰지 않고 그대로 적습니다.

| 무엇 | 지금 상태 | 기관이 할 일 |
|---|---|---|
| **초안을 쓴 사람과 서명한 사람이 달라야 하는가** | 🔴 **강제하지 않습니다.** 같은 계정이 초안을 쓰고 같은 계정이 최종 서명할 수 있습니다. (같은 시스템의 **일반 검사 결과 검증**에는 「입력자는 자기 결과를 검증할 수 없다」는 강제가 있습니다 → [검사 결과 검증](result-verification.md)) | 운영 규정으로 정하고, 필요하면 각 프로젝트에 강제를 요청합니다 |
| **초안 단계를 반드시 거쳐야 하는가** | 🔴 **필수가 아닙니다.** 초안 없이 곧바로 최종 서명이 가능합니다(코드가 「하위호환」이라고 적고 있습니다) | 같음 |
| **고치기 전의 진단문을 남길 것인가** | 🔴 **보고서 본문의 이력 테이블이 없습니다.** 개정하면 판 번호 · 사유 · 새 본문이 남고 **이전 확정 진단문은 남지 않습니다**(추가보고는 덧붙이므로 해당 없음) | 개정 전 보고서를 따로 보존할지 정합니다 |

# 원내 처방집 — 켤 수 있다고 해서 막히는 것은 아니다

**The in-house formulary — being switchable is not the same as being enforced**

> **EN** — The formulary is the set of codes a hospital's committee has approved, plus the request-and-review workflow that changes that set, plus a gate consulted immediately before a prescription is issued. The gate is a per-area map over seven areas; an area that is absent is OFF, but an area whose value is present and unrecognised becomes BLOCK (fail-closed), and the headline mode is the **weakest** area rather than the strongest, reported together with a denominator. Three of the seven areas have **no enforcement point at all** — what the registry stores and what a prescription record stores are different keys — so raising their mode changes nothing, and the admin screen is required to say so. An order carrying no code is recorded as **undecidable from code**, never counted as compliant. The gate ships with every area OFF, and a structural test fails the build if a new file writes prescriptions without importing the gate. AI only drafts candidate checklists by number so it cannot invent a code; a person registers them. Sits on judgment rules ① honesty, ② single source of truth, ④ gates and ⑥ human decision.

## 1. 무엇을 하나

원내 처방집은 **이 병원에서 쓰기로 한 것의 목록**입니다. 세 가지가 붙어 있습니다.

| 무엇 | 하는 일 |
|---|---|
| **승인 집합** | 영역별로 「이 코드는 쓴다」를 모아 둔 것 |
| **등재 요청·심의** | 목록을 바꾸는 길 — 현장이 요청하고 위원회가 정합니다 |
| **발행 게이트** | 처방이 나가기 **직전에** 승인 여부를 봅니다 |

영역은 일곱입니다 — **약 · 검사 · 영상 · 처치 · 식이 · 활동 · 간호.**

🔴 **코드 마스터와는 다릅니다.** 마스터는 「세상에 있는 코드」이고, 처방집은 **「이 병원이 쓰기로 한 코드」**입니다. 처방집은 마스터를 **참조만** 합니다.

## 2. 어떻게 도나

### ① 등재 — 무엇을 키로 잡나

| 영역 | 등재하는 것 |
|---|---|
| 약 | 약품 코드 |
| 검사 · 영상 · 식이 | 수가 코드 |
| 간호 | 간호 코드 |
| 처치 · 활동 | **프리셋 키**(문자열) |

같은 항목을 다시 등재하면 **새로 만들지 않고 되살립니다**(중지·제거 → 사용). 상태는 **사용 · 중지 · 제거** 셋입니다.

마스터에서 그 코드가 사라졌거나 비활성이면 목록에 **그렇게 표시**됩니다 — 이름 자리에 「마스터에서 삭제됨」이 뜨고, 비활성 표식이 붙습니다.

### ② 요청과 심의

| 단계 | 규칙 |
|---|---|
| 요청 | 🔴 **임상 사유가 필수**입니다 · 코드 또는 새 항목명 중 하나는 있어야 합니다 |
| 중복 | 같은 영역·같은 코드의 대기 중 요청이 있으면 **그 요청을 그대로 돌려줍니다**(심의함에 쌓이지 않게) |
| 심의 | 🔴 **반려에는 사유가 필수**입니다 |
| 동시 심의 | 🔴 **먼저 누른 쪽만 성공**합니다 — 늦은 쪽은 「이미 처리된 요청」으로 거절됩니다 |
| 승인 | **즉시 처방집에 반영**되고, 요청 사유가 등재 메모로 남습니다 |

### ③ 시행 모드 — 영역별 · **끔 / 경고 / 차단**

| 값의 상태 | 해석 |
|---|---|
| 그 영역 키가 **없음** | **끔**(등록 기본) |
| `OFF` · `WARN` | 그대로 |
| 🔴 **그 밖의 값**(오타 · 다른 표기 · 뒤 공백) | **차단** — 모르는 값은 안전한 쪽으로 접습니다 |

🔴 **기준 커밋 기본값은 빈 맵입니다 — 일곱 영역 전부 끔.**

**대표 모드는 「가장 약한 고리」입니다.** 한 영역이라도 끔이면 대표는 끔입니다. 그리고 **시행 중인 영역 수 / 설정된 영역 수**를 함께 냅니다.

→ **왜 최저인가** — 하나라도 차단이면 차단으로 접던 때, 일곱 중 한 영역만 차단이어도 붉은 배지가 떠서 **나머지 여섯이 열려 있다는 사실이 가려졌습니다.** 안전은 가장 약한 고리로 정해집니다([안전 게이트](safety-gates.md)).

### ④ 발행 게이트 — 판정은 일곱 가지

처방이 나가기 직전에 이 게이트를 부릅니다. 결과는 일곱 중 하나입니다.

| 판정 | 뜻 | 막나 |
|---|---|---|
| 해당 없음 | 처방집 영역이 아닌 처방 | 아니오 |
| 🔴 **집행 불가** | 그 영역에는 **대조할 수단이 없다**(아래 ⑤) | 아니오 |
| 🔴 **판정 불가** | 코드 없는 자유기재 오더 — 승인 여부를 **알 수 없다** | 아니오 |
| 승인됨 | 처방집에 사용 상태로 있다 | 아니오 |
| 끔 | 미승인이지만 게이트가 꺼져 있다 | 아니오(기록만) |
| 경고 | 미승인 — **통과시키되 위반을 남긴다** | 아니오 |
| 차단 | 미승인 — **거부하고 등재 요청으로 보낸다** | 예 |

🔴 **「판정 불가」를 준수로 세지 않습니다.** 코드 없이 글로만 적은 오더는 대조할 것이 없습니다. 이것을 조용히 통과로 세면 **관제의 「위반 0」이 거짓**이 됩니다.

미승인 사유는 **미등재**와 **위원회 사용중지**를 갈라 말하고, 차단 메시지에는 **코드 이름과 번호**가 함께 붙습니다.

### ⑤ 🔴 **모드를 올려도 막히지 않는 세 영역**

| 영역 | 왜 못 막나 |
|---|---|
| **처치** · **활동** | 등재는 프리셋 키인데, 처방은 **자유기재로 저장**됩니다 — 맞춰 볼 칸이 없습니다 |
| **간호** | 등재는 간호 코드인데, 처방 기록에 **그 칸이 없습니다** |

이 세 영역은 모드를 경고나 차단으로 올려도 **막히는 것이 없습니다.** 그래서 게이트는 모드가 켜져 있는데 집행 수단이 없으면 **그 사실 자체를 위반 원장에 남기고**, 관리 화면은 **「집행점 없음」과 그 사유를 표시**합니다.

→ **왜 굳이 말하나** — 침묵하면 화면이 **「적용 중」이라고 거짓말**합니다.

### ⑥ 집행은 **서버**가 한다

게이트는 처방 서비스의 발행 세 경로(신규 · 복사 · 반복)가 **함께 쓰는 한 자리**에서 불립니다.

🔴 **화면의 확인창은 집행이 아닙니다.** 화면에만 검사가 있으면 모바일 · 워크스테이션 · API 직접 호출이 전부 통과하는데, 관리 화면은 「시행 중」이라고 말하게 됩니다.

그리고 **구조 가드**가 있습니다 — 처방을 직접 만드는 **새 파일이 이 게이트를 부르지 않으면 검사가 실패**합니다. 미배선 경로 목록은 **현재 비어 있습니다.**

→ 🔴 **목록을 비워 둔 것도 정직화의 일부입니다** — 화면이 **실제보다 덜 안전하게** 말하는 것도 사실이 아닙니다. 새 발행 경로를 만들고 게이트를 못 붙였다면 **그 목록에 적어야** 합니다.

### ⑦ 위반 기록

경고 통과 · 차단 · 판정 불가 · 끔 상태의 미승인은 모두 **게이트 위반 원장**에 남습니다.

🔴 **기록은 트랜잭션 밖에서 남깁니다** — 차단 때문에 처방이 되돌려져도 **「막았다」는 사실은 남아야** 합니다([안전 게이트](safety-gates.md)).

### ⑧ 처음 채우기 — 두 가지 길

| 길 | 무엇 | 🔴 주의 |
|---|---|---|
| **사용 실적 일괄 등재** | 최근 몇 개월 처방에 쓰인 코드를 한 번에 사용 상태로 | 🔴 **쓰던 것을 그대로 승인으로 만듭니다** — 위원회가 본 것이 아닙니다 |
| **AI 초안** | 주제를 주면 후보를 묶은 **체크리스트 초안**을 만듭니다 | 초안일 뿐이고 **등재는 사람이 누릅니다** |

AI 초안이 도는 방식은 이렇습니다.

1. 주제로 **검색 키워드**를 만듭니다
2. 그 키워드로 **마스터에서 후보를 찾습니다**(영역별 · 중복 제거 · 개수 상한)
3. 🔴 **후보에 번호를 붙여 주고, AI 는 번호만 고르게 합니다**

→ **왜 번호만인가** — 코드를 직접 쓰게 하면 **없는 코드를 지어냅니다.** 번호를 벗어난 값은 버려집니다. **AI 는 후보를 묶어 초안을 만들 뿐이고, 무엇을 등재할지는 사람이 정합니다.**

초안은 시간이 걸려서 **작업 번호를 먼저 돌려주고 나중에 결과를 받는 방식**입니다. AI 서버 주소가 없으면 **「미설정」이라고 말합니다** — 「허용되지 않음」과 다른 사실이라 같은 말로 내려보내지 않습니다. 🔴 **생성 모델 이름은 코드에 고정**돼 있습니다([S6 AI 켜기](../../build-guide/S6-ai.md)).

## 3. 🔴 왜 그렇게 만들었나

- **정책 해석을 한 곳에 모은 이유.** 같은 판정을 두 곳에서 하면 **갈라집니다.** 실제로 한쪽은 모르는 값을 조용히 「끔」으로 떨어뜨렸고, 그래서 **오타 하나가 통제를 통째로 열었습니다**(판정 규칙 ②).
- **부재는 끔, 모르는 값은 차단인 이유.** 아직 안 정한 것과 **잘못 적은 것**은 다릅니다. 안 정한 것은 열어 두고, **잘못 적은 것은 안전한 쪽**으로 접습니다.
- **대표 모드가 가장 약한 고리인 이유.** 위 ③ 그대로 — 강한 쪽으로 접으면 **열려 있는 영역이 배지 뒤로 숨습니다.** 그리고 분모 없는 배지는 **얼마나 통제되는지**를 말하지 못합니다(판정 규칙 ⑦).
- **집행을 서버에 둔 이유.** 화면은 **하나가 아닙니다.** 화면마다 검사를 붙이면 안 붙은 화면이 곧 우회로가 됩니다(판정 규칙 ④).
- **구조 가드를 둔 이유.** 처방을 만드는 길은 **나중에 또 생깁니다.** 사람이 기억해서 붙이는 대신, **안 붙이면 검사가 실패**하게 했습니다(판정 규칙 ③ — 가드는 결함을 재주입해 실패해야 가드입니다).
- **미배선 목록을 비운 것도 정직화인 이유.** 위 ⑥ 그대로 — **실제보다 덜 안전하게 말하는 것도 사실이 아닙니다.**
- **「판정 불가」를 따로 둔 이유.** 대조할 수 없는 것을 **준수로 세면 「위반 0」이 거짓**이 됩니다. 이 생태계에서 0 은 **세 가지 뜻**을 가질 수 있습니다([안전 게이트](safety-gates.md)).
- **집행 불가 영역을 화면이 말하게 한 이유.** 모드를 올려 둔 관리자는 **막히고 있다고 믿습니다.** 막히지 않는다면 그 사실이 **같은 화면에** 있어야 합니다(판정 규칙 ①).
- **위반 기록을 트랜잭션 밖에 둔 이유.** 차단은 처방을 되돌립니다. 기록까지 함께 되돌아가면 **막았다는 사실이 사라집니다.**
- **동시 심의를 조건부 갱신으로 막은 이유.** 두 사람이 같은 요청을 동시에 열면 **승인과 반려가 겹쳐 쓰일 수** 있습니다.
- **AI 에 번호만 고르게 한 이유.** 위 ⑧ 그대로 — **코드를 직접 쓰게 하면 지어냅니다.**
- 🔴 **찾지 못한 것 — 기본이 전 영역 끔인 이유.** 왜 등록 기본이 「끔」인지는 기록에서 찾지 못했습니다. 🔴 **기관이 개시 전에 반드시 정할 값**입니다.
- 🔴 **찾지 못한 것 — 수의 출처.** 사용 실적 일괄 등재의 **기본 개월 수**, AI 초안의 **후보 상한**과 **카테고리 개수 범위**가 어디에서 온 값인지 기록에서 찾지 못했습니다.

## 4. 🔴 무엇을 막나

- **위원회가 승인하지 않은 코드의 처방** — 차단 모드일 때, 등재 요청으로 보냅니다
- **오타 하나로 통제가 통째로 열리는 것** — 모르는 값은 차단 쪽으로 접습니다
- **한 영역만 켜 두고 「시행 중」이라 말하는 것** — 대표는 가장 약한 고리이고, 분모가 함께 붙습니다
- **화면만 고치고 서버는 통과시키는 것** — 집행은 발행 경로 한 자리에서 합니다
- **게이트를 부르지 않는 새 발행 경로** — 구조 가드가 빌드를 실패시킵니다
- **대조할 수 없는 것을 준수로 세는 것** — 「판정 불가」로 따로 남깁니다
- **막히지 않는 영역을 「적용 중」이라 말하는 것** — 집행점 없음과 사유를 표시합니다
- **AI 가 없는 코드를 지어내는 것** — 후보 번호 밖의 값은 버립니다
- **막았다는 기록이 롤백과 함께 사라지는 것** — 기록은 트랜잭션 밖입니다
- **같은 요청이 동시에 두 번 심의되는 것** — 먼저 누른 쪽만 성공합니다
- **같은 항목이 중복으로 쌓이는 것** — 재등재는 되살리기이고, 중복 요청은 기존 요청을 돌려줍니다
- **막지 못하는 것**
  - 🔴 **기준 커밋 기본은 일곱 영역 전부 끔**입니다 — 켜기 전에는 **보기만 합니다**
  - 🔴 **처치 · 활동 · 간호는 모드를 올려도 막히지 않습니다** — 대조할 칸이 없습니다
  - 🔴 **등재는 관리자 권한입니다.** 위원회 이름과 메모는 **적는 칸**이지 **검증되는 값이 아닙니다** — 누가 심의했는지는 기관이 운영으로 보장할 일입니다([위원회 의결](governance-enactment.md))
  - 🔴 **사용 실적 일괄 등재는 쓰던 것을 그대로 승인으로 만듭니다** — 콜드스타트를 넘기 위한 길이고, **심의를 대신하지 않습니다**
  - 🔴 코드 없이 글로만 적은 오더는 **어떤 모드에서도 막히지 않습니다**(판정 불가로 남을 뿐입니다)

- 🔴 **이 글은 어떤 약을 쓰라고 말하지 않습니다.** 무엇을 처방집에 올릴지는 **기관의 위원회가 정할 일**이고, 자료는 **목록을 누가 바꾸고 시스템이 무엇을 강제하는지**까지만 적습니다.
- AI 초안은 **AI 서버가 켜져 있어야** 돕니다([S6 AI 켜기](../../build-guide/S6-ai.md) · [AI Server 구성서](../../systems/ai-server.md)).

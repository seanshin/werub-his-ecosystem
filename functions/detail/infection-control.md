# 감염관리 — 세지 못한 것과 나가지 않은 신고를 그대로 말한다

**Infection control — it says plainly what it could not count and what never left the building**

> **EN** — Infection control here is five things: surveillance of healthcare-associated infections, isolation census, hand-hygiene observation, staff exposure incidents, and statutory reporting. What makes it worth a page is not the feature list but the honesty rules baked into it. Hand-hygiene compliance returns **null, not 0%**, when no observations exist, because an empty sample is not perfect failure. The isolation census merges four sources and reports **which source contributed what**, after two conflicting definitions once put "1 isolated patient" and "4 on contact precautions" on the same screen. Statutory disease reporting and the national HAI surveillance feed are **not implemented** — the code refuses to let any flag render as "reported", assigns an explicitly local reference number, and keeps such cases re-submittable. A dedicated "screen truth" test suite re-injects each past regression. Sits on judgment rules ① honesty, ② single source of truth, ③ guards, ⑥ outbound sending and ⑦ numbers with denominators.

## 1. 무엇을 하나

감염관리는 다섯 갈래입니다 — **의료관련감염 감시 · 격리 현황 · 손위생 관찰 · 직원 노출 사고 · 법정 보고.**

이 글이 기능 목록보다 오래 붙드는 것은 **이 다섯이 전부 「셀 수 없는 상태」를 정면으로 다룬다**는 점입니다. 관찰이 0건인 손위생, 정의가 둘이던 격리 환자, 구축된 적 없는 대외 전송 — 셋 다 **화면이 숫자를 그럴듯하게 만들어 낼 수 있는 자리**였고, 지금은 셋 다 만들어 내지 않습니다.

## 2. 어떻게 도나

### ① 손위생 — 🔴 관측이 없으면 비율은 `0%` 가 아니라 「산출 불가」

관찰자가 **WHO 다섯 순간**(환자 접촉 전 · 청결·무균처치 전 · 체액 노출 위험 후 · 환자 접촉 후 · 환자 주변환경 접촉 후) 중 하나를 골라 **수행 / 미수행**을 기록합니다. 순간 번호가 1~5 밖이거나 수행·미수행 둘 중 하나가 아니면 **접수하지 않습니다.**

| 상황 | 무엇을 돌려주나 |
|---|---|
| 관측이 있고 수행이 있음 | 실제 준수율(소수 첫째 자리) |
| 관측이 있고 **전부 미수행** | **0%** — 관측된 진짜 0 은 0 이라고 말합니다 |
| 🔴 관측 0건 | **비율 없음** + 「표본 있음: 아니오」 + **사유 문장**("관찰 기록이 없어 준수율을 산출할 수 없습니다") |

역할별·순간별로도 같은 규칙입니다 — 관측이 없는 순간은 0% 가 아니라 **값 없음**입니다. 기간을 지정하지 않으면 **최근 30일**을 봅니다. 목표치(90)는 값과 함께 내려가지만, **목표가 있다고 해서 없는 값을 0 으로 채우지 않습니다.**

→ 그래서 개원 초기 화면은 손위생 칸을 **「산출 불가」**로 그립니다. 이것은 준수율이 나쁘다는 뜻이 아니라 **아직 아무도 관찰을 기록하지 않았다**는 뜻입니다([간호 안내](../../clinicians/nursing.md)).

### ② 격리 환자 — 정본이 둘이었고, 넓은 쪽으로 합쳤다

「격리 환자 N명」은 **네 곳을 합쳐 환자 단위로 중복을 지운 수**입니다.

| 무엇을 세나 | 조건 |
|---|---|
| 격리 오더 | 진행 중인 것 |
| 감염 감시 | **해소되지 않았고** 격리 유형이 적힌 것 |
| 다제내성균 등록 | 활성이고 해제되지 않은 것 |
| 중환자실 | 재원 중이고 격리 표시가 있는 것 |

한 환자가 여러 곳에 걸쳐 있어도 **1명**입니다. 그리고 응답은 **어느 출처에서 몇 명이 왔는지**를 함께 돌려주어, 화면이 「무엇을 세었는지」를 주석으로 적을 수 있게 합니다.

🔴 **왜 이렇게 됐나** — 종전에는 상단 카드가 격리 오더 유무만 세고 해소 여부를 무시했습니다. 그래서 같은 화면에서 **「격리 환자 1」과 「4명 전원 접촉격리」가 동시에** 보였습니다. 정의가 둘이었던 것입니다. 지금은 **넓은 쪽**으로 수렴했습니다 — 격리 주의는 **오더가 없어도 필요**하고, 좁게 세면 접촉주의가 필요한 환자를 화면이 숨기기 때문입니다.

### ③ 직원 노출 사고 — 🔴 0 은 「사고 없음」이 아니다

주삿바늘 자상 · 체액 노출 등을 접수하고 추적관찰합니다.

| 무엇 | 어떻게 |
|---|---|
| 목록 | 최근 순 **최대 500건**. 🔴 넘으면 **「잘렸다」고 응답이 말합니다**(전체 수와 상한을 함께) |
| 요약 | 🔴 **잘린 목록이 아니라 전체에서 셉니다** — 안 그러면 같은 응답 안에서 「전체 700 · 추적중 500」 같은 모순이 생깁니다 |
| 추적 대기 | 종결되지 않은 건 수 |
| 🔴 원환자 감염상태 **미상** | 간염·HIV 상태가 아직 비어 있는 건 수를 **따로** 셉니다 — 노출 후 예방조치 판단이 여기 걸려 있습니다 |
| 🔴 0건일 때 | **「사고가 없었다」고 말하지 않습니다** — "이 시스템에 접수된 기록이 없습니다(수기 서식 접수분은 포함되지 않습니다)" |
| 본인 이력 | 신고한 사람이 **자기 추적 상태를 직접** 봅니다. 🔴 로그인 계정이 직원 원장과 연결돼 있지 않으면 **빈 목록이 아니라 사유를 돌려줍니다**(인사 담당에게 계정↔직원 연결을 요청하라고 적습니다) |

개인정보 쪽 규칙도 코드에 박혀 있습니다 — 노출 사고 화면에 나가는 원환자 정보는 **환자번호와 이름까지**이고, 암호화해 보관하는 신원번호류는 **싣지 않습니다.**

### ④ 법정 보고 · 국가 감시체계 — 🔴 전송 채널이 없다

법정감염병 신고와 전국 의료관련감염 감시체계 보고는 **기준 커밋에서 구현돼 있지 않습니다**(`미구현`). 이 생태계가 택한 방식은 **없는 연동을 흉내내지 않는 것**입니다.

| 무엇 | 어떻게 |
|---|---|
| 채널 | 두 채널 모두 「구현됨: 아니오」로 코드에 선언돼 있고, **그 값이 거짓인 동안 어떤 코드도 「전송 완료」를 적을 수 없습니다** |
| 접수번호 | 원내에서 만든 번호에는 **「원내」 접두어**가 붙습니다 — 기관이 준 번호처럼 보이지 않게 |
| 상태 어휘 | 초안 · **원내 접수만 완료**(나가지 않음) · 전송 실패 · 전송 성공 · 접수 확인 · 반려. 🔴 「전송 성공」은 **채널이 붙는 날까지 새로 기록되지 않습니다** |
| 재시도 | 🔴 **실제로 나가지 않은 건은 다시 신고할 수 있습니다.** 종전에는 한 번 누르면 상태가 굳어 **영구 미신고**가 됐습니다 |
| 미전송 기록 | 시각 · 시도자 · 사유 · **사람이 대신 할 일**(수기 신고 후 접수번호 입력)이 한 줄로 남습니다 |
| 감시 목록 | 신고 표시가 있어도 **「신고 표시(전송 근거 없음)」**로 적고, 표시가 없으면 **「미신고」로 단정하지 않고** 「신고 표시 없음」이라고만 적습니다 |
| 해소 구분 | 해소된 건은 **해소로 표시해 뒤로 밀립니다** — 종전에는 해소된 감염도 격리 배지를 단 채 현재 감염처럼 보였습니다 |

→ 화면도 같은 말을 합니다: **"자동 전송 연동이 없습니다 — 종결해도 보고되지 않으며, 웹에서 수기 보고해야 합니다."** 미보고 건수를 세고, 건마다 배지를 답니다([HIS 화면](../../screens/his.md#연구와-감염관리--만들지-않은-것을-만든-척하지-않는다)).

이것은 [마약류 수불 원장](narcotics-ledger.md)이 법정 취급보고를 다루는 방식과 **같은 규약**입니다 — 실제 발송만 발송, 채널 미구현은 미전송, 실패는 실패.

### ⑤ 가드 — 지나간 잘못을 다시 집어넣어 확인한다

감염관리에는 **「화면 진실성」 시험 묶음**이 따로 있습니다. 「관측 0건이면 비율이 없음이어야 한다 — **0 이면 회귀**」, 「신고 표시를 신고완료로 번역하지 않는다 — **참이면 회귀**」처럼, **한 번 일어났던 잘못을 그대로 재주입**해 실패하는지 봅니다. 통과가 아니라 **재주입 실패**가 가드의 증거라는 것이 이 저장소의 규칙입니다(판정 규칙 ③).

## 3. 🔴 왜 그렇게 만들었나

- **표본 부재의 정답은 0 이 아니다.** 종전 손위생은 관측 0건에 **0%** 를 돌려줬고, 화면은 목표 90% 대비 **빨간 큰 글씨**로 그렸습니다. 읽는 사람에게 그것은 「직원이 손을 전혀 안 씻는다」였습니다. 같은 사실을 다른 화면은 이미 「값 없음」으로 말하고 있었으므로 — **정본이 둘이었고, 정직한 쪽으로 수렴**했습니다(판정 규칙 ①·②).
- **넓은 정의로 합친 이유.** 격리 주의는 **격리 오더가 없어도 필요**합니다. 좁게 세면 접촉주의가 필요한 환자를 화면이 숨깁니다. 세는 기준을 넓히되 **무엇을 셌는지 함께 돌려주는** 쪽을 택했습니다(판정 규칙 ⑦).
- **없는 연동을 흉내내지 않은 이유.** 종전에는 신고 버튼이 상태와 접수번호를 **적기만** 했는데 화면은 초록 「신고완료」 배지를 보여 줬습니다. 전송 코드는 코드베이스 어디에도 없었습니다. **법정 신고에서 「완료」로 보이는 오표시는 신고 누락 그 자체보다 위험합니다** — 담당자가 더 이상 확인하지 않게 되기 때문입니다(판정 규칙 ①·⑥).
- **고칠 자리를 한 곳으로 모은 이유.** 실제 연동이 붙는 날 바꿀 곳은 **전송 함수 두 개뿐**이라고 코드가 적어 두었습니다. 흉내가 여기저기 퍼지면 붙이는 날 어디를 고쳐야 할지 알 수 없게 됩니다(판정 규칙 ②).
- **요약을 전체에서 센 이유.** 잘린 페이지에서 요약을 세면 **같은 응답 안에서 수가 서로 어긋나고**, 관리자는 상한을 전부로 읽습니다.
- 🔴 **찾지 못한 것** — 손위생 목표 90 이 어느 기준에서 온 값인지는 코드와 릴리즈 기록에서 찾지 못했습니다. 기관이 자기 목표로 다시 정해야 합니다.

## 4. 🔴 무엇을 막나

- **표본 없이 비율을 내는 것** — 관측 0건이면 비율 자체를 만들지 않습니다(진짜 0% 와 구분합니다)
- **정의가 둘인 채로 두는 것** — 격리 환자는 한 정의로 합치고, 출처별 내역을 함께 돌려줍니다
- **나가지 않은 신고를 「신고완료」로 적는 것** — 채널이 미구현인 동안 어떤 플래그도 전송으로 번역되지 않습니다
- **기관 접수번호를 흉내내는 것** — 원내 번호에는 원내 접두어가 붙습니다
- **한 번 눌러 영구 미신고로 굳는 것** — 나가지 않은 건은 다시 신고할 수 있습니다
- **표시가 없다고 미신고로 단정하는 것** — 「신고 표시 없음」까지만 말합니다
- **해소된 감염을 현재 감염처럼 보이게 하는 것** — 해소 여부를 구분해 정렬합니다
- **0 을 「사고 없음」으로 읽게 두는 것** — 노출 사고 0 은 「접수된 기록이 없음」이라고 적습니다
- **잘린 목록을 전부로 보이게 하는 것** — 잘렸으면 잘렸다고 말하고, 요약은 전체에서 셉니다
- **막지 못하는 것** — 🔴 **대외 전송은 사람이 합니다.** 수기 보고와 접수번호 입력이 빠지면 이 시스템은 그 사실을 알 방법이 없습니다

- 이 기능은 **한 시스템 안**에서 끝나므로 [연결 상태 표](../../RELEASES/2026.09/compatibility.md)에는 나오지 않습니다.

## 다섯 줄 요약

1. **AI 연산은 AI Server 한 곳이 맡습니다.** 각 시스템은 AI Server 를 불러 초안 · 분류 보조 · 근거 검색 · 음성 인식을 받습니다.
2. **소비자용 GPU 한 장(NVIDIA RTX 5080 · VRAM 16GB)을 기준으로** 개발하고 돌려 왔습니다.
3. **환자 데이터는 기관 밖 AI 로 나가지 않게** — 의료 · 개인건강정보 · 규제 관련 작업은 `local_only` 로 묶여, 외부 AI 제공자로 보내려 하면 코드가 거부합니다.
4. **AI 는 보조하고 초안을 만듭니다.** 사람이 승인해야 정본이 되고, 승인 이력이 남습니다.
5. **설치 직후 AI 기능을 끄고, 기관 결정으로 하나씩 켭니다.** 코드 기본값이 켜진 기능이 있기 때문입니다.

그림은 [⑦ AI 호출 지도](../diagrams/ai-map.md)에 있습니다.

## AI 가 하는 일 — 모두 사람의 판단을 돕는 보조

| 보조 | 무엇을 만드나 | 누가 확정하나 |
|---|---|---|
| 분류(triage) 보조 | 증상 분류 제안 | 의료진 |
| 진료 기록 초안 · 음성 기록 | 진료 대화 · 음성에서 기록 초안 | 의료진이 승인해야 기록이 됨 |
| 약물 설명 · 검진 결과 설명 | 환자용 설명 초안 | 사람이 감수 · 승인하는 화면을 거침 |
| 약물 상호작용 점검(DUR) 보조 | 점검 결과 제안 | 의료진 · 약사 |
| 근거 문서 질의(RAG) | 근거 문서에서 찾은 답변 초안(cerno 는 근거가 없으면 생성하지 않음) | 의료진 |
| 위험 점수 카드(twin) | 위험 예측 보조 · SBAR 초안 | 의료진이 '차트 저장'을 눌러야 HIS 에 저장 |
| 영상 판독 초안(PACS) | 예비 판독문 초안 · 비교 판독 · 영상 자동 선별 알림 | 판독의 |

근거: [README 「AI 는 소비자용 GPU 한 장으로」](../README.md#ai-는-소비자용-gpu-한-장으로--rtx-508016gb) · [HIS 릴리즈 요약 §2](../RELEASES/draft/systems/his.md) · [PACS 구성서](../systems/pacs.md) · [연결 상태](../RELEASES/draft/compatibility.md).

AI 는 진단 · 처방을 확정하지 않습니다([의료 면책 고지](../DISCLAIMER.md) 3항). 화면의 AI 표기는 공용 상수 하나(`AI(WeRU.B)`)로 통일돼 있고 면책 문구를 함께 보여 줍니다. ERP 의 청구 사전심사도 신고 금액 확정은 AI 에 넘기지 않습니다([S6](../build-guide/S6-ai.md)).

## GPU 한 장으로 — 16GB 를 나눠 쓰는 방식

"AI 기반 HIS"라고 하면 대형 서버실과 데이터센터용 GPU 를 먼저 떠올립니다. 이 생태계는 반대 방향으로 설계했습니다. 코드도 처음부터 16GB 안에서 여러 모델을 나눠 쓰도록 짜여 있습니다(2026-09-11 코드 확인).

| 항목 | 내용 |
|---|---|
| 기본 모델 | 범용 14B 급 하나(실제 적재 약 10.5GB) |
| 운용 방식(설정 한 줄) | **상주**(첫 응답이 빠름) 또는 **요청할 때 적재**(쉬는 동안 VRAM 을 비움 · 5분 미사용 시 내림 · 쉬고 난 뒤 첫 요청에 적재 시간이 붙음) |
| 동시에 올려 두는 모델 수 | 모델 서빙 설정으로 정합니다. 저장소 문서에 1개와 2개 두 기록이 함께 있어, 권장값은 계측해 싣습니다 |
| 자리가 모자라면 | 우선순위가 낮은 모델부터 내리고 올립니다(1.5GB 여유를 남김) |
| 시간대 프로파일 | 진료 시간(08:00~19:00)은 범용 14B 상주 + 의료 특화 4B~8B 필요 시 적재 · 진료 외 시간은 범용 7B(약 5.0GB) |
| 음성 인식 · 임베딩 | 같은 16GB 를 나눠 씁니다. 임베딩 모델은 약 1GB |
| 가속기 | NVIDIA CUDA · Apple Silicon(Metal) · CPU 중 자동 선택 |

모델별 VRAM 수치는 AI Server 코드에 적힌 **추정값**이고, 실행 중에는 실제 적재량을 다시 읽어 씁니다.

> 📏 **아직 계측이 없는 것** — 동시 사용자 수에 따른 처리량 · 모델별 응답 시간 · GPU 없는 환경의 속도. 계측하지 않은 것을 "충분하다"고 말하지 않습니다. 부족하면 시간대 프로파일로 나눠 쓰거나 GPU 를 늘립니다([S6 「아직 안 되는 것」](../build-guide/S6-ai.md)).

## 환자 데이터는 기관 밖으로 나가지 않게 — `local_only`

- 의료 · 개인건강정보 · 규제 관련 AI 작업은 코드에서 `local_only` 정책으로 묶여 있습니다. 외부 AI 제공자로 보내려고 하면 **코드가 거부합니다**(실패하면 막는 쪽으로 동작).
- 외부 AI 제공자를 연결할 자리는 있지만, 기본값은 모두 꺼져 있습니다(2026-09-11 확인).
- 호출하는 쪽은 모델 이름이 아니라 **역할 이름**을 부르고, AI Server 의 역할 → 모델 라우팅 표가 모델을 고릅니다. 등록되지 않은 역할은 다른 모델로 흘러가지 않고 바로 실패합니다.
- 그래서 클라우드 AI 사용료가 들지 않고, 인터넷 사정이 좋지 않은 곳에서도 AI 가 외부 서비스에 기대지 않습니다.

기관이 정할 것: 임상데이터 처리 경계(`legal.phiBoundary.gpuTier` — 원내 GPU 인가 위탁 유지인가)와 임상데이터 전송 목적지의 법적 한정(`legal.aiEgress.transferScope`)입니다([결정 등록부](../checklist/decisions.md)).

## 끄고 시작해 결정으로 하나씩 켠다

AI 서버 없이도 HIS 는 동작하도록 설계했습니다. AI 가 없거나 멈추면 화면이 그 칸을 "폴백" 또는 "산출 불가"로 표시합니다. 그런데 **코드 기본값은 기능마다 다릅니다**(2026-09-11 코드 확인).

| 기본 켜짐 — 설치 직후 끔 | 기본 꺼짐 — 꺼져 있는지 확인 |
|---|---|
| HIS 의 AI 기능 전체 스위치(`ai.server.enabled`) | 환자 AI 브리핑 야간 배치(`ai.brief.batch.enabled`) |
| PACS 영상 자동 선별 | 데이터 품질 AI(`quality.ai.enabled`) |
| HIS 의 AI 인사(`ai.greeting.enabled` — 기준 커밋 설정 목록) | 음성 EMR · 앰비언트 기록 · 진료 스크라이브 등 |
| | PACS 판독문 자동 초안 · 드리프트 자동 격리 |

근거: [README](../README.md#최소한의-사양과-구현으로-쓸-수-있게) · [S6 「설정」](../build-guide/S6-ai.md). 코드 기본값이 꺼짐이어도 설치본의 DB 값(시드 포함)이 다를 수 있으므로, 시스템 설정 화면에서 **값과 출처**를 함께 봅니다.

**켜는 순서**([S6](../build-guide/S6-ai.md) · [구축 단계 로드맵](../diagrams/build-roadmap.md#s6--왜-먼저-끄는가))

1. 설치 직후 위의 "기본 켜짐" 기능을 끕니다. 자기 기관 AI Server 주소를 넣기 전에는 AI 를 켜지 않습니다.
2. **선행 결정을 기록합니다** — 의료기기(SaMD) 해당성(`legal.ai.deviceClassification`) · 임상데이터 처리 경계(`legal.phiBoundary.gpuTier`) · 진료 음성 녹음 · 보관의 적법 근거(`legal.voiceRecording.basis`) · 전송 목적지의 법적 한정(`legal.aiEgress.transferScope`).
3. **켤 범위를 원내 위원회가 정합니다** — AI 임상 기능 범위(`policy.ai.clinicalFeatureScope`)는 선행 결정 셋이 먼저 정해져야 하는 **개시 전 필수** 결정입니다.
4. HIS 를 AI Server 에 연결하고 전체 스위치를 켭니다. 이때도 개별 기능 스위치는 꺼져 있어야 합니다.
5. **기능을 하나씩 켭니다** — 결정 기록 → 스위치 → Go-Live 항목 표시 → 감독 화면에서 제안 · 승인 기록 확인 → 다음 기능. 켠 순서와 날짜를 기관 문서에 남기고, 되돌릴 때도 같은 순서로 끕니다.

AI 계층의 사람 결정은 10개, 이 단계를 닫는 Go-Live 항목은 15개입니다(모두 개시를 막지 않는 추적 항목 · [S6](../build-guide/S6-ai.md)의 배정 · HIS v4.18.0 레지스트리 2026-09-11 추출).

**따로 챙길 설정** — 상담실 AI 자동응답(`consult.ai.autoReply`)은 켜면 사람 검토 없이 환자에게 전송된다고 설정 설명이 적습니다. 결정 등록부에 항목이 없어 기관이 따로 정합니다.

## 무엇이 남나 — 감독

| 어디 | 남는 것 |
|---|---|
| HIS | AI 제안 원장(생성 → 승인 · 수정 · 거부) · 모델 릴리즈 기록 · AI 호출 기록 · 환자를 지목한 AI 조회의 감사 기록 |
| HIS 품질 임계 | 임계값은 기본이 **미설정**이고, 원내 위원회가 과거 실측에서 정합니다(`policy.aiQualityThreshold`). 표본이 최소 호출 수보다 적으면 판정을 보류합니다 |
| AI Server | 충실도(근거와 맞는지) · 검색 품질 등 자기 품질 계측, 응답에 실리는 버전 정보 |
| twin | 모델이 바뀌면 알림(모델 digest 대조) |

## 모델은 기관이 골라서 직접 받습니다

모델 가중치는 이 저장소에도 생태계 소스에도 들어 있지 않습니다. **약관은 MIT 가 아니고 모델마다 다릅니다.**

| 기본 경로 모델 | 쓰는 곳 | 약관에서 눈여겨볼 것 |
|---|---|---|
| Qwen2.5 14B · 7B · Qwen3 8B · Qwen3-VL 8B | 일반 질의 · 요약 · 증상 분류 · RAG 답변 · 도구 호출 | Apache-2.0 |
| **MedGemma 1.5 4B · MedGemma 4B** | 의료 영상 판독 **초안** · 이중 판독 · 구조화 판독 초안 | HAI-DEF 약관 — 임상 사용(환자의 진단 · 치료에 쓰는 것, 연구 포함)에 해당하면 **관할 규제 기관의 승인을 받으라고** 적습니다 |
| Llama3-Med42-8B · Meditron 7B | 임상 질의 · 위험 추론 후보 · 약물 분석 1단계 | Llama 3 · Llama 2 Community License. **개발사가 추가 검증 없이 임상에 쓰지 말라고 경고**합니다 |
| BGE-M3 · Whisper · SpeechBrain ECAPA · DeepSeek-OCR | 임베딩 · 음성 인식 · 화자 구분 · 문서 글자 인식 | MIT · Apache-2.0 계열(모델별 원문은 THIRD_PARTY) |

- 일부 기본 태그는 원 개발사가 아닌 **제3자가 재포장한 태그**입니다. 가중치와 약관이 원본과 같은지 기관이 확인합니다.
- 자체 파인튜닝 의료 모델 2종은 공개 배포하지 않습니다. 공개 모델로 바꾸는 설정이 있습니다.
- 모델별 약관 원문과 확인일은 [THIRD_PARTY.md §3](../THIRD_PARTY.md#3-ai-모델-가중치)에 있습니다. 약관 요약은 법률 검토가 아니므로 반드시 원문을 읽습니다.

## 규제에 관해

이 소프트웨어는 어느 국가에서도 의료기기(SaMD 포함)로 인허가를 받지 않았습니다([의료 면책 고지](../DISCLAIMER.md)). 기준 버전의 AI 는 의료기기 해당성이 확정되지 않았고(twin 은 안전 등급 분류 예비 단계 · cerno 는 비임상 한정), **임상에 쓸지 · 어느 범위에서 쓸지는 구축 기관이 판단합니다.**

이 자료는 규제 항목을 `대응 설계` · `자체 점검 완료` · `외부 인증·승인`(증빙 번호가 있을 때만) 세 단계로만 적습니다. AI Server 저장소는 LLM 기반 디지털의료기기 가이드라인에 대응하는 체계(근거 없는 생성 방지 · 모델 판본 고정 · 파라미터 재현성)를 갖췄다고 적고, 이 자료는 이를 **`대응 설계`** 로 적습니다. 자체 점검 완료 · 외부 인증 · 승인 기록은 없습니다([AI Server 구성서](../systems/ai-server.md)) → [9장](09-terms.md).
